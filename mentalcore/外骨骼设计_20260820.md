# 外骨骼 / Work 大魔方 —— 设计定稿与实现说明

> 状态：已授权「开搞」（用户指令「你先独立搞，把整个 work 大魔方搞出来」）。
> 本文档固定讨论定稿，作为 `mentalcore/mentalcore/exo/` 实现的引用基线。

## 1. 定位：双 Agent 链（心智魔方 + 外骨骼）

| 角色 | 实体 | 责任边界 |
|------|------|----------|
| **Boss（心智魔方）** | `MentalCore` | 纯聊天文本通道；快速回复、角色卡语言加工；**不控制工具调用** |
| **Worker（外骨骼）** | `WorkCube` | 只干活；无性格纯执行者；回传结果给 Boss 做语言加工 |

- Boss 与 Worker **不直接面对用户的只有 Boss**；Worker 是「AI 教 AI 干活」的后台执行体。
- Boss 决定何时委派：**不靠关键词**，而是让 Boss 模型在回复末尾追加文本协议标记 `||EXO||{goal,context}||END||`。
- Worker 干完**自动回传** Boss（经 `core.receive()` 入队），下一轮 Boss 用角色卡再做语言加工。

## 2. 接入协议：`||EXO||`（复用 `||DATA||` 同管线）

- `ReplySplitter` 在解析 `||DATA||`（消费型好感度）的同时，识别 `||EXO||` 块 → 作为 `out_fields["exo"]` 透传（不面向用户渲染）。
- `MentalCore` 新增可选 `exo_broker` 钩子：`stream_message` 在 done 前若发现 exo 字段，调用 `exo_broker(payload)`（**后台线程**拉起 Worker，不阻塞 Boss 流式回复）。
- 不依赖 function calling，任意聊天模型可用；标记损坏则丢弃（容错）。

## 3. Worker 架构：微核心 + 6 个小魔方

```
              WorkCore（cpu：原生工具循环 + 调度）
        ┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
        │ 工具魔方 │ 沙箱魔方 │ 计划魔方 │ 通信魔方 │ 记忆魔方 │ 安全魔方 │
        │ 注册编排 │ 隔离执行 │ ReAct分解│ 审计回传 │ 专业记忆 │ 安全总闸 │
        └──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
```
- **核心 = WorkCore**：采用归档双 Agent 设计（移植自 palm dual_core/dual_runner/dual_plan）——
  原生 function-calling 循环（ExoLLM.complete(prompt, tools) → {text, tool_calls}），
  反思自检（reflect_once）+ 自主规划（PlanEngine，use_planning）+ 干预队列；
  `||TOOL||`/`||FIN||` 文本标记仅作兼容兜底。
- 每个小魔方 = 微内核 = agent 内部层级，可独立演进。

## 4. 安全魔方（SecurityCube）：Agent 安全总闸，安全职责全部集中

| 安全职责 | 落点 | 策略 |
|------|------|------|
| **权限判定** | 安全魔方（工具魔方委托） | 每个工具声明 `requires`（权限标签）；执行前 `check_permission()` 校验，越权即拒绝（fail-closed） |
| **提示注入清洗（H1）** | 安全魔方 | 工具入参/外部文本剔除高信号注入短语（移植 `_INJECTION_RE`）；输出剥离装饰壳 |
| **SSRF 防护（M7）** | 安全魔方 | 网络目标主机校验，私有/环回/链路本地/保留/组播一律拒绝 |
| **危险指令拦截** | 安全魔方（沙箱魔方委托） | 统一危险命令黑名单，命中即拦截（沙箱之外的第二道防线） |
| **护栏规则（5 档 Profile + 规则引擎）** | 安全魔方（`guardrail.py`，对齐归档 GuardPort） | 工具级精细裁决：trigger+条件 AND 匹配，deny/ask/warn/allow 四动作；hardline/strict/loose/ai/whitelist 档位切换（默认 strict 兼容 fail-closed）；`policies()` 导出 + `set_policy()` 热更新；规则可 yaml 加载（`exo_rules_yaml`） |
| **防幻觉门 / 确认门** | 安全魔方（前置校验） | `requires_grounding` 需 verification_id（防幻觉误删/误发）；`requires_confirmation` 需显式 confirmed=true（高危操作确认） |
| **代码静态扫描** | `code_guard.py`（run_code 前置） | 5 类风险扫描（daemon 无 join/破坏性删除/子进程无超时/系统路径删除/detach 后台）+ 系统目录硬阻断（不可被 autoconfirm 放行）；`MENTALCORE_EXO_AUTOCONFIRM_RUN_CODE=1` 才告警放行，默认拒绝 |
| **文件保险库** | 归档工具组 delete_file | 删除前先归档副本到保险库（`_vault`，可 `MENTALCORE_EXO_VAULT_DIR` 指定），再移回收目录——杜绝永久硬删 |
| **隔离执行** | 沙箱魔方 | 需隔离的工具（shell/代码）经沙箱受限 cwd + 超时下 subprocess 执行；fail-closed |
| **受限账户执行** | 沙箱魔方（`exec_mode`） | legacy（默认，黑名单纵深）/ restricted（受限 Token 禁用全部特权，**非管理员 fail-closed 拒绝，不静默降级**）/ deny（禁用 shell 执行）；`build_exo(sandbox_exec_mode=...)` |
| **密钥加密存储** | `secure_config.py` | API 密钥等敏感配置 SM4 加密 JSON 落盘（明文不写盘）；`save_api_secret`/`load_api_secret`/`config_from_secret` 一行接入装配 |
| **审计** | 通信魔方（Worker 轨迹）+ 安全魔方（安全事件） | 轨迹审计走 TraceStore；安全事件（拒绝/拦截/清洗/护栏/门）独立记入 `security_log` |

## 5. 模型解耦

- Boss 模型：`MENTALCORE_MODEL`（心智魔方自有，纯聊天）。
- Worker 模型：`MENTALCORE_EXO_MODEL`（独立配置，可不同模型）。
- Worker 模型层**原生支持 tool**：`PalmLLM.collect_with_tools` 把工具 schema 交给模型，
  返回 {text, tool_calls}（tool_calls 分段聚合）；`ExoLLM.complete(prompt, tools)` 封装。
- 默认 fallback：未配 EXO 模型则用 Boss 同款模型实例。

## 6. 记忆与落盘

- 心智魔方：聊天记录/向量加密落盘（live）；mock 零落盘（已验证）。
- 外骨骼：聊天不落地；**仅专业记忆**（移植自 palm 双 Agent 资产 `professional_memory.py`，sqlite 明文）。`ProfessionalMemory` 默认内存态（`db_path=None`），传入 `db_path` 才持久化明文经验。

## 7. 文件结构（`mentalcore/mentalcore/exo/`）

- `__init__.py`：`ExoSlotPort`（ABC）、`WorkCube`、`build_exo`、`build_coordinator`
- `core.py`：`WorkCore`（归档式原生工具循环 + 反思 + 规划）、`WorkCube`（ExoSlotPort 实现）、`build_ask_bridge`
- `model.py`：`ExoLLM`（复用 PalmLLM，原生 function calling）/ `ExoMockLLM`（离线）
- `protocol.py`：`||TOOL||`/`||FIN||` 解析、TaskGoal
- `cubes/`：tool_cube.py / sandbox_cube.py / plan_cube.py / comm_cube.py / **security_cube.py**
- `archived_tools.py`：归档工具组（文件 10 + 网络 2 + run_code + ask_user + GUI automate，共 15 个）
- `extended_tools.py`：扩展工具组（prod 4：成语/节日/汉字词典/二维码 + scheduler 2：remind/schedule_task 进程内 Timer 经心智魔方传达 + 沙箱 3：还原点快照/清理/后台任务）——Worker 工具共 28 个
- `tool_matcher.py`：移植自 palm tool_matcher 的语义工具筛选（关键词+描述词频，零依赖）——`describe_for_prompt(query)`/`to_openai_tool(query)` 按输入筛 Top-K，缩小暴露面
- `completion_gate.py`：移植自 palm completion_gate 的完成判定门（read_file 首行/网页标题/pytest 等可注册规则）——确定性工具结果直接收尾防空转
- `evolution.py`：自主进化（移植 palm services/evolution）——`SkillRegistry`（技能注册+状态治理）/ `EvolutionGate`（注入剥离+高风险阻断）/ `SkillInjector`（注入 Worker 提示）
- `expansion.py`：**PCB 扩展板**——AI 可插拔扩展槽位（`plug`/`unplug`/`list_extensions`/`register_skill`）；AI 经工具 `register_skill`/`list_extensions`/`unregister_extension` 自注册技能，进化门把关（恶意内容拒绝），技能注入未来任务
- `token_ledger.py`：Token 计量台账（逐笔记账 + 汇总 + 预算闸门 `token_budget`），接入 `ExoLLM.complete`
- `cron.py`：轻量 5 字段 cron 解析（`Cron.next_time`），`schedule_task` 支持 cron/daily/weekly/monthly
- `trace_store.py`：移植自 palm dual 的 `TraceStore`（轨迹分片 + 关键词检索）
- `professional_memory.py`：移植自 palm dual 的 `ProfessionalMemory`（跨任务经验库）
- `intent_router.py`：移植自 palm dual 的 `IntentRouter`（chat/task/intervention/query 分类）
- `dual_parse.py`：移植自 palm dual 的 `_normalize_native_chunk` / `_should_reflect`
- `prompt.py`：移植自 palm dual_runner/dual_prompt 的 Worker 提示模板 + 装饰壳清洗；`keep_recent=6` 历史摘要压缩（早期轨迹按工具名统计成摘要置末，零 LLM，输入封顶且不损前缀缓存命中）
- `runner.py`：移植自 palm dual_runner 的反思自检（`reflect_once` + `_REFLECT_PROMPT`）
- `planner.py`：移植自 palm dual_planner 的 `Planner` / `Plan` / `PlanStep`（LLM 规划 + 降级）
- `plan_engine.py`：移植自 palm dual_plan 的 `PlanEngine`（分步执行 + 失败重规划）
- `coordinator.py`：移植自 palm coordinator 的 `ExoCoordinator`（Boss=心智魔方 / Worker=外骨骼）
- `selftest.py`：离线自检

## 8. 接口（ExoSlotPort）

- `submit_async(task_goal, context, core)`：后台拉起 Worker（经 broker）。
- `intervene(action, instruction)`：Boss→Worker 干预（cancel/pause/resume/redirect，经 Queue 队列，对齐 dual_core 干预语义）。
- `worker_summary()`：供 Boss 注入的 Worker 轨迹摘要；无轨迹返回空串（不污染闲聊）。
- `get_status()` / `query_trace(keyword)`：进度与轨迹检索。
- `get_capabilities()`：对外能力清单（镜像归档 `WorkSlotPort`），含工具/模型/是否活跃。
- `classify(msg)` / `answer_query(msg)` / `forward_intervention(action)`：Worker 侧 query/intervention 路由（对应 coordinator 的 query/intervention 处理逻辑）。
- `make_broker(core)`：产出 `(payload) -> None` 闭包，供 `MentalCore.exo_broker` 调用；同时把自身挂到 `MentalCore._exo_cube`，使 Boss 在下一轮回复时自动注入 Worker 轨迹摘要（对齐 coordinator 的 `_worker_trace_summary` 注入）。

## 9. 编码铁律（沿用 palm）

- 文件 < 500 行；函数 ≤ 50 行；单一职责；业务意图命名；全程中文说明。
- mock 零落盘；缺依赖即降级（fail-operational），不崩溃。
