## 1. 协议与架构正确性（两组一致，重点结论）

- **数据区协议**：affinity_delta 全部被消费（50/50 与 17/17 轮均不出现在外发字段）；外发字段恒为 `inner_note`。拆分中间件契约稳定。
- **注入清单**：动态模块随轮次演进——R1 为 `(persona, emotion, weave, rhythm)`（记忆面首轮无历史不注入），R2 起恒为 `(persona, memory, emotion, weave, rhythm)`，两组行为完全一致。
- **好感度链路**：base 单调缓升（mock 4.0 / live 1.9），Δ 全为小数制（-0.1 ~ +0.2），溢出结转 bond、档位阈值为 100 的吝啬制设计符合预期——50 轮不足以升档，属**设计行为而非缺陷**。
- **档位细节差异**：live R1 显示「陌生」（base=0），mock R1 显示「初识」——档位映射对 base=0 的处理两组不同，值得在最终报告中标注（同一代码，为何不同？疑 base 初始化差异，见 §4）。

## 2. 性能对比（mock 4ms vs live 179s 均值）

- **mock**：单轮 4 ms 恒定，本地编排（注入组装+拆分+结算+SM4 加密落盘）开销可忽略，验证了核心管线性能。
- **live**：总耗时分布极不均匀——中位 74 s 但均值 179 s，R6=599 s、R8=499 s、R9=696 s 三个极端值把均值拉高 2.4 倍。三个极端值的共同点：**端点流式输出阶段逐 token 极慢**（236~359 字正文耗 500~700 s，≈0.5 字/秒）。
- **live TTFB**：17 轮中 12 轮 >15 s，最高 39 s；仅 2 轮 <5 s。与快照实测 1.09 s 相比，当前时段端点负载明显恶化。

## 3. 首字 33 s 根因（已实证，高置信）

专项对照（同端点同机器）：

| 实验 | TTFB 结果 |
|---|---|
| 裸 httpx 短 prompt ×5 | 15.5 / 4.5 / 1.2 / 1.3 / 12.8 s |
| 裸 httpx 长 prompt（max_tokens=400） | 4.6 s（但流式总时长 77 s） |
| 完整链路单轮 | 8.7 s（本地开销仅 1~2 s） |
| live 50 轮实测 R1~R17 | 3.4 ~ 39 s，均值 20.6 s |

结论：**33 s 级首字 = NoneLinear 免费端点排队延迟**。本地链路（build_core 42 ms、语义检索 1.8 s 仅首轮、装配结算 1.5~2.2 s）全部可忽略。附加发现：warmup 仅预热 sync 连接池，对话走 async 连接池未预热。

## 4. 待 50 轮完成后复核的疑点

1. **R9~R13 流式后附加等待 65~102 s**：诊断脚本在干净环境未复现（add/search 均 <2 s、collect 0.8 s、persist 1 s），R14 起自动恢复。疑似端点高峰期连接挂起（httpx 600 s 超时窗口）或 chromadb 偶发锁竞争。**需采集完成后用完整进程日志复核**；若复现，加每轮逐函数打点定位。
2. **live R1 档位「陌生」vs mock R1「初识」**：疑好感度 base 初始值在两组装配路径下不同（live 组 storage 从空文件 load 得 0，mock 组历史留痕？），待核对 build_core 装配。
3. **live Δ 全为正或零（无负值）**：语料温柔 + 模型倾向正向；mock 有 8 次 -0.1。样本量不足，不构成异常，但 50 轮后应统计模型对「吃醋/道歉」轮的反应。
4. **情绪识别差异**：live 可识别 -0.5（工作压力轮）、0.65（初见轮）等连续值；mock 关键词词典对「累/压力/孤独/想家」类词汇**零命中**（42/50 中性）。mock 词典覆盖不足，属已知局限，建议后续扩充。

## 5. 预判性结论

- 心智魔方**功能正确性不依赖模型层**：mock 即可 100% 验证架构契约；live 确认真实 LLM 下协议同样遵守。
- **性能瓶颈在端点**：换稳定端点（付费/自建 Ollama）或降频可解决 33 s 首字与 696 s 极值；本地编排非瓶颈。
- 报告最终版将包含：完整 50×2 逐轮数据表、统计分析、R9~R13 疑点复核、协议/好感度/情绪全量轨迹。
