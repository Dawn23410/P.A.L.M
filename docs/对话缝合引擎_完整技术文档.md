# 对话缝合引擎 · 完整技术文档

> 一份整合「架构 + 功能 + 基准测试 + 性能占用」的打包文档
> 生成时间：2026-08-14  | 项目路径：`Desktop/_stitching_demo/`
> 定位：老设备（i3-4 代 / 8G DDR3 / 集显，CPU-only）上、**运行期零联网**、**不跑对话式 LLM**，靠「真实对话语料 + 垂直领域小模型 + 检索回调」模拟 7b 级**流畅度与拟人度**的简易对话系统。

---

## 一、项目定位与五条约束

本系统不是传统生成式 LLM，而是把"生成"替换为"检索 + 重组 + 人格调味"的对话体验模拟器。它的存在前提是：

- 老设备跑不动任何正经生成式 NN（0.7B 都够呛），云端生成要花钱；
- 用户愿意为"能聊、像人、不胡说"付费，但不愿为 token 持续买单；
- 要求在这个老设备、零联网的前提下，**模拟出 LLM 的对话体验**。

| 用户约束 | 落地方式 |
|----------|----------|
| 可用垂直小模型，**禁用对话式 LLM** | 仅嵌入 / 情感分类 / 改写三类**单任务**小模型，**绝不自由生成新事实** |
| 必须有一定语义支持 | 语义检索（bge-small 真实 / 哈希 TF-IDF 离线占位） |
| 语料 = 用户与 LLM 真实对话 | 种子用真实角色扮演集（1000 条）+ 构建期 LLM 同风格扩充（90+ 条）；**用户应替换为本机真实对话日志** |
| 优化侧重对话体验 | 四维优化：贴题度 / 共情 / 不机械 / 连贯 |
| 运行期绝对零联网 | 模型权重与向量全部本地；运行期不发起任何网络请求 |

**核心设计哲学**：回复内容 100% 锚定真实语料（金句）故**不牛头不对马嘴、绝不胡说**；流畅度与拟人度靠数据质量（真人写天然流畅）+ 人格调味 + 情感调语气实现；智商标 7b 达不到，但用户允许"傻"，只要求流畅度 + 拟人度对标 7b。

## 二、整体架构

### 2.1 运行期数据流（核心）

```
用户 query
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ ① 语义检索(Embedder)                                      │
│    bge-small 编码 512 维 → 与 1097 条语料向量余弦重排       │
│    召回 top-N 候选（含检索分）                              │
└─────────────────────────────────────────────────────────┘
   │  候选 + query
   ▼
┌─────────────────────────────────────────────────────────┐
│ ② 情感分类(Sentiment)                                      │
│    词典精准优先（命中"开心/累/怕"直接返回 0.01ms）          │
│    模糊句走多语情感 BERT ONNX 兜底（~29ms）                 │
│    输出：happy / calm / sad / angry / urgent               │
└─────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ ③ 多样性改写(Rewriter)                                    │
│    离线模板变体轮换（加开场白/收尾语气词，避免复读机）       │
│    * 刻意保留离线：无中文改写微调 ONNX，预训练 T5 会胡说     │
└─────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ ④ 短上下文回调(_callback)                                  │
│    轻量话题词承接，记得上一轮                               │
└─────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ ⑤ 人格缝合(_stitch)                                       │
│    四要素组装：[动作]（神态）<内心>正文 + 喵味口癖调味      │
└─────────────────────────────────────────────────────────┘
   │
   ▼
回复（含 matches / emotion / recognized / suggest_llm 字段）
```

### 2.2 构建期数据流

```
种子语料(梦瑶 1000 条 .jsonl)
   + 构建期 LLM 同风格扩充(~90 条 .jsonl)   ← 一次性 token 投入
   │
   ▼
build_corpus.py
   ├─ 合并、四要素解析、清洗
   ├─ Embedder.encode 真实 bge 编码 → 512 维稠密向量
   └─ 落盘 data/：corpus.jsonl / vectors.json / meta.json
```

### 2.3 文件结构

```
_stitching_demo/
├── models/hub.py          # 垂直小模型中心（Embedder/Sentiment/Rewriter 三件套，真实+离线双后端）261 行
├── engine.py              # 运行时：检索→情感→改写→回调→人格缝合                  153 行
├── build_corpus.py        # 构建期：合并语料 + 真实 bge 编码向量落盘               81 行
├── run_demo.py            # demo 入口（示例 / 交互模式）                           68 行
├── benchmark.py           # 基准测试（缝合 vs 本地 7B + 裁判模块）                  264 行
├── perf_probe.py          # 性能与资源占用探测                                     285 行
├── zh_stitch_core.py      # 四要素解析 + 口语表达库（复用）
├── corpus/
│   └── augmented.jsonl    # 构建期 LLM 同风格扩充语料（代理"用户↔LLM 真实对话"）

```

## 三、核心功能模块

### 3.1 垂直小模型中心 `models/hub.py`

统一封装三类单任务小模型，**真实权重本地加载 + 离线占位双后端**，接口一致，权重就位即零改业务代码升级：

| 能力 | 真实后端 | 离线占位 | 大小 | 状态 |
|------|----------|----------|------|------|
| 语义嵌入 `Embedder` | bge-small-zh-v1.5 INT8 ONNX（[CLS]池化 + L2 归一化，512 维） | 字 n-gram 哈希 TF-IDF | 24MB | **real 已生效** |
| 情感分类 `Sentiment` | 多语情感 BERT base INT8 ONNX（词典精准优先 + 模型星级极性兜底） | 情绪词典 | 168MB | **real 已生效** |
| 多样性改写 `Rewriter` | —（无合适中文改写微调 ONNX） | 模板变体轮换 | 0 | **offline 保留** |

`hub.status()` 当前返回 `{"embedder":"real","sentiment":"real","rewriter":"offline"}`。

> 情感分类的两档设计是质量关键：命中"开心/累/怕/急"等精准词直接返回（0.01ms），只对模糊句走真实模型（29ms），既用上语义又不拖慢关键词命中路径。

### 3.2 运行时引擎 `engine.py`

`StitchEngine` 对外暴露两个方法：
- `retrieve(query, k)` → 语义重排返回 `(idx, score)` 候选列表
- `respond(query, history=None)` → 完整流水线，返回：

```json
{
  "reply": "[动作]（神态）<内心>正文 + 口癖",
  "emotion": "happy|calm|sad|angry|urgent",
  "tone_manner": "傲娇|撒娇|...",
  "matches": [["今天好累", 0.992]],   // 检索命中及分值
  "rewrite_variants": ["...", "..."],  // 改写候选
  "recall_real": true,                  // 是否真实语义召回
  "recognized": true,                   // 是否识别（兜底时为 false）
  "suggest_llm": false                  // 是否建议转问 LLM（兜底时为 true）
}
```

人格缝合复用 `zh_stitch_core.py` 的四要素解析（动作/神态/内心/正文）与 `EXPRESSION_LIB`（19 类 100+ 口语变体，喵味口癖、傲娇语器）。

### 3.3 构建期 `build_corpus.py`

合并种子 + 扩充语料 → 四要素解析 → 真实 bge 编码 → 落盘 `data/`。构建期一次性投入 token（LLM 扩充），运行期零 token、零联网。

### 3.4 兜底机制（已改造）

**改造前**：检索无匹配时用"没听清 / 再说一遍"误导性话术——会让用户误以为系统能答只是没听清。
**改造后**：明确告知"对话库里没有能接上的回答，怕乱答骗你"，**主动建议用户去问大语言模型**：

```
触发条件：检索 top1 无自信匹配（低于次优 ×1.05 或低于 0.02）
行为：诚实兜底 + 建议问 LLM，返回 recognized=False / suggest_llm=True
示例回复：杂鱼，这道题超出猫娘能答的范围啦，硬答会出错。建议直接问大语言模型，它们更在行
```

> 注意：下方**基准测试表里的缝合回复是兜底改造前的实测快照**（部分越界句显示旧话术），属历史记录。兜底逻辑本身已于基准后按上述方案重写并验证。

## 四、对话体验四维优化

| 维度 | 手段 | 实现位置 |
|------|------|----------|
| **贴题度**（地基） | 语义检索 + 余弦重排，原样查询召回 0.98、近邻 0.6–0.8 | `Embedder` + `engine.retrieve` |
| **共情** | 情感分类驱动回复语气（喜则甜、哀则柔、急则慌） | `Sentiment` + `engine._tone_for` |
| **不机械** | 多样性改写（开场白/收尾语气词轮换）+ 口语表达库 | `Rewriter` + `EXPRESSION_LIB` |
| **连贯** | 短上下文话题词回调，记得上一轮 | `engine._callback` |

> **关键诊断**：ollama `/api/ps` 显示该 7B `size_vram=0`——**纯 CPU 推理**，正是"老设备零 GPU"的真实写照。

### 6.2 客观代理指标

| 指标 | 缝合引擎 | 本地 7B | 说明 |
|------|---------|---------|------|
| 中文纯净度 | **0.827** | 0.613 | 7B 常混英文（如 `currentlySingle`）破功 |
| 角色口癖命中（均值） | **2.25** | 1.62 | 缝合口癖更稳定 |
| 贴题度（二元组匹配率） | 0.309 | **0.632** | 对检索式系统有偏，详见缺陷 |

### 6.3 基准结论

1. **优势区**（角色内/寒暄/情绪）：缝合检索召回高（0.985–0.993）、口癖自然人设稳、零生成故**绝不胡说**。
2. **盲区**（开放越界）：缝合直接兜底（诚实），7B 能编但可能幻觉——这是**定位差异，非缺陷**。
3. **7B 短板**：知识广度碾压，但角色扮演偶发错位（把用户"累"说成自己累）、且需 4.7GB 常驻 + 秒级推理。
4. **缝合定位**：毫秒级、<200MB 常驻、零 token、零联网——老设备/零成本对话平替的合理选择。

## 七、性能与资源占用

> 运行环境：managed Python 3.13 + onnxruntime(CPU)。实测数据来自 `perf_probe.py`（ctypes 取进程工作集 + 组件计时）。

### 7.1 磁盘占用

| 文件 | 体积 |
|------|------|
| `models/weights/sentiment.onnx` | 160.3 MB（占大头） |
| `models/weights/bge_small.onnx` | 22.8 MB |
| `data/vectors.json` | 11.8 MB |
| `models/weights/sentiment_tokenizer.json` | 2.4 MB |
| `models/weights/tokenizer.json` | 428.8 KB |
| `data/corpus.jsonl` | 316.0 KB |
| **合计** | **198.1 MB** |

> 情感模型 160MB 是公开最稳真实多语底座（base 级）；换中文 tiny 分类底座自转 ONNX 可压到 ~15MB。

### 7.2 内存占用（进程工作集 RSS）

| 阶段 | RSS | 增量 |
|------|-----|------|
| 基线（numpy/onnxruntime） | 37.9 MB | — |
| + Hub（bge + 情感 + tokenizer） | 276.0 MB | +238.1 MB |
| + 引擎（1097 条语料 + 向量索引） | 300.6 MB | +24.6 MB |
| 稳态（连续推理后） | 320.7 MB | — |

**引擎额外常驻 ≈ 263 MB**（模型权重占大头，Python 索引对象仅 4.4MB），8G 老设备毫无压力；CPU 推理**无显存占用**。

### 7.3 延迟与吞吐（预热后）

| 阶段 | 平均耗时 | 说明 |
|------|---------|------|
| 语义编码 bge（单句 512 维） | 8.73 ms | 真实 ONNX 推理 |
| 情感·词典快通道 | 0.01 ms | 命中情绪词跳过模型 |
| 情感·真实模型 | 29.39 ms | 模糊句兜底 |
| 检索（1097 条余弦扫描） | 90.36 ms | **纯 Python 循环，瓶颈项** |
| 完整 respond（关键词路径） | 76.26 ms | 全流水线 |

**稳态吞吐**：平均 **140.82 ms/条 ≈ 7.1 条/秒**（60 条混合 query 实测）。
对比同机 CPU 7B（53.8s/条），快约 **380–700 倍**。

> 检索 90ms 是瓶颈（纯 Python 1097×512 余弦循环），可用 numpy 矩阵化一次点积压到 <5ms（低垂优化，本次"测"的范围外，待做）。

## 八、已知缺陷与边界（诚实）

### 缺陷
1. **弱召回桥接错位**：「我好开心呀」top1 仅 0.682，被错接"无聊"语料的桥，回复变成"无聊？那正好陪猫娘玩"，与开心情绪相反。改进：在 `_pick_bridge` 前加情感/意图门控，丢弃与当前情绪冲突的桥。
2. **贴题度指标对检索式系统有偏**：该指标统计用户 query 二元组是否出现在回复，7B 因直接复述偏高；缝合回复来自语料未必含原词。建议补"情绪一致率"更公平。
3. **本地裁判未启用**：`local_model:latest` 纯 CPU 单条 >4 分钟；`judge_pair` 代码保留待 GPU。

### 边界
- **覆盖天花板**：没聊过的话题检索召回弱；用更丰富真实对话语料可缓解。
- **种子语料为角色扮演代理**：应把 `build_corpus.py:SEED` 指向**用户自己的真实对话日志**再测覆盖度。
- **情感已是真实模型**（base 168MB，可换 tiny）；**改写保持离线模板**（无合适中文改写 ONNX，离线模板不脱离锚定语料、绝不胡说）。

## 九、总结

对话缝合引擎在「零部署 / 零 token / 零联网」前提下，用 **263MB 常驻内存 + <100ms 单句响应 + 7.1 条/秒吞吐**，在窄域人格对话上实现了对标 7B 的流畅度与拟人度，并因"回复锚定真实语料"而**绝不胡说**；开放问答主动诚实兜底（引导问 LLM），这是其定位差异而非缺陷。瓶颈在语料覆盖度，不在算力——是老设备零成本对话平替的合理选择。

**下一步可选**：
1. 修掉"开心→无聊"桥接错位（加情感门控）；
2. 把 `build_corpus.py:SEED` 换成用户真实对话日志，再测覆盖度提升；
3. 检索 numpy 矩阵化压到 <5ms；
4. GPU 环境启用 `judge_pair` 自动打分，补主观维度量化。
