# P.A.L.M 模块复用性分析报告

> 📅 **时间线**：2026-08-12 生成（Trae 会话产物）
> 原始可视化版本见 archive/ 备份。

- **7** 可直接抽走复用

- **9** 需小改即可复用

- **6** 可直接替换模块

- **8** 深度耦合不可抽

评估标准说明

- 直接复用 无P.A.L.M特有依赖，接口清晰，复制目录就能用
- 小改复用 依赖1-2个内部基类或配置，剥离即可独立
- 可替换 有标准接口定义，可以换成其他实现
- 深度耦合 依赖主板/Agent/砖块框架核心，抽离成本高

## 一、可直接抽走复用的模块（7个，约6,200行）
这些模块内部自洽，仅依赖Python标准库或通用第三方库，没有P.A.L.M主板/Agent/砖块框架的深度依赖，其他人复制过去改改配置就能用。

| ---------------------------- | ----- | -------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |

## 六、客观评价与建议

### 复用价值最高的"黄金模块"
- sandbox三层沙箱（3166行）：开源独一份的AST+网络拦截+蜜罐三合一，AI Agent安全领域的硬需求，抽离成独立库价值最大
- world_model_cache屏幕世界模型（~1500行）：解决GUI Agent最大痛点（token消耗），增量diff思路在开源GUI Agent领域无人实现
- completion_gate完成门（142行）：短小精悍，解决Agent"虚假完成"的通用痛点，适合做成轻量PyPI包
- emotion_detector+affinity情感系统（1260行）：非对称编码+6阶段关系模型，AI伴侣/陪伴机器人领域有需求
- code_guard代码安全校验（296行）：轻量AST检查，无依赖，适合作为AI代码生成的前置校验器

### 架构层面观察
- 模块化做得比预想的好：砖块架构确实实现了解耦，有近30%代码（~1.5万行）可以低成本抽离复用
- 核心模块耦合度高是正常的：主Agent+前端占了50%代码，这是产品的"灵魂"，本来就不该被抽走，整体fork才有意义
- 接口抽象还有提升空间：部分可复用模块（如裁决引擎、记忆系统）仍继承Brick基类，如果一开始就用Protocol/Interface会更利于开源复用
- 安全相关模块复用价值最高：sandbox/code_guard/trust_root/pollution_guard/completion_gate这一整套安全闭环，在开源Agent框架里普遍缺失

### 如果开源，建议优先独立出去的模块顺序
- completion_gate（142行，零依赖，最容易做成独立包）
- code_guard（296行，零依赖，通用需求）
- eventbus（96行，零依赖，通用工具）
- sandbox（3166行，核心创新点，价值最大但剥离需要点工作）
- emotion_detector（263行，通用情感识别）
- world_model_cache（~1500行，GUI Agent刚需）
