# dynprobe.py 制作规格 — 通用动态测试工具（边界 / 并发 / 安全 / 模糊 / 资源）

> 状态：**已实现并验证**（2026-09-04）。dynprobe.py ~1300 行零依赖，五族全通，demo 自测 + 三开源库对照。
> 调研依据：2026-09-04 五路检索（BVA/EP、并发、OWASP SAST、PBT、混沌工程）。

## 0. 被测对象抽象（工具核心难点，先定这个）

`--target` 三种形态，能力降级设计——跑不动就自动降级为静态/清单模式，绝不硬失败：

| 形态 | 写法 | 可执行探测 | 不可执行时的降级 |
|---|---|---|---|
| 白盒函数 | `module::func`（import 后直调，可传参可并发） | 边界/模糊/并发全开 | import 失败 → 只给目标函数的 AST 静态结论（签名、参数类型猜测） |
| 黑盒命令 | `cmd:python app.py --port 9000` 或 `cmd:./bin`（subprocess 喂 stdin/argv，测退出码/stderr/超时） | 边界(CLI 参数)/模糊(随机 argv+stdin)/超时 | —（命令本身不可用则报错退出，不降级） |
| HTTP 端点 | `url:http://127.0.0.1:9000/api`（GET/POST，测状态码/响应/时延） | 边界(参数注入)/并发(加压)/安全(动态头与注入探测) | 连接失败 → 提示需先起服务，不硬跑 |

族选择 `--kind boundary|concurrency|security|fuzz|resource`，可 `--kind boundary,concurrency` 组合。
通用输出：发现列表(文件/用例/现象/严重度) + 汇总指标 + 0–100 分 + 字母级 + `--fail-under N` 门禁。

## 1. 边界测试族 boundary（最高性价比，先做）

**规则：EP 划分 + 三值 BVA（B-1/B/B+1）。** 商用两值即可，P.A.L.M 商用级 + guardrail 语义 → 用三值。
调研要点（mastersoftwaretesting/sudarshantechlabs/softwaretestpilot/ISTQB 口径）：
- BVA 单测性价比最高，EP 负责裁剪空间；**只测有效分区是最大错误**，无效分区至少与有效等量。
- 每边界三值：B-1, B, B+1；区间 [a..b] → a-1,a,a+1,…,b-1,b,b+1。
- 分区必须互斥；一次只注入一个无效值（其余字段有效）；组合行为用 pairwise/决策表。

**内置生成器（按参数类型，从目标签名或 `--args` 声明推断）：**

| 类型 | 用例集 |
|---|---|
| int | min-1, min, min+1, max-1, max, max+1, 0, -1, 1, ±MAX, ±MAX±1, NaN 邻域(见下) |
| float | ±0.0, -0.0, 极小(1e-308), 极大, ±Inf, NaN, 0.1+0.2 精度陷阱, ±1e308×10(溢出) |
| str | "", 纯空白, 1 字符, min-1/min/max/max+1 长, 超长(10×max), 控制字符, 全角/emoji/零宽, 无效 UTF-8 字节, 换行/引号注入样本, \x00 |
| list/dict | [], [1], 1 元素边界, N 元素边界, 嵌套深(JSON 深度), 超大(内存边界), 键冲突, None 混入 |
| date/time | 上/下边界, 闰年 2/29, 月末, 时区切换, 2038/9999, 非法 13/45 |
| bool/枚举 | None, 未提供, 枚举外值, 类型错乱("1" 当 int) |
| 特殊 | 半开区间, 求和=n 的 n-1/n/n+1, 有序集合首尾, ASCII 邻界 @/A/Z/[ |

**量化输出：** 每目标 N 个用例 → 通过/异常/挂起(超时)/崩溃 计数；异常里区分"被正确处理(有异常类型/错误码)"与"裸崩(未捕获/非预期类型)"——后者才是缺陷。分数 = 100 − 裸崩×25 − 挂起×15 − 错误码不一致×5。

## 2. 并发测试族 concurrency

**调研要点：** 竞态/死锁/活锁/饥饿/数据损坏/线程安全；关键信号 = 吞吐不再随并发上升（饱和点）、时延上升而吞吐平坦、错误率尖峰；**测试贵在"同时刻争抢同一资源"，不是用户总数**。

**台阶加压协议（默认 1→2→4→8→16→32→64，可 `--max-conc`）：**
每级并发 N：并发调用 M 次（默认 100×N）→ 记 吞吐(QPS)/时延分位/错误率。
- 饱和点 = 吞吐首次环比 <5% 增长时的上一级（saturation_conc）
- 失速判定：p99 与 p50 比值 >10 或错误率 >2% → 标记 collapse
- 平坦健康：时延平、吞吐升 ✓；时延升、吞吐平 = 饱和信号
- 白盒模式附 Lost-update 自检：`--selfcheck module::func` 要求函数含累加语义时给出期望值，比对实际（如 shared_counter 期望 20×500，丢更数即 race 证据）
- 死锁探测：每级加全局限时（默认 30s），超时未完成 = 疑似死锁/活锁；输出等待中的调用栈

**量化输出：** 各级 QPS/p50/p95/p99/错误率表 + 饱和点 + 崩溃/异常数 + 丢更新%（白盒自检时）。分数：基线级(1)与饱和级差距、错误率、异常数加权。

## 3. 安全测试族 security（静态为主，动态可选）

**调研要点（JFrog SAST 规则表 / OWASP Top10 2021 / CodeAnt 映射）：** SAST 强项 = 注入(A03)、加密失效(A02)、漏洞组件(A06)；弱项 = 设计(A04)/日志(A09) 需动态。高置信度检测来自明确定义的 sink 模式。

**规则骨架（AST 模式匹配，Python 优先，映射 OWASP 2021）：**

| 类别 | 检测模式示例 | 严重度 |
|---|---|---|
| 命令/代码注入 A03 | `os.system/eval/exec/__import__/subprocess(shell=True)` 且参数含非字面量 | high |
| 硬编码凭据 A07 | `password|token|secret|api_key\s*=\s*"..."` 字面量(非空串/非占位符) | high |
| 弱密码学 A02 | `md5/sha1(密码场景)/DES/RC4/AES-ECB/random(安全场景)` | medium |
| 不安全反序列化 A08 | `pickle.loads/yaml.load(Loader=unsafe)` 默认 | high |
| 路径遍历 A01 | `open(...)` 参数拼接用户输入未 sanitize | medium |
| SSRF A10 | `requests/urllib(url=外部输入)` 无校验 | medium |
| XXE A05 | `xml.etree` 未禁用外部实体 / `lxml` 默认 | medium |
| 危险 web 配置 | `Flask debug=True`、`CORS *`、`verify=False` | medium |
| SQL 注入 A03 | f-string/`%`/`+` 拼 SQL | high |
| 日志泄露 A09 | 打印/日志含密钥变量 | low |
| 栈追踪暴露 A05 | 异常处理打印 `traceback`/`e` 到响应 | low |
| 不安全随机 A02 | 密码/token/OTP 用 `random` 而非 `secrets` | medium |

**动态(仅 url 形态)：** 缺安全头检测(HSTS/CSP/X-Frame-Options/X-Content-Type-Options)、`Server:` 指纹暴露、OPTIONS 方法敞开、错误页泄露（触发 404/500 看 body 是否含 traceback/路径）。
分数 = 100 − high×25 − medium×10 − low×3（截到 0）。**误报率高规则需实测调参后保留**（沿用 AI_CODE_STANDARD 误报率>10% 删规则原则）。

## 4. 模糊/属性测试族 fuzz（白盒与黑盒命令形态）

**调研要点（QuickCheck/Hypothesis/JQF-Zest/OSS-Fuzz）：** PBT = 生成器 + 不变量；crash 只是浅 oracle，语义漂移要靠属性。Hypothesis 核心 = 统一字节流表示 + 自动 shrinking。零依赖约束下做不了完整 Hypothesis，但可以做：
- **生成器**：复用 boundary 族的类型生成器 + 随机混合(有效/畸形/超大/结构突变)
- **内置通用不变量**：不崩溃、不裸异常、输出类型稳定、幂等/roundtrip(用户提供属性函数 `--prop module::prop` 时启用)
- **最小化复现（简化版 shrinking）**：发现失败输入后二分删减（字符串去半/数值逼近/列表减半），输出最小复现样本——这是最有价值的部分，OSS-Fuzz 25k bug 的可用性全在 shrink
- 迭代上限 `--runs N`(默认 500)，固定种子 `--seed` 保证可复测
- 每次执行限时（默认 2s），超时即记"挂起"防无限循环输入

**量化输出：** runs/崩溃数/裸异常数/属性违反数/最小复现样本/覆盖率代理(可黑盒统计响应码多样性)。分数 = 100 − (崩溃+属性违反)×20 − 挂起×10。

## 5. 资源耗尽族 resource（轻量，白盒/命令）

大输入 → 内存/时间边界：超大 list/超长 str/深嵌套/大文件 → 测 OOM(子进程或 subprocess 隔离跑，防拖垮宿主)、超时、优雅拒绝(应报错而非崩)。
- 子进程隔离：白盒函数用 `multiprocessing` 子进程 + 内存上限探测（RSS 峰值采样）
- 分数 = 100 − OOM 崩×30 − 超时无响应×15 − 无优雅拒绝×5

## 6. 混沌工程（本工具不做，规格仅备忘——需编排层+root，留给运维域）

调研要点（Netflix 原则/OneUptime/Chaos Toolkit）：稳态假设(量化 SLO) → 假设 → 注入 → 对照测 → 学习；**必须有 kill switch 与爆炸半径矩阵**，无 kill switch 的实验是破坏。故障注入清单：实例终止/网络时延·丢包·分区/DNS 失败/CPU·内存·磁盘耗尽/依赖 500·超时/时钟偏移/证书过期。
P.A.L.M 适用场景在 palm-watchdog/cloudflared 隧道层（host 级 GameDay），不属于零依赖静态工具的输入契约，故不并入 dynprobe。

## 7. 分级与门禁（对齐全家桶口径）

- 0–100 分 + A(≥90)/B(≥75)/C(≥60)/D(≥45)/E(<45)；`--fail-under N` 非零退出
- `--json out.json` 全量留证（对齐 codequal_PALM_*.json 惯例）
- `--demo` 自带自测（对齐其余 7 脚本）
- 阈值全部 `--thr key=value` 可覆盖，默认值写死为上述口径

## 8. 落地顺序建议（小步）

1. **boundary 族**（纯生成器+白盒/CLI 探测，不依赖网络，最快出价值；黑盒 cmd 形态顺带覆盖边界 argv 用例）
2. **fuzz 族**（复用 boundary 生成器 + 最小化复现，增量小）
3. **concurrency 族**（台阶加压协议，纯 stdlib threading/subprocess，注意 GIL 说明）
4. **security 静态族**（AST 规则集，参照 JFrog 表，先 8–10 条高置信规则再扩）
5. resource 族 + url 形态动态探测收尾
