## 3. 重建方法

纯 plumbing（`git commit-tree`），零工作区扰动：

```
9e87f93（08-18 基线根）
  └─ 98 笔 empty commit（subject = [原SHA] 原始message；author/commit date = 原日期）
       └─ merge main（树取 main，两个父提交对接两侧历史）
```

- 分支名：`history/reconstructed`，与 main 共存，**main 的 10 笔 SHA 未被改写**，远端无需强推。
- 时间精度：**日级**（文档只记到天）；日内按文档顺序铺 09:00 起每笔 +3 分钟，保证同日内先后正确。08-18 之前的"真实时刻"已不可考。
- 交付脚本：`knowledge/ima_kb/_rebuild_history.py`（数据源 `knowledge/ima_kb/_old_history.json`，可重放）。

## 4. 已知局限

1. **新旧 SHA 无对应关系**：旧 SHA（如 `355decb`）仅作为标记保存在新提交的 message 里，指向的是新链上的空提交。
2. **empty commit 无 diff**：两笔重建提交之间 `git diff` 无意义——内容颗粒度只到 08-18 基线快照。
3. 08-11 ~ 08-18 之间无提交记录可考（时间线文档止于 08-10，08-11 收口无独立条目）。
4. 一条特殊事件未入链：「Agent 内核可插拔重构」为 Trae 会话，原文标注"未提交 git"。
5. 日内时刻（09:00 +3min 序列）为编排值，非历史真实值。

## 6. 防复发

重构/重建仓库前先打全量 bundle（秒级）：

```bash
git bundle create ../PALM_backup_$(date +%Y%m%d).bundle --all
```

bundle 同时含全部历史与全部分支，clone 它即可完整还原。
