> 测试时间：2026-08-15 11:05（后台完整跑通，两模型各 9 轮）
> 测试设备：RTX 5060 Laptop 8GB 显存（CUDA），Windows 11
> 测试文本：短（12 字）/ 中（40 字）/ 长（90 字 出师表节选），各 3 轮取中位数

---

## 一、总览

| 指标 | GSV（GPT-SoVITS v2final，音色克隆） | QwenTTS（Qwen3-TTS-12Hz-1.7B VoiceDesign，NF4 4bit） |
|---|---|---|
| **服务启动耗时** | 18.6 秒（启动即同步加载模型） | 3.1 秒（懒加载，秒起服务） |
| **首次合成（模型加载）** | 0.51 秒 | 27.1 秒 |
| **显存占用** | 基线 2506 MiB，峰值 2540 MiB（恒定） | 基线 3242 MiB，峰值 4656 MiB（随文本变长增长） |
| **内存占用（RAM 工作集）** | 基线 3656 MiB，峰值 3719 MiB | 基线 2240 MiB，峰值 2288 MiB |
| **权重磁盘占用** | 1.2 GB | 4.3 GB |
| **平均端到端延迟** | 3.04 秒 | 42.56 秒 |
| **平均实时倍率 RTF** | 0.47x（≈ 2.1 倍实时，**快于实时**） | 2.69x（比实时慢 2.7 倍） |
| **流式首包** | 无（整包返回） | 无（整包返回） |

RTF = 合成耗时 ÷ 音频时长；**< 1 即比实时快，> 1 即比实时慢**。

## 三、关键结论

### 速度 / 延迟
- **GSV 全面碾压**：短句 0.8 秒出结果，长文本 6.4 秒合成 16 秒音频（2.5 倍实时），日常对话完全无感。
- **QwenTTS 明显偏慢**：短句要 6.6 秒，90 字长文本要 94 秒（比实时慢 2.7 倍）——这是 12Hz 自回归 token 逐帧生成 + 1.7B 模型在笔记本 GPU 上的真实代价，**不适合实时对话场景**。

### 资源占用
- **显存**：GSV 恒定 ~2.5 GB，且不随文本变长增长；Qwen 基线 3.2 GB，长文本涨到 4.6 GB（快占满 8 GB 的一半）。两者都无法与 7B LLM 同时常驻。
- **内存**：Qwen（~2.3 GB）比 GSV（~3.7 GB）省 1.4 GB。
- **磁盘**：Qwen 权重 4.3 GB ≈ GSV 的 3.6 倍。
- **启动**：Qwen 懒加载、服务 3 秒起（但首次合成要等 27 秒）；GSV 启动即加载（18.6 秒），之后首句 0.5 秒出。

### 选型建议
| 场景 | 推荐 |
|---|---|
| 实时对话 / 低延迟响应（本项目核心场景） | **GSV**：快 20 倍以上，显存恒定 |
| 一次性批量生成 / 对延迟不敏感 | 两者皆可，Qwen 音质/情感表现更好 |
| 服务常驻 + 内存紧张 | Qwen（RAM 低），但需接受长文本慢 |
| 需要音色克隆（复刻指定人声） | 仅 GSV 支持（参考音频克隆） |

**对本项目（P.A.L.M 对话系统）的结论**：GSV 的延迟与显存特性明显更适合做实时 TTS 主引擎；QwenTTS 可作为离线批量 / 高音质备选。若二选一常驻，建议 GSV。

## 四、测试说明

- 串行测试（GSV → Qwen），避免同时占显存互相干扰；系统桌面进程（约 1.1 GB 显存基线）为日常真实状态。
- 模型均已在本地（离线）加载：GSV 用 `plugins/tts_sovits` 自带权重，QwenTTS 用 `Data/qwen_tts_model/` 预下载权重（4.3 GB）。
- 首包延迟 ≈ 端到端延迟（两模型均非流式，整包返回）。
- 测试脚本：`bench_tts_local.py`（可用 `--rounds N` 调整轮数）；原始数据：`tts_bench_local.json`。
