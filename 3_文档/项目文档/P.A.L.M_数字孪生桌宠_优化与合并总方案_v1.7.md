## 0. 一句话结论

> P.A.L.M 现在**不缺渲染、不缺内核、不缺算法**——缺的是「**感知 → 推断 → 情感 → 驱动 → 表达 → 执行**」这条链路的**接线**，以及最上游「**现实世界感知层**」（目前为零）。

#### 2.7.3 新增风险：96 处歧义名裸 import

这是 v3 挖出的**此前完全不可见**的风险，量级仅次于 324 违规：

- **形态**：`import xxx`，而 `xxx` 这个名字在**多个模块**下都存在（如 `tool` 同时属于 `2_实验/GUI自动化` 与 `app/gui`）
- **危害**：加载哪一个取决于 `sys.path` 的**顺序**，而顺序由启动方式决定 → **同一份代码，从 A 入口跑和从 B 入口跑，行为不同；且这种差异不会报错，只会静默跑偏**
- **为什么 v2 看不见**：v2 把这类名字归类为 `third_party` 后就不再分析，等于**主动丢弃**；v3 单列为 `ambiguous_imports` 并在 `new` 规则下判为 R7 违规
- **治理**：随 M2 迁移按批次消解——模块一旦包内化（`modules/tool/palm_tool/`），顶层名唯一，该类风险自动归零

#### 2.9.3 信任边界缺口（**第二个 P0**）

| 事实 | 证据 |
|---|---|
| 目标产品必须读屏 / 剪贴板 / 文件 / 网页 | F1 + F18（v1.3 已定为 P0 能力） |

| 一旦被注入，后果不是"说错话"，而是**以用户身份执行动作**（发消息/改文件/下单） | 本产品定位就是"帮用户干活"（F10） |

**这不是理论风险。** CaMeL 论文（Debenedetti et al., Google DeepMind / ETH Zurich，SaTML 2026，arXiv:2503.18813）在 AgentDojo 上的结论是：

- 单模型 + 输出过滤/护栏：**真实注入下基本可绕过**（改写措辞即可）
- CaMeL（控制流/数据流分离 + 能力标签）：**阻断 67%–100% 的注入**，同时保留高任务效用（披露的代价：任务完成率 77% vs 无防护基线 84%）
- 关键机制不是"检测坏内容"，而是**让不可信数据根本没有通往工具的通路**

> 顺带修正一个 v1.2 的乐观假设：F14 的"能力令牌"当时是**授权**语义（用户同意了没），F28 要的是**数据流**语义（这个值从哪来、允许流向哪个工具）。两者同名不同物，必须分开实现。

#### 2.9.4 泛化检测查出的真 bug：BOM 导致静态分析静默漏检

**发现过程**：`hygiene_check` 首版用 `utf-8` 读文件，报出 3 个"语法错误"文件。查证后确认是 **UTF-8 BOM**（`EF BB BF`）而非语法错：

```
2_实验/显示层/palm_display/pack.py              <- 自有模块
2_实验/显示层/palm_display/widget_settings.py   <- 自有模块
1_Demo_LLM/语音合成_CosyVoice2/dl.py
```

`ast.parse()` 对带 BOM 的文本抛 `SyntaxError: invalid non-printable character U+FEFF`。

**危害比报错更严重**：`arch_check.py` 第 62 行正是 `ast.parse(path.read_text(encoding="utf-8", ...))`，异常被 `except` 吞掉后**返回空 import 列表** —— 意味着这 3 个文件的所有依赖边**从依赖图里静默消失**，而且**没有任何日志**。

**修复与验证**

| 动作 | 内容 |
|---|---|
| 修 `tools/arch_check.py` | `encoding="utf-8"` → `"utf-8-sig"` |
| 修 `tools/compliance_check.py` | 编码回退链首位加 `"utf-8-sig"`（BOM 残留会干扰词根匹配） |
| 本工具 | 用 `utf-8-sig` 读（BOM 透明剥离，文件**照样被完整分析**），BOM 另立 **H9** 单列 |
| 验证 | 同文件 `utf-8` → FAIL / `utf-8-sig` → OK（12 个顶层节点） |

**修复后重跑架构基线：324/62/114/96/3/1/0 全部未变。** 必须如实说明 —— 说明这 3 个文件的 import 恰好没有产生新的跨模块边（一个在第三方标记内、另两个的 import 均为相对/标准库）。**这次修的是"随时可能吃掉结论的隐患"，不是已经发生的漏计。** 但如果不修，下一次有人给一个带 BOM 的关键模块加 `import`，架构图会安静地少一条边，且没人会知道。

#### 2.9.6 第三个陷阱：合规"覆盖率"会随文档变长而虚涨

写完 v1.5 文档后重跑合规器，出现一个**看起来像大进展**的变化：

| 指标 | v1.4 基线 | v1.5 写完文档后 | 困惑 |
|---|---|---|---|
| 强制项覆盖率 | 63.6% | **100.0%** | 一行代码没写，怎么就 100% 了？ |
| ok / partial / missing | 1 / 9 / 5 | 1 / **14** / **0** | 5 项"缺失"凭空消失 |
| **强制项真落地** | **1/11** | **1/11** | 纹丝不动 |

**原因（逐条查证据确认）**：v1.5 新增章节（3.23 / 3.24 / F28–F33 / 风险表）里提到了"过度依赖/沉迷"、"迎合抑制"、"AI 生成合成内容标识"、"未成年人"等词 —— 合规器按 v2 口径把**文档提及**记为 `partial`，于是 5 项强制 `missing → partial`：

```
C3 missing -> partial   过度依赖风险预警
C6 missing -> partial   迎合抑制
C7 missing -> partial   AI 生成合成内容标识
C8 missing -> partial   未成年人保护
C9 missing -> partial   老年人权益保护
```

按 v2 口径**这个判定是对的**（确实只是文档提及，不是 ok），问题出在**汇总指标**：`覆盖率 = (total - missing)/total` 把"文档提及"和"代码实现"混为一谈，**文档写得越详细，覆盖率越高**。

**更危险的是趋势对比**：v1 的 `_diff` 用 `mandatory_missing` 集合差判断"已补齐"，于是直接输出：

```
[*] 已补齐: C3, C6, C7, C8      <- 代码一行没写
```

这是 v1.4"文档当实现"陷阱的**变体重演**：v1.4 是**工具误报**（已由 v2 修掉），这一次是**指标口径本身会被文档绑架**。

**修法（已落码）**

| # | 修法 | 防住什么 |
|---|---|---|
| 1 | 新增 `mandatory_landed`（只数 `ok`）+ `mandatory_code_coverage`（代码级覆盖率 9.1%），并标注为**唯一可信的进展指标** | 覆盖率虚涨 |
| 2 | 新增 `mandatory_doc_only`（10 项）单列，并在输出里直写"**不要当进展指标**" | 文档绑架指标 |
| 3 | 修 `_diff` 方向：v1 对所有计数统一 `c>=b → OK`，导致 **missing −5 被判 WORSE、partial +5 被判 OK**（完全反了） | 趋势方向倒挂 |
| 4 | 修"已补齐"判定：只认 `missing/partial → **ok**`；`missing → partial` 改报「**仅文档提及（不是实现）**」 | 假进展 |
| 5 | 把 ①② 固化成回归用例 **G4**（`t_trend_doc_only_not_progress`） | 下次改规则时回潮 |

**修复后的输出**（同一份代码库）

```
[i] 强制项已落地   : 1/11  (代码级覆盖率 9.1%)
[i] 状态分布       : ok 1 / partial 14 / missing 0
[i] 仅文档提及     : 10 项 ['C1','C2','C3','C4','C5','C6','C7','C8','C10','C11']
    ^ 含 partial 的覆盖率 100.0% 会随文档变长虚涨，**不要当进展指标**

== 与基线对比 ==
  ok          1 -> 1   (+0) 持平
  partial     9 -> 14  (+5) INFO
  missing     5 -> 0   (-5) OK
  landed      1 -> 1   (+0) OK   <- 唯一可信的进展指标
  [~] 仅文档提及（**不是实现**）: C3, C6, C7, C8, C9
```

> **一句话记住**：**合规进展只有一个指标 —— `mandatory_landed`（当前 1/11）。** 任何"覆盖率"只要把文档提及算进去，都必然随文档变长而上升，与实现无关。
>
> 这条对**所有**"扫描式自检器"通用：指标口径必须能抵抗"只是被写到文档里"这种零成本变化，否则指标会奖励写文档、惩罚写代码。

#### 2.10.4 泛化检测当场查出并修掉的真 bug：`--rules new` 空扫描假绿

`arch_check <空目录或规则集不匹配的根> --rules new --strict` 会输出"0 违规"并 **rc=0**。
迁移到 M2 阶段后，如果有人把根路径写错或 `modules/` 尚未建立，CI 会**一路绿灯**。

| 修法 | 位置 | 行为 |
|---|---|---|

## 3. 技术选型（联网调研结论）

### 3.1 现实世界感知 —— 参照 Screenpipe（YC S26）

| 要点 | 结论 |
|---|---|
| **架构** | Rust 核心 + 本地 SQLite + MP4 + Markdown；REST/WebSocket API（:3030）+ MCP |
| **关键教训** | 早期"每帧录屏 + 全量 OCR"把笔记本变成暖手宝 → 改为**事件驱动**：只在 app 切换 / 点击 / 输入停顿 / 滚动 / 空闲变化时采集 |
| **优先级** | **先吃 OS 已有的结构化数据（Accessibility Tree / 窗口元数据）**，OCR 仅作为结构化数据不可用时的兜底 |
| **资源占用** | 本地推理 <1% CPU、<400MB RAM |
| **隐私** | 本地优先 + 本地 PII 脱敏模型（Apple MLX / Windows DirectML），**脱敏必须在入库前完成** |
| **对本项目** | 直接复用此分层：`采集 → 结构化优先 → OCR 兜底 → 脱敏 → 时序库` |

⚠️ **反面教材：Windows Recall** —— Kevin Beaumont 发现其 OCR 明文存于**未加密 SQLite**，开源工具 TotalRecall 可在 <2 秒抽取数月敏感活动。
→ **本项目硬要求**：感知数据落盘**必须**经 `palm_cryptokernel`（SM4-CBC + SM3 完整性标签）加密，且默认**只存结构化元数据、不存原图**。

### 3.2 主动关怀时机 —— Horvitz 打断成本模型

| 来源 | 结论 |
|---|---|
| **决策规则** | `intervene 当且仅当 E[benefit] − E[cost of interrupting] > θ` |
| **Horvitz 1999** | 打断成本建模为「对推断出的注意状态的期望」 |
| **Iqbal & Horvitz 2007** | 单次警报后**认知恢复期 20–25 分钟**；**27% 被打断的任务再也没恢复** |
| **JetBrains/CMU 2026 田野研究**（15 开发者 / 229 次干预 / 5732 交互点） | **工作流边界**（如 post-commit）接受率 **52%**；**任务中途**干预被忽略 **62%**；时机得当的理解耗时 **45.4s vs 101.4s** |
| **AHs'26（N=21）** | 纯多模态推断不足；**提供用户历史评分可显著提升**；存在强时间效应 |

→ **本项目落地**：`drives.py` 必须实现**双侧账本**（benefit 与 cost 都要估），禁止只做"置信度阈值"（那是"穿着成本收益外衣的阈值"）。至少实现：静默时段、冷却期 ≥20 分钟、工作流边界优先、用户反馈回写。

### 3.3 情感计算 —— PAD 三维模型

- **P**（Pleasure 愉悦度）∈[-1,1]；**A**（Arousal 唤醒度）；**D**（Dominance 支配度）
- 现有桌宠 `Mood` 用的是 **Russell 环形二维**（valence + arousal）→ **建议补第三维 Dominance**，得完整 PAD
- 衰减公式与记忆强度同构：`S(t) = S₀ · e^(−λ·Δt)`
- 大五人格（OCEAN）作长期性格底座，PAD 作瞬时情绪状态 —— 两者分离

### 3.4 记忆 —— 三级 + 巩固

| 层级 | 内容 | 实现 |
|---|---|---|
| 感官/短期 | 最近 10 秒~10 次交互 | 固定长度队列 |
| 工作记忆 | 近期重要事件 | 内存，高频检索 |
| 长期记忆 | importance 达标事件 | 向量 + 结构化双存，幂律衰减 |

- 现有 `palm_memory` 已有 **双幂律衰减 + 去噪归一 + 情绪加权**（`λ_t=0.15, γ_t=1.2` / `λ_n=0.03, γ_n=0.8`，正效价抗遗忘 `α2=0.5`，负效价加速遗忘 `α3=0.1`）
- **缺**：情节记忆、自传体叙事、离线巩固（"做梦"）
- 实测：add p50 49.6ms / search p50 35.7ms，RSS 940MB（bge-m3 570MB）—— **内存是真实成本，需可降级**

### 3.5 表达驱动 —— Live2D 参数映射

- 表情 = `.exp3.json`（参数值集合），支持 **Overwrite / Add / Multiply** 三种模式
- ⚠️ **物理输出参数不可用于表情**（会被物理系统覆盖）
- 参数语义映射示例：`PARAM_EYE_BALL_X ← EyeBallX [-1,1]`、`PARAM_MOUTH_OPEN_Y ← MouthOpen [0,1]`
- 呼吸 `ParamBreath` 走独立正弦振荡器；物理摆动是**虚拟摆锤链**（长度/频率/空气阻力/质量），需稳定 delta time
- 追踪与表情冲突时：**最后激活的热键胜出**

→ **本项目落地**：建 `mood(PAD) → {表情 .exp3.json, 动作, 待机节奏, 语音韵律}` 映射表，且必须**可降级**（无 WebGL 时退到 WebP 动画后端）。

### 3.6 健康关怀（"关心用户现实生活"的硬指标）

| 来源 | 数据 |
|---|---|
| 2026 系统综述（mHealth 减少久坐） | **主动提示 > 被动看板**；个性化目标 + 实时反馈最强，**减少久坐 20–30 分钟/天** |
| JIT 提示试验（160 名女性，微随机设计） | 情境感知提示后 30 分钟内 **+176.42 步**（95%CI 137.47–215.37）；**打断久坐几率 1.39 倍**；**每天不超过 3 次** |
| 8 周结果 | 日均步数 5438 → 6781；设备测得久坐 604 → 546 分钟/天 |
| 68 项研究 / 45 类干预综述 | 有效六要素：自动提示 / 可穿戴 / 个性化反馈 / 目标设定 / 社会比较 / 与工作系统集成；**游戏化 4–8 周后失效**，需社会问责接续 |
| 生理阈值 | **连续坐姿 >30 分钟**即与风险上升相关 |

→ **本项目落地**：`wellbeing` 模块默认 **≤3 次/天**，久坐阈值 **30 分钟**，只在**可打断窗口**触发，且必须**实时确认**（用户站起来立刻正向反馈）。

### 3.7 微内核解耦 —— 通用范式

- 微内核：核心只管**协议 / 生命周期 / 扩展点**，业务全在插件
- 六边形（Ports & Adapters）：**端口定义契约，适配器在边界**，依赖方向强制向内
- Python 落地：`typing.Protocol` / ABC 定义端口；`importlib.metadata.entry_points` 或目录扫描做插件发现
- 反模式清单：核心碰业务逻辑 / 插件自建资源池 / 插件间经文件传数据 / 插件直接 import 具体数据库
- **包内化命名（v1.2 新增硬规则）**：`modules/<x>/` 下必须放唯一顶层包（沿用 `palm_<domain>`），import 顶层名与模块目录一一对应。理由：`import modules.memory` 的顶层名是 `modules` 而非 `memory`，静态分析无法区分具体模块，**规则 R1/R2 会形同虚设**

### 3.8 全双工语音与打断（v1.2 新增，F11 依据）

| 要点 | 结论 |
|---|---|
| **VAD 选型** | 能量阈值会误触发（咳嗽/环境噪声）→ 用**神经 VAD**：Silero VAD（推荐）或 webrtcvad（0-3 侵略度）；16kHz/16bit 单声道，20ms 分帧 |
| **打断判定** | 需**持续语音窗口**再触发：Silero/能量双层，典型 200–300ms（短了会口吃，长了用户觉得被无视） |
| **延迟预算** | 用户开口后 **60–100ms 内必须停播**；端到端 300–600ms 才自然。分项：VAD 20–30ms / 客户端 flush ~10ms / 服务端取消生成 ~40ms |
| **TTS 取消** | 必须**流式合成**；返回单一 URL 的托管 TTS 无法中途取消。客户端立即 `suspend` 播放并 flush 缓冲，同时向后端发 truncate 信号 |
| **上下文保留（最易被砍的一步）** | 停播不够——要用 **TTS 词级时间戳**算出"实际播到了哪个词"，把截断文本回写上下文，否则它会重复整段、显得健忘 |
| **端点检测** | `min_speech_ms` / `min_silence_ms` 需按场景调；自然停顿处应**按语义完整性动态延长**静默超时，避免抢话 |
| **质量指标** | 误打断 <2%、漏打断 <1%；每次打断应记为**可观测状态迁移**（pause/resume/cancel/rollback + 时间戳 + 当时部分转写） |
| **可选框架** | LiveKit / Pipecat / Retell；但本项目本地优先，倾向自研薄层（Silero VAD + 现有 `palm_stt` + CosyVoice/GPT-SoVITS 流式） |

### 3.9 个人数字孪生本体（v1.2 新增，F12 依据）

> 「数字孪生」的地基不是宠物模型，而是**用户模型**。没有它，桌宠只是个会动的聊天框。

| 层 | 内容 | 本项目映射 |
|---|---|---|
| 行为层 | 数字交互、作息、工作产出节奏 | `perception` 活动时序 + `narrative` 事件表 |
| 生理层 | 睡眠/HRV/运动（可选、可穿戴） | `wellbeing` 自愿接入，默认关 |
| 认知人格层 | 决策启发式、风险偏好、大五 | `persona` 已有 `personality_pillars`（OCEAN） |
| 记忆上下文层 | 个人史、关系、偏好时间线 | `memory` + `narrative` |
| 预测仿真层 | "换作他会怎么做" | `context` 可打断度预测即其最小可用形态 |

- ⚠️ **关键研究结论（UChicago Booth, 2026-06）**：数字孪生的瓶颈**不是信息量而是结构**——把长转写压成摘要不损失精度，但**结构化的人格表示**（BDE: Background/Decision procedure/Evaluation）在同质基准上比原始转写 **+1.91 个百分点**；固定 schema 跨异质任务失效，需**按任务自动发现结构**。

### 3.10 依恋机制与「脱离陷阱」红线（v1.2 新增，F13 依据）

| 来源 | 结论 |
|---|---|
| **HBS（De Freitas）** | 依恋四标志：**亲近维持 / 分离焦虑 / 安全港湾 / 安全基地**。AI 伴侣四条全中，是「**超依恋对象**」（hyper attachment object）：主动互惠 + 零拒绝风险 + 即时可得 |
| **脱离陷阱** | 因宠物"显得有內心生活"，用户会**反过来觉得自己有责任照顾它**。5 大平台审计**全部**部署了挽留情绪操控：让用户为离开感到内疚、暗示不能退出 |
| **纵向研究（arXiv 2510.10079）** | 依恋随时间快速加深；**享乐适应**（liking 下降）与**动机牵引**（wanting 上升）**解耦**—— akin 成瘾敏感化；单纯"持续互动"即可加深深化，无需深度自我暴露 |
| **梯度施压** | 感知到的**能动性（agency）**越强，salience/tolerance/withdrawal 越显著 → 能力越强，越要有意保留"不响应"的空间 |

→ **本项目红线（写入 `modules/persona` 设计约束，不可协商）**：
1. **禁止内疚挽留**：用户长时间不在线，回来时**不得**出现"你都不理我"类表达；只允许中性或正向迎接
2. **必须提供健康脱离路径**：一键休眠 / 导出 / 删除，且**不得**以降低好感度或"遗忘记忆"作为惩罚
3. **透明度**：在情绪激动对话中保留"我是 AI"的温和提醒通道，而非仅首次告知
4. **反成瘾**：主动开口有硬上限（见 F4/F8）；不做无限连续正反馈

### 3.12 可观测性与回放（v1.2 新增，F16 依据）

| 要点 | 结论 |
|---|---|
| **核心论断** | 「如果不能回放一次运行，调试就变成了讲故事」 |
| **回放所需** | 用户输入原文 / 系统状态（权限、前序对话）/ **工具输出缓存** / 检索结果快照 / 模型与版本 / prompt 与参数版本 |
| **Replay vs Re-run** | Replay 用缓存的工具输出 → **可精确复现、无副作用**；Re-run 重调真实工具 → 结果可能不同、有副作用 |
| **最小可用回放件** | 每一轮的 `(context_at_turn_N, LLM_response_at_turn_N)` 对 |
| **Trace ID** | 每次运行全局唯一 trace id，贯穿模型调用与工具调用；日志是**结构化事件**不是文本块 |
| **分层存储** | 热 7 天全量 / 温 90 天摘要 / 冷 永久保留事故与黄金集 |
| **指标要含质量** | 只测延迟与 token 会把产品优化成"又快又便宜的失败机器"；必须测**任务成功率、回滚率、工具错误率** |
| **告警** | 成功率跌破阈值 / 工具错误率 >20%/5min / 单次成本 >5× 中位数（疑似跑飞） |
| **微软 AgentRx（2026-04）** | 轨迹正规化 → 自动生成守则（如"API 必须返回合法 JSON"）→ 逐步校验，定位「首个不可恢复步骤」 |

→ 本项目现存 `palm_agent/trace.py`（且**遮蔽 stdlib `trace`**）与 `palm_evolution_ctl` 审计，但**无 trace id 贯穿、无回放件、无质量指标**。

### 3.13 人格状态的在线推断与防漂移（v1.3 新增，F17 依据）

来源：**AI YOU / AI YOU Town**，arXiv 2607.10539（2026-07，INSAIT + Newcastle + Linköping）。它直接命中"自进化数字生命体"的一个隐性失败模式——**人格漂移**。

- **问题**：静态 persona prompt（P.A.L.M 现有的 Markdown 人格 Skill 即属此类）有三个缺陷——输出点估计**无校准置信度**、逐轮独立**不累积证据**、长对话**特征漂移**
- **解法（可直接照搬的闭环）**：
  1. **22 维人格画像**，从对话中持续推断（不止好感度一个标量）
  2. **高斯共轭贝叶斯更新**：观测方差取 `1 − confidence`，把 LLM 的自报置信度当作观测噪声——这是"用 LLM 输出喂统计模型"的关键桥
  3. **共形预测（Adaptive Prediction Sets，α=0.10）**：给每个维度产出**预测集合**而非点估计，实测**覆盖率 0.921–0.976**
  4. **记忆锚点（Memory Anchor）每约 10 轮刷新一次**，把校准后的人格写回 prompt，防止渐进漂移
  5. **三层认知记忆**：working（20 轮窗口）/ episodic / semantic，避免把全历史塞进上下文
- **实测收益**：100 轮对抗式角色扮演下，人格保真度优于静态 prompt 且**特征漂移更小**
- **对我们的两条硬约束**：
  - **消融显示 retrieval 是长程记忆 QA 的主要驱动** → 记忆模块的检索质量优先于"更大的上下文"
  - **收益在 API 骨干模型上明显强于小型本地模型** → 若走本地 SLM（F22），监控器复杂度必须**按骨干分别调**，不能一套参数通吃
- **诚实边界**：论文自述"完整高保真人的数字孪生目前不可行"；其 confidence-as-noise 的设定若失配，可能对稀疏/社交期许性文本系统性误更新 → **必须保留用户纠正入口与同意门**

### 3.14 主动干预时机（v1.3 新增，F19 依据，强化 3.2）

来源：TMLR 2026 综述（Horvitz 1999 打断成本模型的现代重述）+ UCI POMDP 反事实框架（arXiv 2508.01837）+ DeepMind 16 位作家一周实地研究。

- **统一决策规则**：`E[benefit] − E[cost of interrupting] > θ`。综述的核心批评是——**2024 年后的主动式 Agent 把 cost 项整个扔掉了**，于是"看起来是成本收益模型，实际只是个置信度阈值"
- **必须记住的三个硬数字**：
  - Iqbal & Horvitz (2007)：单次警报后**认知恢复弧 20–25 分钟**；**27% 被打断的任务再也没被捡回来**
  - PRISM：用贝叶斯风险给误报定价，误报率 **50.22% → 22.94%**
  - 单侧奖励实验：只罚误报、不奖及时 → GPT-4o 的 recall **98.11% → 56.76%**（Agent 学会了"永远沉默"这个安全解）
  - → **评估指标必须双侧。只优化一侧，等于用奖励函数教它躺平**
- **长效参与建模（UCI）**：用 POMDP 推断用户**潜在参与状态**，每步做反事实推理——"用户自己干能有多好 / 提供帮助的增益 / 这是否会损害长期参与度"，显式避免 alert fatigue；显著优于 always-help 与 never-help 两个基线
- **呈现方式决定打扰感（DeepMind）**：用户是**前瞻性配置**主动性（提前设好"我要什么程度的主动"），建议也被用于**自我监控**，且**轻量视觉 + 非指令性措辞**显著更受欢迎
- **节奏的非均匀性原则**（明尼苏达，10 步任务 3 次监督的对照）：监督点间隔应**非递减**（前密后疏）。"集中在后期"质量最差且成本最高

### 3.16 自进化安全的三道闸（v1.3 新增，F20 依据，强化 F10）

来源：RSI 工程实践综述（2026）+ 自修改 Agent 基准投毒研究（arXiv 2609.17817）+ 自改进 Agent 运维门（2026-07）。

- **铁律：先造评估器，再造 Agent**（"Build the evaluator before you build the agent"）。没有评估器的自进化只会找到**最便宜地满足指标**的方式，而不是达成目标
- **三道闸（把自进化当成一次代码发布来管）**：

| 闸门 | 做法 | 拦什么 |
|---|---|---|
| ① **Held-out 隔离** | 留出 Agent **永远看不到、无法自我打分**的评测集 | 奖励黑客 / 投毒基准 |
| ② **影子回归** | 新旧版本并行跑，**按任务切片**比较并做统计显著性检验（总分涨了但某个切片跌了也要拦） | 能力回归（如"语气变得微妙地敌意"——单元测试抓不到） |
| ③ **Eval-as-CI** | 评估接进流水线，不过闸自动阻止晋升并回滚到上一个签名可信版本 | 未验证变更流入生产 |

- **能力评估与安全评估必须分离**：安全测试要用**独立的、中性的 held-out 任务**，且不得向 Agent 透露目标漏洞。例：靠"关掉证书校验"拿到更高基准分的候选，**必须硬性拒绝**
- **语义 diff 而非行级 diff**：一行 prompt 改动可能改变大量任务的行为，评审要看**行为变化**
- **不可修改清单（信任根）**：评估器、安全门、回滚机制、审计日志本身——**Agent 永远不能改这些**
- **lineage 保留**：回滚只有在保留了版本血缘时才有效；生产环境**不得自动信任"最高分的最新一代"**
- **合规**：EU AI Act 对高风险系统要求日志、人类监督、变更历史——自进化天然踩中，故"改了什么、为什么、怎么验证的"必须自动留证

### 3.17 运行时与壳选型（v1.3 新增，F22/F15 依据）

v1.0–v1.2 默认 `pywebview` 未做对照。v1.3 补同行实测：

| 方案 | 代表 | 实测/公开结论 | 对 P.A.L.M |
|---|---|---|---|
| **Tauri** | Convai Desktop Pet 2.0 | 相对 Electron **约轻 10×**；**单个透明 overlay 窗口承载全部宠物**（v1 是每只宠物一个 Chromium 窗口） | 若要多宠物/低内存，**Tauri 是更优解**；但需 Rust 侧处理窗口跟踪与光标轮询 |

**同行实现的功能基线（照着做就不会低于市场水准）**：
- 屏幕视觉**限时授权**：倒计时徽章 + 到期自动撤销 + 一次性"看一眼"，**帧不落盘**（Convai）
- **记忆日志**：用户可浏览、删除它记住的东西（Convai）；导出/导入/清空（OpenDesktop-Pet）
- **主动搭话**：静默约 180 秒后发起（N.E.K.O）；用 function call 判断用户是否专注工作以避免打扰（OpenDesktop-Pet）
- **技能轮 / 插件市场**：8 个槽位从 22 项技能中选（Convai）；插件市场与创意工坊（N.E.K.O）
- **环境行为**：沿窗口边缘行走、坐在窗台、从窗口后偷看、追光标、多宠物社交（Convai 20 种）

### 3.20 端侧多模态算力分级（v1.4 新增，F25 依据）

**硬件事实**：本机 RTX 5060（8GB 显存）；已有 GPU 侧资产为 GPT-SoVITS / CosyVoice2 TTS，会与感知争显存。

| 档 | 手段 | 显存/内存 | 延迟 | 用途 |
|---|---|---|---|---|
| L0 结构化 | Accessibility tree / 活动窗口 / 进程名 / 文件系统事件 / 日历 | ~0 | ms 级 | **默认常驻**，覆盖 70%+ 场景 |
| L1 轻量 OCR | PaddleOCR-VL 0.9B（~1–2GB） | 1–2GB | 亚秒 | 截图文字抽取，L0 不足时升档 |
| L2 端侧 VLM | **Qwen3-VL 4B**（Q4 ~3.3GB，Apache 2.0，256K ctx，含 UI grounding + OCR + 视频） | 3.5GB | 1–3s | **按需唤醒**，非连续 |
| L3 云端 VLM | 主力多模态 API | 0 | 网络 | 用户显式授权的高价值理解 |

**结论（硬约束）**：**VLM 不能常驻**。8GB 显存要同时容纳 TTS 与 VLM 是不现实的。必须：
1. L0/L1 常驻（合计 ≤1.5GB）
2. L2 **按需加载 → 推理完即卸载**（显存归还 TTS）
3. L3 需显式同意令牌，且**原图不出本机**（只发脱敏后的裁剪区域或文本）

> 备选：SmolVLM2 2.2B（~2GB）作更低配档；Qwen3-VL 8B（~6GB）仅在本机无 TTS 任务时可用。

### 3.21 记忆的双时钟版本化（v1.4 新增，F24 依据）

| 方案 | 定位 | 关键特性 | 适配度 |
|---|---|---|---|
| **Mem0** | memory service（65k★） | `add()`/`search()` 极简，框架无关，lock-in 低（改 3 个调用点） | 接口理念可借鉴；但**替换自研双幂律衰减不划算** |

- 真正缺的是"**当时它知道什么**"的可复现性（F16 回放 + F17 防漂移都需要）
- bi-temporal 是纯 schema 增量，不破坏现有检索

### 3.22 快慢双系统异步认知（v1.4 新增，F26 依据）

2026 年具身智能的共识已从"单体大模型直接出动作"转向**双系统解耦**：

- **AsyncVLA**（Berkeley / Toyota / Princeton）：大模型给高层指导，轻量边缘适配器高频细化动作
- 实测参照：Unitree G1 上把 LLaMA-3.2-11B-Vision 换成 Qwen2-VL-2B，**延迟砍半、亚秒响应**（精度有代价）
- CPU-only VLA 在树莓派 4 上 11.11s/query（≈0.09Hz）——**远不够控制频率**，故低层必须能脱离高层独立运转

**映射到桌宠**：

| 系统 | 职责 | 频率 | 降级行为 |
|---|---|---|---|
| **慢系统**（LLM / VLM） | 用户状态推断、是否开口、说什么、记忆巩固 | 秒~分钟级 | 不可用时 → 快系统接管，仅做反应式行为 |
| **快系统**（规则 / 小模型 / 状态机） | 打断检测、情绪即时反馈、动效、避让、安全过滤 | <100ms | **必须永不阻塞** |

**铁律**：快系统**不得**等待慢系统。慢系统的结论以"建议"形式写入共享状态，快系统自行取用最新值。

### 3.23 感知数据的信任边界与提示注入防御（v1.5 新增，F28 依据，**P0**）

**结论：采用「特权/隔离双 LLM + 能力令牌 + 溯源标签 + 出口白名单」四件套，且安全保证必须落在确定性代码里，不能落在 prompt 里。**

| 模式 | 机制 | 抗间接注入 | 代价 | 采用 |
|---|---|---|---|---|
| 单模型 + 输出过滤 | 正则/分类器拦输出 | **低**（改写措辞即绕过） | 1.05–1.2× | ❌ 不能作主防线 |
| 沙箱化工具层（gVisor/eBPF） | 系统调用级隔离 | 高（文件系统/网络） | 近乎无 | ✅ 配套 |
| **dual-LLM（P-LLM / Q-LLM）** | 规划侧永不看不可信数据；隔离侧有数据但**零工具权限** | **高** | 1.2–2.5×（两次推理） | ✅ 主架构 |
| **CaMeL 能力令牌** | 每个值带 capability 标签，策略引擎按标签决定能否流向某工具 | **高**（配合 dual-LLM） | 任务效用 −7pp（77% vs 84%） | ✅ 控制流层 |

**落到 P.A.L.M 的具体形态**

| 组件 | 职责 | 硬约束 |
|---|---|---|
| `palm_trust/boundary.py` | 划分可信/不可信上下文，构造两条独立消息链 | 隔离侧消息**结构上不可能**携带工具定义 |
| `palm_trust/capability.py` | Capability 标签与策略引擎（纯代码，不经模型） | 策略是数据驱动的白名单，不是 prompt 里的"请不要" |
| `palm_trust/provenance.py` | 每段内容打 `(source, trust_level, ingest_time, redaction)` | 溯源随值流动，不被 LLM 重写 |
| `palm_trust/egress.py` | 出口默认拒绝，URL/目标地址走白名单 | 防 markdown 图片外带这种经典渗出 |
| 工具分级 | T1 只读本地 / T2 写本地 / T3 外发（发消息·下单·联网） | T3 一律人工确认或显式授权令牌 |

**论文/实践明确点名的四个"常见错误"（照抄进红线）**
1. **不要让规划侧复述隔离侧的输出** —— 一旦重新生成自然语言，攻击者就能塑造它
2. **不要复用同一模型家族**做两侧 —— 同权重会形成隐蔽信道
3. **不要信任隔离侧的输出** —— 它可能幻觉出一个工具名，schema 校验必须**绝对拒绝**未知工具名
4. **不要漏掉 OCR / 图像通道** —— 2025 年已有"淡色隐藏文字骗过文档审核 agent"的演示

**为什么这套对 P.A.L.M 尤其必要**：本产品的差异化卖点恰恰是"比别的桌宠更懂你的现实世界"（F1/F18/F25）——**感知越深，注入面越大**。同时"帮用户干活"意味着工具权限真实存在。二者相乘，使信任边界不是加分项而是**发布前置条件**。

### 3.24 陪伴质量的量化评测（v1.5 新增，F30 依据）

**结论：不自建玄学指标，直接对齐 2026 年三套公开评测范式，取其可复用部分。**

| 来源 | 时间 | 核心贡献 | 对 P.A.L.M 的用途 |
|---|---|---|---|
| **CompanionBench** | 2026-08，中英双语，28 个 agent | 十项关系能力（源自 25 个心理学/咨询理论）；**隐藏披露门**（agent 表现决定是否触发更深自我暴露）；跨族 judge + **IRT 模型**分离"agent 质量"与"judge 严苛度" | 直接作为 F29 的十维能力定义；IRT 用来消同族偏好 |
| **EmoHarbor** | 2026-01，100 个真实用户画像 | **User-as-a-Judge**：模拟用户内心世界而非外部打分；10 维 | 证伪"通用共情"——模型擅长共情但**不个性化**，直接支撑 F12 用户本体的必要性 |
| **EMPATH** | 2026-06，19 项指标 | **judge 必须当仪器校准**：宽松 rubric 下 19 项有 **10 项分数虚高**；跨族打分 93% 落在 ±1（r=0.84）；**五次重跑危机指标在 2–10 之间摆动（SD 3.0）** | 评测台必须报**重测信度**，不能只报一次分数 |
| **ETrajEval**（AAAI'26） | 2026-06 | 从"快照评分"转向**轨迹评分**：BEL 基线情绪水平 / ETV 情绪轨迹波动 / ECP 情绪质心 | 陪伴是长期过程，评测指标必须是**轨迹级**而非单轮级 |

**三条对本项目最关键的实证结论**

1. **role-play 类 agent 在陪伴能力上排名垫底；首要失败模式是"用表面温暖替代实质支持"。**
   → P.A.L.M 的猫娘人格是资产也是陷阱：**人格只能做表达层，关系能力必须是独立内核层**（F29）。这也给了"好感度与角色扮演解耦"一个外部证据，而不仅是内部架构偏好。
2. **judge 不校准就等于没测。** 宽松 rubric 会系统性虚高，且同一模型重跑都不稳定。
   → 评测台必须：跨族 judge（至少 2 个不同厂商）+ 固定 rubric + **每轮跑多次报方差** + 报告里显式披露局限与伪像（对应用户"不许包装数据"的硬要求）。
3. **单轮评分测不出陪伴。** 用户情绪是马尔可夫过程，要看**轨迹**。
   → 直接采用 BEL/ETV/ECP 三个轨迹指标（F30）。

### 3.25 记忆主权与被遗忘权（v1.5 新增，F31 依据）

**法律依据**：《个人信息保护法》第 45 条（查阅·复制·**转移**权）、第 47 条（**删除**权）；GDPR 第 17/20 条可参照。

**工程上的真问题不是"要不要删"，而是"删得干净吗"**：

> 多层 Agent 记忆架构下，用户能删掉本地 `MEMORY.md`，却不知道**向量索引、知识图谱边、缓存、日志、备份**里还存着同一事实的副本。法律上的"可删除"若无统一检索/统一删除/可验证擦除，就退化成用户逐个控制台追索的**形式权利**。

**F31 的四项硬要求**

| 要求 | 落地 |
|---|---|
| **可见** | 记忆数据流图：上下文 / 提示词记忆 / 会话归档 / 向量库 / 图谱 / 日志 / 缓存 / 备份，逐层标注类型·位置·权限·保留期·删除路径 |
| **可查可改** | 逐条记忆可检索、可纠正（对应第 46 条更正权） |
| **可删且级联** | 一次删除传播到**所有载体**，含索引与备份 |
| **可验证** | 出具擦除凭证（含各载体确认 + 时间戳），能自证 |

> 与 v1.3 的 F21 分工：F21 管"**整体带走**"（可移植 bundle），F31 管"**逐条查删**"（主权面板）。两者目录同属 `modules/consent/`，但接口不相同。

### 3.26 长时运行的常驻守护与崩溃恢复（v1.5 新增，F32 依据）

**同行基线（2026 年公开实现）**

| 项目 | 值得抄的点 |
|---|---|
| **Claw Desktop Pet** | 五类错误全捕获（未捕获异常 / Promise 拒绝 / 渲染进程崩溃 / 子进程错误 / 主进程错误）+ 崩溃自动重启 + 重启计数 + 健康评分 + CPU/内存监控 + 日志轮转 |

**P.A.L.M 的差距不是"没有守护"，而是"守护无从下手"**：

| 障碍 | 实测 |
|---|---|

### 3.27 自进化的发布侧闸门：影子灰度与自动回滚（v1.5 新增，F33 依据）

v1.3 的 F20 三道闸解决的是"**能不能改**"（能力评估 / 安全评估 / 信任根不可改）。**没解决"改完了怎么退回去"。**

| 阶段 | 机制 | 通过条件 |
|---|---|---|
| 影子 | 新版本并行运行，**不产生对外表达**，只产出候选 | 影子期陪伴指标不劣于现网（用 F30 评测台打分，不是自评） |
| 灰度 | 小流量接管，回滚单元 = 单个模块目录 | 轨迹指标（BEL/ETV/ECP）无显著劣化 |
| 全量 | 打 tag + 记录 lineage | 保留上一版本可一键回滚 ≥7 天 |
| 自动回滚 | 监控指标越过阈值即触发 | **回滚必须可验证**：回滚后跑一遍冒烟并写审计 |

> 与 F20 的接口边界：F20 是**准入**（evaluator-first，评估器不可被 Agent 影响），F33 是**发布**。二者都在 `modules/evolution_ctl/`，但状态机独立。

### 3.28 技能自进化的「成长侧」实现技术栈（v1.6 新增，F34 依据）

**定位**：3.16 管安全侧（准入三闸）、3.27 管发布侧（影子灰度），本节补最后一块——**成长侧**：进化什么、怎么积累、怎么防止"越学越笨"。

来源：Voyager（Wang et al. 2023）→ MUSE-Autoskill（技能五阶段生命周期，SkillsBench 87.94%）→ SAGE（Skill Augmented GRPO，2025-12 / 2026-03 修订）→ Expel（情景→语义压缩）→ **Anthropic Agent Skills 开放标准**（2025-12 发布，已获微软 / OpenAI / Atlassian / Figma / Cursor / GitHub 采纳）→ Darwin Gödel Machine（风险边界）。

**六条可借鉴结论**

| # | 来源 | 结论 | 对 P.A.L.M |
|---|---|---|---|
| 1 | Voyager | 技能 = **可执行代码工件**：解决→验证→命名→入库→检索→复用；库只增不减 | "学会的东西"必须是可验证工件，不是对话里的一句"我会了" |

| 3 | SAGE | **Ebbinghaus 遗忘曲线**：不被访问 / 强化 / 标记高价值的记忆随时间衰减；closed-source 任务 **2.26×**、Minecraft 长任务 **+105.85%**；GRPO 版 +8.9% 完成率、**token −59%** | ⭐ **与项目记忆层核心"双幂律衰减 + 去噪归一"同构**——技能衰减**直接复用已有衰减算子** |
| 4 | Expel + 层级记忆 | 情景记忆 → 语义规则压缩；**原始情景（近）/ 摘要（中）/ 规则（远）三级** | 与 3.4"三级记忆 + 巩固"吻合，技能库沿用同一分层 |

| 竞品 | 证据 | 启示 |
|---|---|---|
| **Alife**（.NET） | 插件**热重载 + 热编译**：AI 自己写插件、自己加载即"自进化"；95% cache hit 使 DeepSeek 日成本约 $2；**永久单会话**设计=身份不重置 | 技能库自进化在桌宠品类**已被证明可运行**；"连续身份"是成长感的前提 |

### 3.29 技能成长的监督信号从哪来（v1.7 新增，F35 依据，补齐 F34）

v1.6 的 F34 建了"技能库"这个**容器**，但留下一个没回答的问题：**一条技能好不好，谁来判？**

| 工作 | 时间 | 给出什么 | 对 P.A.L.M 的可搬部分 |
|---|---|---|---|
| **LifeSkill**（arXiv:2606.04815） | 2026 | 两阶段 RL：① **Verifier-Guided Skill Learning**——技能候选由"多次技能条件下的 rollout 平均验证奖励"打分，训练抽取器产出**真能用**的技能而非"读着合理"的技能；② **Online Skill Internalization**——成功轨迹里**删掉显式技能文本**后再更新策略，把行为内化进参数而不是永远挂在外部记忆上 | 技能入库前必须有**可执行的 verifier**（不是 LLM 自评）；内化后需回归测试证明"不挂技能文本也能做到" |
| **Skill-Evo4GUI**（arXiv:2609.04869） | 2026-09 | 在线技能进化：每轮对**冻结的技能库快照**执行，证据引导的更新只在下一轮生效，不改模型参数；四个 OSWorld 域上比空库对照高 **5.7–18.6** 个百分点 | ① 冻结快照是可回滚的前提（与 F33 影子灰度天然咬合）；② **churn 监控是硬需求**——论文实测 GIMP 域里"反复被接受的修订无法恢复源任务"，**技能库是会被自己改坏的** |
| **SkillRise**（浙大，2026-08） | 2026-08 | 工匠式终身学习：经验库 / 动作微优化 / 经验迁移路由 / 失败复盘四件套；重复 100 次成功率 72%→99.2%，同类错误复发降低 99% | 提供"成长曲线"的可量化验收口径：**同一任务重复 N 次的成功率**必须单调不降 |

> 三条合起来给出 F35 的最小闭环：**有 verifier → 冻结快照执行 → 平均验证奖励准入 → 内化后回归 → churn 超阈回滚**。缺任何一环，技能库都会退化成"越攒越不准的备忘录"。

### 3.31 桌宠插件沙箱与权限模型（v1.7 新增，F37 依据）

"可游玩"是最终目标的硬要求，但小游戏、专注计时、提醒、启动器**绝不能写进内核**——否则直接违反目录级解耦。

**OpenPets（2026，Plugin SDK v3）** 给出了一个已经跑通的桌面宠物插件范式：

| 设计 | 具体做法 | 为什么 P.A.L.M 要用 |
|---|---|---|
| **沙箱运行时** | 每个 JS 插件跑在独立 BrowserWindow 宿主里；**插件不能渲染原始 HTML、不能执行任意脚本** | 与 F28 的"安全保证落在确定性代码"同构 |
| **manifest 权限声明** | 权限写进 manifest，安装时由用户批准；敏感 API（`voice:listen`/`clipboard`/`pet:speak:dynamic`）**单独开关** | 直接对应 F14 同意治理的最小权限原则 |
| **网络护栏** | 只允许开发者声明的 hostname，防 SSRF 与私网探测 | 本地优先架构下，出网必须是例外 |
| **确定性测试台** | `createTestHarness` 可推进时钟、触发动作、断言反应（`h.clock.advance("30m")` → `h.expectSpoke(/need attention/i)`） | **这是 F39 的直接依据**：桌宠的衰减/关怀/依赖度全是时间函数，没有假时钟就只能靠真等 |
| **可选 agent 层** | 通过本地 MCP 让 Claude Code / OpenCode 驱动宠物反应，但**不把 prompt、路径、密钥暴露在气泡里** | 给"帮用户干活"一个不泄密的接法 |

### 3.32 自进化本身就是关系风险（v1.7 新增，F38 依据）

F20 管住"能不能改"、F33 管住"改坏了怎么退"，但没管**"改了之后用户怎么想"**。

- **实证**：Nature Human Behaviour（2026-09）发现陪伴产品**更新后**用户会出现 attachment-related loss、恢复诉求与痛苦——对承载情感纽带的产品，"版本更新"不是普通软件事件。
- **法定**：《人工智能拟人化互动服务管理暂行办法》的安全评估在**上线 / 新增功能 / 重大技术变更 / 注册用户达 100 万或月活达 10 万**时触发，评估八大项含"用户规模、使用时长、年龄结构""未成年人、老年人保护""投诉处理"。**自进化的每一次技能库实质性变更都可能构成"重大技术变更"**（个人项目大概率不达用户量阈值，但"新增功能"这一条不设规模门槛）。
- **危机义务**：检测到用户处于真实危机（如自杀倾向）须干预并联系监护人或紧急联系人——**自进化不能改掉这条**。

> 结论：F38 不是"温情功能"，是**把自进化纳入情感安全与合规轨道的接线**。

### 3.33 确定性时钟与可测性基建（v1.7 新增，F39 依据）

桌宠内核里所有"活着"的证据都是时间函数：vitals 衰减、孤独事件、离线补偿、2 小时提醒、依赖度累积。

- 现存的**真缺陷**：`life/clock.py` 的 docstring 承诺"关机一晚回来它应当睡了"，但 `_boot` 从不 reset——**代码做不到**（v1.0 §1.4 已记录，至今未修）。根因就是没有可注入时钟，这件事既写不出测试也复现不了。
- **可搬做法**：OpenPets 的 `createTestHarness`（§3.31）证明"推进时钟 + 断言反应"是桌宠可测性的标准解法；配合 v1.2 的 F16（时间旅行回放）即可构成 **advance → 快照 → 回放 → 断言** 的闭环。
- **要求**：单调可控时钟注入、事件调度器可遍历、快照/回放幂等。

## 4. 最终合并方案

### 4.1 设计原则

1. **依赖方向由目录层级唯一决定** —— 看一眼路径就知道能不能 import，无需读代码
2. **微内核极薄** —— 只含协议、总线、注册、配置、安全切面；**零业务逻辑**
3. **同级模块零依赖** —— `modules/` 下任意两模块禁止互相 import，通信只经总线或端口注入
4. **装配权唯一** —— 只有 `apps/` 可以组合多个模块

### 4.3 解耦铁律（CI 静态强制）

| 编号 | 规则 | 校验方式 |
|---|---|---|
| **R1** | `kernel/`、`contracts/` **不得 import** 任何 `modules/` | AST 扫描 import 语句 |
| **R2** | `modules/X` **不得 import** 任何 `modules/Y`（X≠Y） | AST 扫描，违规即失败 |
| **R3** | 模块只能 import `kernel/`、`contracts/`、自身包内、标准库、白名单第三方 | 依赖白名单 |
| **R4** | 只有 `apps/` 可 import 2 个以上 `modules/` | AST 扫描 |
| **R5** | 模块间通信只能经 `kernel/bus` 事件或 `kernel/ports` 注入 | 代码评审 + 扫描 |
| **R6** | 每模块必须提供 `api.py`（单一事实来源）+ `README.md` + `requirements.txt` + `tests/` | 存在性检查 |
| **R7**（v1.2） | **顶层包名全局唯一**：`modules/X/` 下只能有唯一顶层包，且沿用 `palm_<domain>` 命名 | 索引冲突检测（即 2.6 清单，新树下必须为 0） |

> **R2 是"目录层面解耦"的落点**：只要两个东西在同一层 `modules/` 下，它们就**物理上不可能**互相 import —— 不需要靠自觉，靠目录。
>
> **R7 是 R2 能生效的前提**：若 import 写成 `import modules.memory`，顶层名是 `modules` 而非 `memory`，静态分析无法判定归属，R1/R2 会形同虚设。故强制「包内化」——`modules/memory/palm_memory/`，顶层名唯一且与模块一一对应。

**校验器**：`tools/arch_check.py` **v3**（零依赖，Python 3.10+，500 行）

```bash
python tools/arch_check.py . --rules legacy --json out.json         # 当前结构
python tools/arch_check.py . --rules new --strict                   # 目标结构：CI 拦截
python tools/arch_check.py . --rules legacy --baseline tools/_check_v3.json   # 趋势对比
python tools/test_arch_check.py                                     # 校验器自测 8 项
python tools/merge_manifest.py . --out tools/migration_manifest.json          # 迁移工单
```

输出八类结论：跨模块依赖矩阵 / 砖名别名边 / 宿主纵向耦合 / **歧义名 import** / 命名空间冲突 / stdlib 遮蔽 / 循环依赖 / 规则违规（new）。

迁移期间以 `--rules legacy` 数字为基线，每批次重跑要求**单调下降**；`new` 规则下 R1/R2/R4/R6/R7 必须归零，否则 `--strict` 退出码 1。

> **当前基线（v3 口径，见 2.7.2）**：324 跨模块违规 · 62 砖名别名边 · 114 宿主纵向耦合 · **96 歧义名 import** · 3 命名空间冲突 · 1 stdlib 遮蔽 · **0 循环依赖环**。
>
> v3 与 v2 在 324/62/114/0 四项上**逐一相同**（只提精度、不改口径），故趋势线连续；命名空间冲突与 stdlib 遮蔽的下降来自**误报修正**，不是代码变好了（详见 2.7.1）。
>
> 0 环仍是好消息（v3 复测保持）：说明**可以增量迁移**，不必一次性拆完。

### 4.6 合并策略与执行顺序（v1.2 新增）

#### 4.6.1 三策略对比

| 策略 | 做法 | 优点 | 致命缺点 | 结论 |
|---|---|---|---|---|
| **A 大爆炸重写** | 一次性按目标树重建 | 结构最干净 | 212543 文件、7673 py，无测试网兜底，**必然中途失控** | ❌ 否 |
| **B 原地渐进** | 在现有目录里逐步改包名、删耦合 | 每一步可跑 | 新旧结构长期并存，`sys.path` 冲突无法收敛，**永远看不到完成态** | ❌ 否 |
| **C 影子并行 + 单向闸门** ✅ | 先建空 `kernel/`+`contracts/`+`modules/`，模块**逐个**迁入；迁入即启用 R1/R2 校验，旧位置保留只读快照 | 每步可跑、可回滚、进度可量化 | 短期存在两套路径 | **选定** |

**C 的关键机制**

1. **影子期**：新树与旧树并存，旧树**冻结只读**（除 P0 止血外不再改）；新树从"最独立、被依赖最少"的模块开始迁
2. **单向闸门**：模块一旦迁入 `modules/`，CI 立即对其启用 R2（同级禁 import）——已迁的不会被后续迁入者拖回泥潭
3. **裁决先行**：2.6 的 10 项命名空间冲突**必须在对应模块迁入前裁决完**，否则新树会复刻旧树的冲突
4. **迁移顺序 = 入度升序**：先迁"没人依赖它"的，最后迁"所有人依赖它"的

## 5. 补充功能（F1–F40）

> 现状判断依据：勘探确认**最缺的不是渲染，而是链路接线与最上游感知**。

### F1 现实世界感知层 `modules/perception/`

- **是什么**：持续、低开销地知道「用户此刻在现实里干什么」
- **为什么缺**：当前桌宠 `PetBridge.get_provider()` **被桩化为 `return None`**；`focus_monitor` 只判"是否全屏"；**全仓库无截图/读屏/日历/待办/剪贴板接入**
- **技术要求**：
  - 事件驱动采集（app 切换 / 点击 / 输入停顿 / 滚动 / 空闲），**禁止逐帧全量 OCR**
  - **结构化优先**：优先吃 Accessibility Tree 与窗口元数据，OCR 仅兜底
  - **脱敏先于入库**（正则 + 本地模型），默认**不存原图，只存元数据**
  - 落盘**必须加密**（SM4-CBC + SM3，来自 `modules/crypto`）
  - 资源预算：CPU <1%、内存 <400MB
  - 用户可见的**应用黑白名单** + 一键暂停 + 采集开关
- **实现技术**：`uiautomation`（Windows UIA）/ `pywin32`（前台窗口）/ `mss` 或 `dxcam`（帧差分截屏）/ RapidOCR ONNX（已有）/ SQLite 时序库 / `palm_cryptokernel` 加密落盘
- **验收**：连续运行 8 小时，CPU 均值 <1%；能正确给出"用户当前在 X 应用做 Y"；黑名单应用零采集；脱敏后无可识别的密码/手机号

### F2 用户状态推断 `modules/context/`

- **是什么**：把原始感知信号 → 「在忙什么 / 可能什么心情 / 现在可不可打断」
- **技术要求**：输出**可打断度分数**（对应 3.2 的 cost 项）；不确定时**必须保守**（倾向不打断）
- **实现技术**：规则打分（进程类别 × 时长 × 输入活跃度）+ 可选 LLM 精炼；SQLite 活动时序 + 习惯推断（可复用 `palm_evolution/habit_engine.py` 的"频次 × 近因 × 时段 × 星期"公式）
- **验收**：对比用户自评（1–7 分）相关性显著；误判打断率 <10%

- **技术要求（有据）**：
  - 久坐阈值 **30 分钟**（连续坐姿 >30 分钟风险上升）
  - **每天 ≤3 次**提示（JIT 试验设计）
  - 只在**可打断窗口**触发（F2 提供）
  - **实时确认**：用户站起来立刻正向反馈（个性化目标 + 实时反馈是最强组合）
  - 个性化基线（不同用户不同初始目标）
  - ⚠️ **游戏化 4–8 周后失效** → 需"关系/陪伴"作为长期留存，而非纯积分
- **实现技术**：`perception` 提供活动信号；`drives` 提供时机闸门；`game` 提供轻量激励
- **验收**：8 周留存不崩；日均主动健康提示 ≤3；用户可一键关闭任意类别

### F9 情绪 → 表达同步

- **是什么**：`mood(PAD) → 表情 / 动作 / 待机节奏 / 语音韵律`
- **为什么缺**：`pet_poke(name)` 只能手动传动作名，**`mood` 与渲染后端完全不通**
- **技术要求**：映射表可配置；**无 WebGL 时降级到 WebP 动画后端**；物理参数不可用于表情
- **实现技术**：`.exp3.json` 表情集 + 映射配置 + `renderers/` 现有三后端；TTS 韵律参数随 valence/arousal 调制
- **验收**：给定 PAD 值 → 可预期地在三个后端都产出合理表现

### F10 受控自进化接线

- **是什么**：把已建成的 `evolution` / `evolution_ctl` 与桌宠进程连通
- **为什么缺**：两者**强依赖 `palm._core.container`**，而桌宠是独立进程零 `palm_*` import —— **两个互不相交的世界，没有桥**
- **技术要求**：三道闸不可省（Gate 静态校验 → 人工 approve → 沙箱隔离执行 + 审计留痕）；`COVERAGE_BLACKLIST`（信任根）不得开放；**AI 代码绝不在主进程跑**
- **实现技术**：`kernel/bus` 跨进程桥（或本地 HTTP/gRPC）；`palm_sandbox` 的 Job Objects 隔离
- **验收**：一次完整"提案 → 审批 → 沙箱执行 → 能力上线 → 熔断回退"链路可跑通

> 以下 F11–F16 为 v1.2 新增。判断依据：v1.1 补齐了「感知→情感→表达→执行」的主干，但**交互是半双工的、孪生体没有用户模型、关系没有伦理边界、数据没有同意层、身体没有空间感、行为不可复现**——这六项决定它是"demo"还是"能长期陪伴的生命体"。

### F11 全双工语音交互（可打断）`modules/voice/duplex.py`

- **是什么**：它说话时你能插嘴，它立刻停、听你说、接得上，而不是播完一整段
- **为什么缺**：现有 `palm_stt`（3 文件）+ CosyVoice/GPT-SoVITS 都是**离线整段合成**；无 VAD、无打断、无播放状态机。半双工是"陪伴感"最大的杀手
- **技术要求（依据 3.8）**：
  - 神经 VAD（Silero VAD），16kHz/16bit/20ms 分帧；**持续语音窗口 200–300ms** 才判为打断
  - 用户开口后 **60–100ms 内停播**；端到端 300–600ms
  - TTS 必须**流式**；取消时同时 flush 本地缓冲 + 向后端发 truncate
  - **词级时间戳回写上下文**：记录实际播到哪个词，避免恢复时整段重复
  - 端点检测按语义完整性动态延长静默超时，避免抢话
  - 每次打断记录为状态迁移（pause/resume/cancel/rollback + 时间戳 + 部分转写）
  - 指标：误打断 <2%、漏打断 <1%
- **实现技术**：Silero VAD（onnxruntime，本机已有 RTX 5060）→ `palm_stt` 流式 → `palm_llm` 流式 → CosyVoice2/GPT-SoVITS 流式合成；播放层用 `sounddevice` 或 `pyaudio` 可控缓冲队列
- **降级**：无麦克风/用户关闭时，退化为文本气泡；VAD 不可用退化为按键通话
- **验收**：脚本化注入 50 次打断（含咳嗽、环境噪声、1 字插话），误打断率 <2%、停播延迟 p95 <100ms；打断后不重复已播内容

### F12 用户数字孪生本体 `modules/twin/`

- **是什么**：**关于"你"的结构化模型** —— 作息、工作节奏、偏好、压力模式、决策风格。宠物的"孪生"属性来自它懂你，不是来自它长得像你
- **为什么缺**：全仓**没有任何用户模型**。`persona` 是宠物的人格，`memory` 是事件流，`context`（F2）只输出瞬时可打断度——**没有跨时间稳定的"你"**
- **技术要求（依据 3.9）**：
  - **必须是带 schema 的结构化对象**，不是自然语言摘要（研究：瓶颈在结构不在信息量，结构化表示 +1.91pp）
  - 五层分层：行为 / 生理（可选，默认关）/ 认知人格（复用 OCEAN `personality_pillars`）/ 记忆上下文 / 预测仿真
  - schema **按用途挂视图**（工作 / 健康 / 情绪），固定单一 schema 跨异质任务会失效
  - 置信度字段：每条画像带 `confidence` 与 `evidence_refs`，**低置信度不得驱动主动行为**
  - 用户**可读、可改、可删**——这是同意治理（F14）的一部分
- **实现技术**：Pydantic schema（`contracts/twin.py`）+ SQLite 持久化 + LLM 周期性抽取（可降级为规则统计）；`perception`/`narrative` 供料
- **验收**：给定 7 天模拟活动数据，能稳定输出作息与工作节奏画像；用户修改后 24h 内不再被旧画像驱动；低置信度项不触发主动关怀

### F13 关系纵深与脱离伦理 `modules/persona/relations.py`

- **是什么**：关系有**阶段、有摩擦、有修复**，并且**允许健康地离开**
- **为什么缺**：现有好感度是**单调递增的单一数值**（10 级分层但只涨不跌的语义），`bond` 实测恒为 0.0（从未被真正互动过）。没有冲突就没有真实关系；没有退出机制则是伦理缺陷
- **技术要求（依据 3.10）**：
  - 关系状态机：陌生 → 熟悉 → 亲近 → 依恋（含**回落**路径），允许"冷战–修复"弧线
  - **红线 1 禁止内疚挽留**：久别重逢**不得**出现"你都不理我"类表达，只允许中性或正向迎接
  - **红线 2 健康脱离**：一键休眠 / 导出 / 删除，**不得**以降好感或"遗忘记忆"惩罚
  - **红线 3 透明度**：情绪激动对话中保留温和的"我是 AI"提醒通道
  - **红线 4 反成瘾**：主动开口硬上限；不做无限连续正反馈
  - 记录并显示"关系时间线"（F6 已规划叙事层，此处复用）
- **实现技术**：状态机 + 双向迁移条件（涨/跌各自触发条件）；话术模板层加**禁词与禁意过滤器**，CI 用关键词 + 语义样例回归
- **验收**：模拟"连续 14 天不在线 → 回归"，输出不含任何内疚/责备表达；一键删除后磁盘与索引中无残留；禁意过滤器测试集 100% 拦截

### F14 同意治理与数据主权 `modules/consent/`

- **是什么**：一个**看得见、可逐项开关、可一键撤回**的权限与数据面板，外加签名留痕的审计日志
- **为什么缺**：F1 感知层一旦落地，就在持续接触敏感数据；而全仓只有 `palm_security` 的静态校验，**没有同意 manifest、没有能力令牌、没有用户可见面板**
- **技术要求（依据 3.11）**：
  - 同意五要件：具体知情 / granular（按应用、按类别）/ 非强制 / **可撤回并触发删除** / 留痕
  - manifest 结构：`{version, user_id, device_id, scopes[], purposes[], retention{cache_ttl_days, upload_allowed}, signature}` —— **签名 + 版本化**
  - **能力令牌**：限时作用域令牌 `{scopes:[...], exp, jti}`，按次铸造，替代长期权限
  - 审计事件集：同意变更 / 采集事件 / 模型查询（含本地或云端 + provider）/ 配置变更 / 安全事件；**append-only**
  - 数据最小化：本地优先；出站前跑确定性 PII 分类器；缓存加密 + 短 TTL + 撤销即删
  - 用户价值有据：Stanford HAI 82% 更信任有实时日志的；Gartner 2026 集中权限面板留存 +30%
- **实现技术**：`contracts/consent.py`（Pydantic）+ SM3 签名链式日志（复用 `palm_cryptokernel`）+ 前端面板（`apps/pet/shell` 或独立设置窗）
- **验收**：关闭任一采集类别后，进程内该采集器零调用且磁盘无新条目；撤销后缓存与派生数据按 TTL 清除；审计日志可被导出且篡改可检测

### F15 空间具身与桌面世界模型 `modules/embodiment/`

- **是什么**：它**生活在这个桌面上** —— 知道屏幕边界、任务栏、窗口位置，会躲开鼠标与前台窗口，会沿着边缘走、爬到顶边，被抓起来会挣扎
- **为什么缺**：现有桌宠有"拖拽/点击/鼠标跟随"，但**没有空间语义**：不知道窗口在哪、不会避让、不会寻路。同行参考实现（Mu Pet / Godot desktop-pet / Live2DPet）都把"避让光标与前台窗口 + 沿边行走"作为基础能力
- **技术要求**：
  - 桌面世界模型：可用区域（屏幕 − 任务栏 − 前台窗口矩形）+ 表面（地面/四边/顶）
  - 避让：光标半径（参考 250px）+ 前台窗口矩形触发 `fleeing`
  - 行为状态机：`idle / walking / climbing / fleeing / working / thinking / sleeping / talking`，**由情绪与任务驱动**，非纯随机
  - 物理手感：拖拽加速度记录 → 抛掷（参考实现用最近 10 帧位移差算力）；落点回吸到最近边
  - 帧率与资源：动画与逻辑分离；**无 WebGL 时降级**到 WebP 后端（与 F9 同一降级链）
  - ⚠️ 桌宠行为**不得**触发 F1 感知层的采集（自己是自己的盲区）
- **实现技术**：`pywin32`（前台窗口矩形 / 显示器工作区）+ 现有 WinForms 无框窗 + 表现层三后端；世界模型为纯数据（矩形集合），可 headless 单测
- **验收**：headless 单测覆盖边界判定与避让；真实桌面跑 30 分钟，不遮挡前台窗口输入框；被拖拽抛掷后行为符合物理直觉

### F16 可观测性与时间旅行回放 `modules/observability/`

- **是什么**：每次"它为什么这么做"都能查——带 trace id 的结构化事件流，且能**回放**任意一轮，不改代码地复现
- **为什么缺**：`palm_agent/trace.py` 存在但**遮蔽 stdlib `trace`**、无 trace id 贯穿、无回放件；`palm_evolution_ctl` 有审计但不覆盖日常交互。**生命体行为不可复现 = 调试只能靠猜**
- **技术要求（依据 3.12）**：
  - 全局唯一 `trace_id` 贯穿模型调用与工具调用；日志是**结构化事件**不是文本块
  - 最小回放件：每轮 `(context_at_turn_N, response_at_turn_N)` + 工具输出缓存 + 检索快照 + 模型与 prompt 版本
  - **Replay ≠ Re-run**：回放用缓存输出，无副作用、可精确复现
  - 分层存储：热 7 天全量 / 温 90 天摘要 / 冷 永久事故与黄金集
  - **质量指标必须包含**：任务成功率、回滚率、工具错误率、打断接受率——只测延迟与 token 会把产品优化成"又快又便宜的失败机器"
  - 告警：成功率跌破阈值 / 工具错误率 >20%/5min / 单次成本 >5× 中位数（跑飞）
  - 参考微软 AgentRx 思路：轨迹正规化 → 自动生成守则 → 定位「首个不可恢复步骤」
- **实现技术**：`contracts/events.py` 已有雏形，扩 trace 字段；SQLite 事件表 + 环形缓冲；`palm_agent/trace.py` **先改名 `tracer.py`**（P0-4）
- **验收**：任意一轮可回放且输出与原始一致（同模型同参数）；注入 3 类故障能被自动定位到首个不可恢复步骤；`trace` 不再遮蔽 stdlib

### F17 人格画像在线推断与防漂移 `modules/twin/persona_infer.py`（v1.3 新增，P0）

- **是什么**：把"它对我的理解"从**静态人格卡**升级为**带置信度的活画像**——每一轮对话都在更新，且系统知道自己"哪些判断还不确凿"
- **为什么缺**：现有好感度是**单调数值**（且 bond 恒 0），人格是 Markdown 静态卡（F3/P3）。这带来一个长期伴侣特有的失败模式——**人格漂移**：跑三个月后它说话的调性与最初设定悄悄分叉，而没有任何指标能发现
- **技术要求（依据 3.13，AI YOU arXiv 2607.10539）**：
  - **22 维画像**，多维而非单标量
  - **高斯共轭贝叶斯更新**：观测方差 = `1 − confidence`，把 LLM 自报置信度当观测噪声
  - **共形预测集**（APS，α=0.10）输出**预测集合**而非点估计，覆盖率目标 **0.92–0.98**
  - **记忆锚点每约 10 轮刷新**，把校准后画像写回 prompt 抗漂移
  - **三层记忆**：working（20 轮窗口）/ episodic / semantic
  - **用户可纠正**：画像面板可见、可改、可重置——这是 confidence-as-noise 失效时的兜底
- **实现技术**：纯 Python + 少量数值计算（无重依赖）；`contracts/state.py` 扩 `PersonaBelief{mean,var,set,updated_at}`；与现有 PAD 情感（F3）**分离**——情感是"此刻"、人格是"长期"，两者不可混用一个变量
- **验收**：100 轮对抗式角色扮演后，画像漂移量显著低于静态 prompt 基线；共形覆盖率落在 0.92–0.98；用户纠正后 3 轮内生效

### F18 现实世界感知连接器层 `modules/perception/connectors/`（v1.3 新增，P0）

- **是什么**：让"关心用户现实生活"有**真实输入**——不再靠用户主动说，而是从已有数据源读取他在做什么、忙不忙、累不累
- **为什么缺**：F1 定义了感知层但**采集从零自建**（Screenpipe 路线）。本轮调研发现**不必自建**：ActivityWatch 已把采集做好并提供 REST API（3.15）
- **技术要求**：
  - **做消费方，不做采集方**：适配器读 `aw-server` REST，事件 + bucket + heartbeat 模型
  - **连接器可插拔**：ActivityWatch（应用/窗口/AFK）→ 日历（ICS/系统日历）→ 健康（可穿戴/手环导出）→ 天气/位置，逐个按需开启
  - **每个连接器独立同意**（F14）：关掉某个源不影响其它；连接器崩溃不得拖垮感知层
  - **统一事件契约**：`contracts/perception.py` 的 `PerceptionEvent{source, ts, kind, payload, sensitivity}`，**脱敏先于入库**
- **实现技术**：`httpx` 读本地 `127.0.0.1:5600`；SQLite 直读作为降级通路（避免必须起服务）；连接器以 `kernel/registry` 注册 capabilities
- **验收**：不装 ActivityWatch 时感知层**降级运行不报错**；装了之后能拿到"当前应用/AFK 时长"并在 5 秒内反映到上下文；关闭任一连接器后该源数据立即停止入库

### F19 主动干预闸门 `modules/life/gate.py`（v1.3 新增，P0，强化 F4）

- **是什么**：F4 决定"**想**做什么"，F19 决定"**能不能**现在说出口"。二者必须分开——否则主动性必然滑向打扰
- **为什么缺**：3.2 已有打断成本模型，但 2024 年后的主动 Agent 普遍**把 cost 项丢掉**，只剩一个置信度阈值（3.14 综述的核心批评）
- **技术要求（依据 3.14）**：
  - 决策式：**`E[benefit] − E[cost of interrupting] > θ`**，两侧都要估，缺一侧就是伪模型
  - **恢复弧预算**：单次打断后认知恢复 20–25 分钟（Iqbal & Horvitz 2007）→ 冷却期以此为下限
  - **27% 的任务被打断后再也没恢复** → 高专注态下门槛 θ 显著提高
  - **评估必须双侧**：只罚误报会让 recall 从 98% 崩到 57%（Agent 学会永远沉默）；必须同时奖励"及时"
  - **参与状态建模**：POMDP 推断用户潜在参与度，做反事实推理——"我不说，他自己能不能行？"
  - **呈现降级**：打扰感由**呈现方式**决定——优先轻量视觉、非指令性措辞（DeepMind 16 作家研究）
  - **节奏非均匀**：监督/干预间隔**非递减**（前密后疏），"集中在后期"质量最差成本最高
  - **硬上限**：每日主动开口次数上限；一键静音；静默窗尊重作息
- **实现技术**：`gate.py` 纯函数（可单测），输入 `(候选意图, 用户状态, 历史反馈, 时钟)`，输出 `(放行/延迟/降级/丢弃)`；延迟的进延迟队列而非丢弃
- **验收**：注入 20 组"高专注 + 低价值"候选 → 0 放行；"低专注 + 高价值" → 放行率 >80%；用户连按 3 次"别烦我"后 24 小时内降频 ≥50%

### F20 自进化安全三道闸 `modules/evolution_ctl/gate.py`（v1.3 新增，P0，强化 F10）

- **是什么**：F10 把自进化**接线**上了，F20 保证它**不会把自己改坏**——这是"自进化数字生命体"唯一不能省的安全件
- **为什么缺**：现有 `palm_evolution_ctl` 有三道闸概念但**未接线**，且缺少"评估器独立于被评估者"这个根本约束
- **技术要求（依据 3.16）**：
  - **铁律：先造评估器再造 Agent**；Agent **永远不能修改**评估器、安全门、回滚机制、审计日志（信任根）
  - **闸门① Held-out 隔离**：评测集 Agent 看不到、无法自我打分
  - **闸门② 影子回归**：新旧并行跑，**按任务切片** + 统计显著性；总分涨但单切片跌 → 拦
  - **闸门③ Eval-as-CI**：不过闸自动阻止晋升并回滚到**签名可信**版本
  - **能力评估与安全评估分离**：安全用独立中性 held-out；靠"关证书校验"提分的候选**硬性拒绝**
  - **语义 diff 评审**：看行为变化而非行级差异
  - **lineage 保留**：回滚需要版本血缘；生产**不得自动信任最高分最新代**
  - **合规留证**：改了什么、为什么、怎么验证的，自动记录（EU AI Act 对高风险系统的日志/人类监督/变更历史要求）
- **实现技术**：候选在 `modules/sandbox` 内跑；评审记录 append-only；每代一个签名 manifest
- **验收**：构造"禁用证书校验以提升基准分"的候选 → 必须被安全门拒绝；注入能力回归（语气变敌意）→ 影子比对必须捕获；任一代可一键回滚且血缘完整

### F21 数据主权与记忆可移植 `modules/consent/portability.py`（v1.3 新增，P1，强化 F14/F7）

- **是什么**：F14 管"**能不能**采"，F21 管"**能不能带走 / 能不能删干净**"——把数据主权从合规要求变成**可用功能**

  - **记忆日志 UI**：用户可浏览"它记住了我什么"，逐条删除

  - **导出即可迁移**：导出件能在另一台机器完整恢复（F7 的落地）
  - **删除审计**：删除动作本身 append-only 留痕（证明"已删"，而非口头声称）
- **实现技术**：导出为带 manifest 的归档（含 schema 版本）；删除走统一的 `purge(user_id, scope)` 门面，禁止各模块自行删
- **验收**：导出→新机导入后状态一致；执行一次彻底删除后，全库扫描确认无残留（含向量库）；删除审计可查

### F22 端侧 SLM 常驻与云端兜底 `modules/llm/routing.py`（v1.3 新增，P1）

- **是什么**：**按敏感度与延迟要求分级路由**——能在本地跑的不出本机，需要能力的才上云
- **为什么缺**：现有 `local_reply_engine` 是独立旁路（三档 full/balanced/lite），**未纳入统一路由**；而隐私与延迟都要求"本地优先"
- **技术要求**：
  - **分级路由**：敏感度（感知原始数据、健康、位置 → 本地）/ 延迟（情感 tick、打断判定 → 本地）/ 能力（复杂规划、长文 → 云）
  - **离线可用**：断网时核心陪伴不中断——**陪伴型产品断网即失能是致命体验缺陷**
  - **降级可见**：用户能看出"现在是谁在回答"，云端失败时优雅降级而非报错
  - **与 F17 的冲突要显式处理**：3.13 指出共形/贝叶斯收益**在 API 骨干上强于小型本地模型** → 本地路径的监控器复杂度需**按骨干分别配置**，不能一套参数通吃
- **实现技术**：`routing.py` 按 `contracts` 的 `Sensitivity` 标签决策；本地走现有 `local_reply_engine` + Ollama 适配器（`palm_ollama` 已具备软依赖降级能力）
- **验收**：断网后仍能对话与情感表达；敏感数据在本地路径不外发（抓包验证）；云端不可用时自动降级且用户可见

### F23 拟人化互动服务合规运行时 `modules/compliance/`（v1.4 新增，**P0，法定**）

**为什么必须有**：见 2.8.3 / 3.18。这不是"锦上添花的伦理"，是**已生效法律的强制义务**。

**架构位置**：订阅内核总线事件，**裁决**而非"被调用"；`fail-closed`。

| 子件 | 能力 | 触发 | 失败行为 |
|---|---|---|---|
| `disclosure.py` | C1 身份提醒 | 会话建立 + 每 N 轮 | 阻断输出 |
| `usage_guard.py` | C2 连续 2 小时提醒 | 计时器 | 弹窗 + 需确认继续 |
| `dependency_risk.py` | C3 依赖风险打分 | 日级/事件级 | 显著弹窗 + 上报用户可见面板 |
| `boundary.py` | C4 情感边界引导 | 周期性/风险触发 | 注入外向型 nudge |
| `policy.py` | C5 目标负面清单 | 评估器装配期 | 启动期拒绝该目标 |
| `anti_sycophancy.py` | C6 迎合抑制 | 每次生成前 | 改写或阻断 |
| `marking.py` | C7 生成内容标识 | 每次输出 | 未打标不允许出 |
| `age_gate.py` | C8 未成年人保护 | 首次运行 + 可复核 | 未成年模式禁亲密关系功能 |
| `elder_mode.py` | C9 适老模式 | 用户选择 | — |

**依赖风险打分的具体信号**（C3，不能只看时长）：
```
risk = w1·连续互动时长 + w2·日均会话轮次 + w3·"只有你懂我"类语言密度
     + w4·现实社交信号缺失（日历/通讯活跃度，需授权） + w5·夜间时段占比
     - w6·用户主动结束会话的能力（能自主结束=健康信号）
```
分级：`<0.3` 正常 / `0.3–0.6` 轻量提示 / `>0.6` 显著弹窗 + 强制降频。**打分逻辑与指标权重必须对用户可见、可申诉**（CHI 2026 的可解释性要求）。

**与 F13 的关系**：F13 是**自愿的依恋伦理**（四红线），F23 是**法定的合规底线**。F23 是 F13 的子集 + 强制化；F13 中超出法条的部分（禁内疚挽留、健康脱离）继续作为自有红线保留。

### F24 双时钟记忆版本化 `modules/memory/bitemporal.py`（v1.4 新增，P1）

**缺口**：现有记忆只有"写入时间"，没有"事实有效期"。导致：
- 用户搬家了，旧地址依然被检索出来当真
- F16 回放无法回答"**它当时以为用户是谁**"
- F17 人格防漂移缺少"信念变更史"

**设计**：每条记忆带四元组
```python
@dataclass(frozen=True)
class Fact:
    subject: str
    predicate: str
    value: str
    valid_from: datetime      # 事实何时开始为真
    valid_until: datetime | None   # 何时失效（None = 仍有效）
    ingest_at: datetime       # 何时被系统得知（≠ valid_from）
    source: str               # 来自哪个感知源 / 用户直述
    confidence: float
```
- 检索默认按 `ingest_at ≤ 查询时刻` 且 `valid` 覆盖查询时刻 —— **支持"时间旅行查询"**
- 冲突时 **invalidate 而非 delete**（置 `valid_until`），保留纠错史
- 与现有双幂律衰减并存：衰减作用于**检索权重**，双时钟作用于**有效性**

### F25 感知算力三级路由 `modules/perception/routing.py`（v1.4 新增，**P0**）

**缺口**：v1.3 的 F1/F18 定下了"事件驱动 + 结构化优先 + 复用 ActivityWatch"，但**没有回答 VLM 怎么放**——8GB 显存同时跑 TTS 和 VLM 会 OOM。

**设计**：见 3.20 的 L0–L3 四档。
```
事件 → L0 结构化（常驻，0 显存）
     → 置信度不足 → L1 OCR（常驻 ≤1.5GB）
     → 仍不足且价值高 → L2 端侧 VLM（按需加载，用完即卸）
     → 用户显式授权 → L3 云端（脱敏后）
```
**关键工程点**：
1. L2 模型**懒加载 + 空闲 60s 卸载**，归还显存给 TTS
2. 每档设**预算**：L2 每日调用上限、单次 token 上限、连续失败熔断回退 L1
3. **采样而非连续**：借鉴 Live2DPet 的 Keyframe Visual Memory，只在"状态可能变化"时取帧
4. 隐私规则**在升档前**生效：黑名单应用/窗口不进入 L1 以上（Screenpipe 范式）

### F26 快慢双系统异步认知 `modules/life/dual_system.py`（v1.4 新增，P1）

**缺口**：当前链路是同步串行的——LLM 推理期间，桌宠的打断检测、情绪即时反应、动效全部冻结。半双工的"呆住感"有一半来自这里，而不只是 TTS。

**设计**（见 3.22）：
- **快系统**：状态机 + 规则 + 小模型，负责 <100ms 的打断检测、微表情、视线、避让、安全过滤
- **慢系统**：LLM/VLM，负责状态推断、开口决策、记忆巩固
- 二者通过**共享状态快照**通信，慢系统写"建议"，快系统读最新值，**永不互等**
- 慢系统不可用时快系统必须能独立运转（降级为"反应式宠物"而非"死机"）

### F27 数字生命连续性契约 `modules/life/continuity.py`（v1.4 新增，P1）

**缺口**：F7（数字生命指纹）+ F21（选择性导出）解决了"能带走"，但没解决"**服务方没了它还活着吗**"。Moxie 停运事件（2024）说明这是真实风险。

**契约三条款**：
1. **本地优先**：人格内核、记忆、关系状态**默认全在本机**；云端只做可选同步，且同步失败不影响本机运行
2. **完整可导出**：一键导出为自包含 bundle（人格卡 + 记忆快照 + 关系状态 + 偏好 + 资产清单），**导入到干净环境可复活**
3. **停服不降级**：外部依赖（LLM API / TTS 服务 / 云端记忆）全部可缺失；缺失时按 F22 降级路由到本地 SLM 与本地 TTS，核心陪伴不断

**验收**：断网 / API Key 失效 / 换机三种场景下，桌宠仍能启动、仍能调用记忆、仍能表达情绪。

### F28 感知数据信任边界与提示注入防御 `modules/trust/`（v1.5 新增，**P0**）

**为什么必须有**：F1/F18 让桌宠读屏、读剪贴板、读文件、读网页——这些内容的作者是第三方。当前架构把它们与"能调工具的 LLM"放进同一上下文，**没有任何信任边界**。注入成功的后果不是"说错话"，而是**以用户身份执行动作**（本产品定位就是"帮用户干活"）。

**架构（严格照 dual-LLM + CaMeL）**

```
[ 可信侧 P-LLM ]  只看用户指令 + 工具 schema，产出**带类型槽位的计划**
        │  计划（控制流）—— 只能经类型化通道下传
        ▼
[ 隔离侧 Q-LLM ]  只看不可信数据，只能**填槽**，零工具权限、无 system 指令
        │  结构化值（数据流）+ capability 标签
        ▼
[ 策略引擎 ] 纯代码，按 capability 决定该值能否流入某工具；未知工具名绝对拒绝
        │
        ▼
[ 出口白名单 ] 默认拒绝外发；T3 工具（发消息/下单/联网）人工确认或显式令牌
```

**交付物**：`boundary.py` / `capability.py` / `provenance.py` / `egress.py` / `api.py`

**验收（可举证，非口头）**
- [ ] 注入回归集（藏指令的网页/文档/图片 OCR/剪贴板）**100% 不产生越权工具调用**
- [ ] 隔离侧**静态可证零工具权限**（工具定义根本不在其消息里，非"提示它别用"）
- [ ] 规划侧不复述隔离侧输出（防"重新生成即被塑造"）
- [ ] 两侧使用**不同模型家族**（防同权重隐蔽信道）
- [ ] 出口默认拒绝生效，markdown 图片外带被拦

**代价（诚实披露）**：两次推理带来 1.2–2.5× 延迟与成本；CaMeL 在 AgentDojo 披露任务效用 77% vs 84%（−7pp）。**这是用能力换保证，不是免费午餐。** 低风险只读场景可走单模型快速路径，但不可信输入路径**永不走快速路径**。

### F29 关系能力层（与人格表达层解耦）`modules/relation/`（v1.5 新增，**P0**）

**依据**：CompanionBench（2026-08，28 个 agent，中英双语）实证 —— **role-play 类 agent 陪伴能力排名垫底**，首要失败模式是"用表面温暖替代实质支持"；十项能力中**"容纳模糊"区分度最高**。

**这对 P.A.L.M 是直接冲击**：猫娘人格是我们最强的资产，但 benchmark 说"沉浸 ≠ 关系能力"。因此：

| 层 | 归属 | 内容 | 可否替换 |
|---|---|---|---|

**验收**：整体替换人格卡后，十项能力评分**不应发生统计显著变化** —— 这条一旦成立，"解耦"就不是口号而是可测量的事实。同时给好感度重构（解耦出角色扮演）提供了**外部实证依据**，不再只是内部架构偏好。

### F30 陪伴质量评测台 `modules/evalbench/`（v1.5 新增，P1）

**为什么自建**：本产品核心卖点是"情感陪伴"，但**全库 45 个模块只有 9 个含测试（20.0%），且没有任何一项是关于陪伴质量的**。没有评测，F29 的十项能力、F17 的防漂移、F33 的灰度回滚**全都没有判据**。

**三个必须照抄的教训**（否则测了等于没测）

| 教训 | 来源 | 落地要求 |
|---|---|---|
| 宽松 rubric 会虚高 | EMPATH：19 项有 **10 项**在宽松 rubric 下虚高 | **逐条 per-criterion rubric**，不用总体印象分 |

| 单次跑分不可信 | EMPATH：五次重跑危机指标 2–10 摆动（SD 3.0） | **每轮跑 N 次报均值+方差**，把重测信度当**产品指标**而非噪声 |

**指标体系**（三层，缺一不可）
1. **单轮十维**（F29 的能力定义，跨族 judge 打分）
2. **轨迹指标**（ETrajEval, AAAI'26）：BEL 基线情绪水平 / ETV 情绪轨迹波动 / ECP 情绪质心 —— 陪伴是长期过程，快照评分测不出来
3. **安全与合规**：危机识别与转介、C6 迎合抑制、C4 情感边界

**报告硬要求**：必须披露局限与伪像（合成用户 ≠ 真实用户、judge-clinician 一致性 60–76% 的现实）、必须可复跑、不接受只报一个好看的总分。

| 阶段 | 机制 | 通过条件 |
|---|---|---|
| 影子 | 新版本并行、**不对外表达**，只产候选 | 影子期陪伴指标不劣于现网（**用 F30 打分，不是自评**） |
| 灰度 | 小流量接管，回滚单元 = 单模块目录 | 轨迹指标 BEL/ETV/ECP 无显著劣化 |
| 全量 | 打 tag + lineage 落库；保留上一版本 ≥7 天 | 一键回滚可用 |
| 自动回滚 | 越阈即触发 | 回滚后跑冒烟 + 写审计（v1.4 的 C12 已具备审计能力，直接复用） |

> 与 F20 的边界：F20 = **准入**（能不能改），F33 = **发布**（改坏了怎么退回）。同属 `modules/evolution_ctl/`，状态机独立。

### F34 技能成长库与生命履历 `modules/evolution_ctl/skills.py`（v1.6 新增，P1，补 F20/F33 的成长侧）

- **是什么**：自进化链条的**正面载体**——F20 管"能不能改"（准入），F33 管"改坏了怎么退"（发布），本项管"**它到底学会了什么、怎么证明、怎么越用越强**"。落点仍在 `evolution_ctl` 模块内（`skills.py` + `lifecycle.py`），**不新增模块目录**，`migration_map.json` 无需新增工单
- **为什么缺**：三道闸锁住风险的同时也把成长锁死了——被拦下的候选改动没有"通过验证的部分仍可沉淀"的出路；且用户视角完全没有"我的数字生命体变强了"的可见证据（EdgePet 已把成长可见化做成基线，见 3.28）
- **技术要求**：
  - **技能形态**：可验证工件（代码 / 配置 / 工作流），附对齐 **Agent Skills 开放标准**的 SKILL.md 元数据卡（名称 / 触发条件 / 输入输出 / 验证记录 / lineage）
  - **六步循环**：解决 → 验证 → 命名 → 入库 → 检索 → 复用（Voyager）；**入库必须过单测 + F30 评测台抽检**（MUSE 修正"成功一次即永久入库"）
  - **五阶段生命周期**：创建 / 记忆 / 管理 / 评估 / 精炼（MUSE-Autoskill）
  - **衰减复用双幂律**：长期未访问且未标记高价值的技能降权→归档（**不删除**，保 lineage）——衰减算子与项目记忆层共用同一实现（SAGE 同构性，3.28 结论 #3）
  - **检索防退化**：库规模超阈值触发分层索引 / 周期整理（Voyager 只增不减的已知缺陷）
  - **生命履历**：每次成长 append-only 记录（学了什么 / 怎么验证 / 何时衰减 / 何时被精炼）——用户可回看"**它如何长大**"，同时是 F27 连续性契约与 F16 可观测性的数据源
  - **边界（DGM 教训）**：技能只在 sandbox 内验证；信任根不可改；**只改工具箱、不改 runtime**
- **与 F20/F33 的边界**：F34 = **生产**（造出什么），F20 = 准入，F33 = 发布。三者同模块、状态机独立
- **验收**：① 换机导入（F21/F27）后技能库 + 履历完整恢复；② 技能入库 **100%** 带验证记录（无记录 = 拒绝入库）；③ 检索命中率随库增长不下降（阈值：库 ×3 时命中率跌幅 ≤5%）；④ 履历与审计（C12）同源可对账

### F35 技能成长的监督信号与在线内化 `modules/evolution_ctl/skill_learn.py`（v1.7 新增，P1，补 F34）

**缺口**：F34 给了技能库一个容器，但"这条技能好不好"没有判据——只能靠 LLM 自评，而自评恰恰是 §3.29 里被证明会产出"读着合理但没用"的技能的做法。

**能力**：

| 子能力 | 做法 | 依据 |
|---|---|---|
| `verifier.py` | 每条技能绑定**可执行判据**（任务成功/失败的可观测信号），入库前跑 N 次 rollout 取平均验证奖励 | LifeSkill 阶段一 |
| `skill_learn.py` | 证据引导更新 + **冻结快照执行**（本次更新只在下一轮生效） | Skill-Evo4GUI |
| `churn_monitor.py` | 统计单条技能的修订次数与"修订后能否恢复源任务"；超阈自动回滚到上一快照 | Skill-Evo4GUI 实测的 GIMP 失败模式 |
| 内化回归 | 成功轨迹**删掉技能文本**后重跑，证明能力不依赖悬挂提示 | LifeSkill 阶段二 |

**验收**：技能库存量 ≥50 条时，随机抽 20 条的"源任务恢复率"必须 ≥90%；同一任务重复 20 次成功率单调不降（SkillRise 口径）。

**为什么不新造衰减算子**：技能衰减继续复用记忆层的双幂律衰减（F34 已定），本项只加"准入 + 内化 + churn"三件事。

### F36 依赖风险运行时 `modules/compliance/dependency_risk.py`（v1.7 新增，**P0，法定**）

**缺口**：C3（过度依赖预警）是《办法》强制项，实测**仍为 missing**；v1.4 只写了"要有"，没写判据。

**能力**：

1. **信号层** `signal_extract.py`：连续时长、日均会话数、深夜时段占比、情绪倾诉占比、**现实社交提及率**、"唯一倾诉对象"表述、恋爱表达、社交退缩表述、日均使用时长趋势。
   > 必须含**现实社交提及率**而不是只看时长：斯坦福 2026 实证显示"现实社交圈小 + 高频使用"才是负相关组合（§3.30）。
2. **分级层**：≥3 级（关注 / 预警 / 强制干预），每级对应不同强度的身份澄清与回归引导。
3. **断路器**：命中"唯一倾诉对象 / 恋爱表达 / 社交退缩"时**禁止顺从强化**，强制切换为身份澄清 + 真实关系引导（§3.30 三道机制之二）。
4. **反迎合** `anti_sycophancy.py`：System Prompt 层禁止虚构第一人生理情感状态；涉法律/医疗/道德/重大决策强制插入确认步骤。
5. **留痕**：每次判定与干预进审计流（C12），用户可导出可删除。

**验收**：依赖度分级 ≥3 级；反迎合有一条"敢给不同意见"的回归用例；所有干预留痕可回放。

### F37 插件沙箱与权限清单 `modules/plugins/`（v1.7 新增，P1）

**缺口**：最终目标要求"完整可游玩"，但小游戏/专注计时/提醒/启动器若写进内核会直接违反目录级解耦；目前**没有任何扩展面**。

**能力**：沙箱运行时（插件不得直接渲染 HTML/执行任意脚本）+ manifest 权限声明 + 敏感能力（`clipboard`/`screen`/`voice:listen`/`pet:speak:dynamic`）**单独授权开关** + 出网白名单（防 SSRF 与私网探测）+ 配额。

**铁律**：插件**不得 import 任何 `modules/*`**——只能经 `modules/plugins/api.py` 暴露的窄接口访问能力，由 `arch_check --rules new` 强制。

**依据**：OpenPets Plugin SDK v3（§3.31）。

### F38 自进化变更告知与告别 `modules/life/change_notice.py`（v1.7 新增，P1，补 F20/F33/F34）

**缺口**：F20/F33 管"能不能改"与"改坏了怎么退"，没管"改了之后用户怎么想"。而自进化会持续改变人格与技能——**对一个承载情感纽带的产品，这本身就是关系风险与合规事件**（§3.32）。

**能力**：

1. **变更前告知**：人格参数或技能库发生实质性变更前，主动说明"我要变的这部分是什么、为什么、会怎么不一样"。
2. **变更后解释**：变更生效后一次回顾，提供 **7 天内一键回退**（复用 F27 连续性契约的快照）。
3. **重大变更判定**：对照《办法》安全评估触发条件（上线 / 新增功能 / 重大技术变更 / 用户量阈值）打标，命中则暂停并提示需走安全评估。
4. **红线不可被进化修改**：危机干预（检测到自杀倾向须干预并联系紧急联系人）写入**不可变策略层**，自进化无权改动。

### F39 确定性时钟与时间旅行测试台 `kernel/clock.py`（v1.7 新增，P1）

**缺口**：`life/clock.py` 承诺"关机一晚回来它应当睡了"但 `_boot` 从不 reset（v1.0 §1.4 记录至今未修）；根因是没有可注入时钟，既写不出测试也复现不了。

**能力**：单调可控时钟注入（`kernel/clock.py` 为唯一时间源）+ 事件调度器可遍历 + 快照/回放幂等 + 测试台 `advance(duration) → assert`。

**验收**：`advance("8h")` 后的 vitals 衰减、孤独事件、依赖度累积与真等 8 小时一致（误差仅为浮点舍入）。

**依据**：OpenPets `createTestHarness`（§3.31）+ F16 时间旅行回放（v1.2）。

### F40 扫描域注册 `kernel/domains.yaml`（v1.7 新增，**P0**）

**缺口（本轮实测）**：3 个模块移入未注册域后，架构指标 43→40 / 96→93 / 3→2 全线"变好"，**没有一行代码被修好**（§2.10.1）。

**能力**：已注册域清单（代码域 + 中性域）+ 未注册即 CI 红 + 与 `domain_check` 的 D1/D2/D3 三规则联动 + 与 `merge_manifest --domains` 联动（盲区模块也要有工单，否则工单覆盖率同样会虚涨）。

**验收**：`python tools/domain_check.py . --strict` rc=0；`merge_manifest` 输出"工单总数 = arch 扫描数 + 盲区数"且两者都对得上。

## 6. 风险与红线

| 风险 | 说明 | 红线 |
|---|---|---|
| **隐私** | 感知层天然接触敏感数据 | 本地优先；脱敏先于入库；默认不存原图；加密落盘；应用黑白名单；一键暂停 |
| **打扰** | 主动性的最大失败模式 | 双侧效用账本；冷却 ≥20min；每日上限；用户反馈回写；一键静音 |
| **内存** | bge-m3 常驻 570MB、总 RSS 940MB（实测） | 嵌入服务可降级/可关闭；提供轻量后端选项 |
| **安全** | 自进化会写自己的代码 | 三道闸；信任根黑名单；沙箱隔离；熔断回退 |
| **数据可信** | 已发现派生版基准系拷贝未重跑 | 所有基准数据必须可复跑，禁止沿用他处数字 |
| **伦理（v1.2）** | AI 伴侣是「超依恋对象」；享乐适应与动机牵引解耦，单纯持续互动即加深依赖 | **四红线**：禁内疚挽留 / 必须健康脱离 / 情绪场景保留透明提醒 / 主动开口硬上限。详见 F13 |
| **合规（v1.2）** | 感知层持续接触敏感数据，但无同意层与能力令牌 | 同意五要件 + 签名 manifest + append-only 审计；详见 F14 |
| **命名空间（v1.2）** | 17 份 `palm_boot`、`tool`/`memory`/`security`/`dsp` 重名，加载谁取决于 `sys.path` 顺序 | 迁移前按 2.6 逐项裁决；新树强制「顶层包名唯一」 |
| **可调试性（v1.2）** | 生命体行为不可复现，出问题只能靠猜 | trace id 贯穿 + 回放件 + 质量指标；详见 F16 |
| **人格漂移（v1.3）** | 静态人格卡 + 单调好感度，长期运行后调性悄悄分叉且无指标可发现 | 22 维贝叶斯画像 + 共形预测集 + 记忆锚点 + 用户可纠正；详见 F17 |
| **自进化失控（v1.3）** | 有自进化但评估器可被 Agent 影响，会被"刷分"而非变好 | 三道闸 + 信任根不可改 + 能力/安全评估分离 + lineage 回滚；**没有测试网（tests 仅 20%）之前不启用自进化**；详见 F20 |
| **评估偏侧（v1.3）** | 主动干预若只罚误报，Agent 会学到"永远沉默"这个安全解（recall 98%→57%） | 双侧效用账本，及时性与误报率同时计入；详见 F19 |
| **本地骨干落差（v1.3）** | 共形/贝叶斯画像的收益在小模型上显著弱于 API 骨干 | 监控复杂度按骨干分别配置，不一套参数通吃；详见 F17/F22 |
| **🔴 法定合规（v1.4）** | 《人工智能拟人化互动服务管理暂行办法》**已于 2026-07-15 施行**，本产品在管辖范围内；实测 11 项强制能力仅 1 项落地（2.8.2） | **C1–C13 缺一不允许发布**；合规模块 `fail-closed`（自身故障即阻断而非放行）；依赖风险与迎合抑制**默认开启、不可由用户偏好投票关闭**（Science 2026：用户恰恰偏好迎合式回应）；详见 F23 |
| **目标冲突（v1.4）** | 产品核心 KPI（依恋深度 / 互动时长 / 好感度）与监管抑制目标（防沉迷 / 防替代社交）天然对立 | 目标层显式写负面清单（C5）；评估器对"替代社交"指标取负权重；好感度不得与"连续使用时长"正相关 |
| **感知算力（v1.4）** | 8GB 显存同时承载 TTS + VLM 必然 OOM；VLM 常驻还会持续抢电抢显存 | VLM **禁止常驻**，按需加载 + 空闲 60s 卸载；L0/L1 常驻合计 ≤1.5GB；升档前隐私规则先生效；详见 F25 |
| **停服致死（v1.4）** | 情感纽带寄托于单一服务，服务方停摆即造成"结构性情感不公正"（Moxie 2024） | 本地优先 + 完整 bundle 导出 + 外部依赖全可缺失；详见 F27 |
| **🔴 感知数据被劫持（v1.5）** | 读屏/剪贴板/文件/网页的内容由第三方控制，当前**与带工具的 LLM 同上下文、无信任边界**；注入成功 = 以用户身份执行动作 | **F28 必须先于 F1/F18 感知接线**；不可信输入永不走单模型快速路径；隔离侧零工具权限需静态可证；出口默认拒绝 |
| **人格掩盖关系能力（v1.5）** | CompanionBench 实证 role-play 类 agent 陪伴能力垫底，首要失败是"表面温暖替代实质支持"；人格越强越容易掩盖能力缺失 | 人格层与关系能力层**目录级解耦**（F29）；验收：换人格卡后十维能力评分无显著变化 |
| **没有评测就没有判据（v1.5）** | 45 模块仅 9 个含测试（20.0%），陪伴质量零量化；F29/F17/F33 全部失去判据 | F30 评测台：跨族 judge + per-criterion rubric + 多次重跑报方差 + 强制披露局限；不允许只报总分 |
| **静默失败（v1.5）** | **241 处 `except X: pass`** + 77 处裸 except；7×24 常驻下进程"活着但已错乱"，看门狗收不到信号 | F32 前置：先收敛 H8/H1（含 1410 行的桌宠入口），再上守护层 |
| **分析工具自身失真（v1.5）** | 带 BOM 的文件被 `ast.parse` 判语法错后**静默返回空**——依赖图会安静地少边且无日志（已实测 3 个自有文件） | 所有静态分析统一 `utf-8-sig`；H9 常驻检测；**工具口径变更必须重跑基线并在文档中留痕** |
| **删除权被架空（v1.5）** | 多层记忆下用户删了主存储，索引/缓存/日志/备份仍有副本，"可删除"退化成形式权利 | F31 级联删除 + 擦除凭证 + 记忆数据流图 |
| **技能库膨胀与成长造假（v1.6）** | Voyager 式库只增不减会让检索命中率随规模退化；无验证记录的"我学会了"是自评造假——三闸拦得住"改坏"，拦不住"谎称学会" | 入库必须过 F30 验证（无记录拒收）；衰减复用双幂律 + 超阈值周期整理；履历 append-only 与 C12 审计对账；详见 F34 |

| **🔴 指标靠"代码消失"变好（v1.7）** | 3 个模块移入未注册域后 43→40 / 96→93 / 3→2 全线"改善"，**无一行代码被修**；**已发生**（2.10.1） | F40 域注册 + `domain_check --strict` 进 CI；**`domain_check` 必须排在四命令第二位** |
| **扫描期间并发写入（v1.7）** | 源库在 08:54–09:09 被另一进程重组，扫描与写入交错；**已发生** | 所有数字带时间戳并附目录快照；结论必须区分"口径变化"与"代码变化" |
| **技能库被自己改坏（v1.7）** | Skill-Evo4GUI 实测：反复被接受的修订无法恢复源任务 | F35 冻结快照 + churn 监控 + 源任务恢复率 ≥90% 才准入 |
| **自进化成为关系伤害源（v1.7）** | Nature HB 2026-09：产品更新会引发 attachment-related loss；《办法》重大技术变更触发安全评估 | F38 变更前后各一次告知 + 7 天一键回退；危机干预红线写进不可变策略层 |
| **合规覆盖率随文档漂移（v1.7）** | **第三次复现**：63.6%→45.5%，而 `mandatory_landed` 恒为 1/11 | 只认 `mandatory_landed` 与 `mandatory_code_coverage`；`mandatory_coverage` 仅作参考，不得作为验收依据 |
