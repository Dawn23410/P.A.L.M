# 敏感数据虚拟化：脱敏砖 + 凭据管理器设计

> 版本：v1.3  日期：2026-10-16
> 目标：给 AI 一个"敏感数据的虚拟环境"——AI 拿到的全是格式合法的假值，真值由凭据管理器安全持有。
> 原则：fail-closed、最小暴露面、可逆映射、诚实披露还原边界。
> 决策记录（2026-10-15 已确认）：①假值生成引 FPE 密码库；②凭据主密钥=系统密钥派生；③文件隐形范围=仅凭据文件；④落地顺序=文件隐形优先。
> 决策追加（2026-10-16 已确认）：⑤借阅裁决一律走 guardrail（reveal 不再内置简单判断，支持注入规则覆盖内置字段）。
> 决策追加（2026-10-16）：⑥AI 经用户审批可直接拿真凭据（下发后传出可不回传，但防 memory 记忆）。

## 零、要解决的三个问题

1. **上下文泄露**：AI 提示词/工具结果里出现明文敏感信息（key、卡号、身份证、内网拓扑）。
2. **格式破坏**：若用普通占位符替换，AI 会因格式不对而写坏代码/算错——必须"格式保真"。
3. **凭据暴露**：真值不该只靠"脱敏"藏，更该让 AI 根本拿不到真实凭据本体。

## 一、架构总览：两条链

```
        真实世界                            AI 上下文
┌─────────────────────┐          ┌──────────────────────┐
│ 凭据管理器(Vault)    │ 注入真源  │                      │
│  └─ 真值加密持有     │─────────▶│  脱敏砖(Sanitizer)    │
│     AI 不可达       │   detect  │  ┌─ 识别敏感          │
│  用户管理/审批       │          │  ├─ 格式保真生成假值   │
└──────────▲──────────┘          │  └─ 映射图谱(真↔假)    │
           │ 还原                │          │             │
    ┌──────┴──────┐              │  发给AI ◀┘ 仅假值      │
    │ netguard DLP │◀──兜底──────│  AI输出含假值           │
    └─────────────┘  真值不出网  └──────────────────────┘
```

**关键分层**：
- **真源**（Vault）：加密持有真值，AI 只读、用户管理。
- **脱敏**（Sanitizer）：生成格式合法的假值 + 维护映射，AI 只见假值。
- **兜底**（netguard DLP）：即便脱敏遗漏，真值也过不了出站网关。

## 二、脱敏砖 Sanitizer Brick

### 2.1 职责与流程

| 步骤 | 能力 | 说明 |
|---|---|---|
| `detect(text)` | 识别敏感 | 复用 netguard 的扫描器（key 形态/私钥块/凭据赋值 + Luhn/GB11643 校验位）+ 新增类型（手机号/内网 IP/域名） |
| `sanitize(text)` | 生成假值 | 对每个敏感字段做"格式保真替换"，写入映射图谱 |
| `restore(text)` | 还原 | 在 AI 输出里把假值换回真值 |
| `reveal(key)` | 门控取真 | AI 要真值时走 guardrail 裁决（readOnly 拒 / askOnReveal 询问 / 其余按 profile） |

### 2.2 格式保真：核心设计决策

**你点中的关键点：不能占位符，格式必须匹配。** 决策：**引 FPE 密码库**（业界银行/医院级方案，FF1/FF3 算法，NIST 标准）。FPE 保证"加密后格式与原值完全相同"（16 位卡号→16 位数字、身份证→18 位含合法校验位），比自研格式模板更贴近"真加密"，可逆性由算法本身保证，映射图谱只做会话级绑定。

| 敏感类型 | 真实值形态 | FPE 假值 | 校验 |
|---|---|---|---|
| API key | `sk-abc123...` | FPE 保持前缀+同字符集同长 | 无需 |
| 手机号 | `1[3-9]\d{9}` | FPE 保持段位结构 | 段位合法 |
| 银行卡 | 16-19 位数字 | FPE 保持长度+数字 | Luhn 通过 |
| 身份证 | 18 位 | FPE 保持长度+字符集 | 校验位合法 |
| 内网 IP | `192.168.x.x` | FPE 保持私有网段 | isPrivateIp 通过 |

> 引 FPE 库引入一个运行时依赖（密码学库），这是刻意为之的安全投入。需在 `package.json` 声明（registry manifest `packages` 字段），由 install 装。

### 2.3 映射图谱 Vault（内存级）

```
Map<假值, 真值>   // 还原方向：AI 输出 → 真值
Map<真值, 假值>   // 替换方向：识别 → 假值
Map<假值, 元信息> // 类型/网段/过期时间，供还原策略参考
```

**生命周期**：一次任务/会话绑定一个图谱，任务结束即焚（防跨会话假值串扰）。图谱本身不进上下文、不出网。

### 2.4 还原策略与诚实边界

AI 输出的还原**不是 100% 可靠**，这是必须诚实披露的边界：

| AI 行为 | 还原 | 机制 |
|---|---|---|
| 原样回显假值 | 精确还原 | 命中图谱精确替换 |
| 截断/拼接假值 | 部分还原 | 片段 + 图谱正则重建 |
| 自由改写假值 | **失败** | 无法重建 → 返回 `null` + 审计告警 |

> **架构结论**：脱敏最可靠用于 **AI 当工具**（读写配置、调 API、结构化处理）；若让 AI 自由创作含敏感字段的内容，还原必然有失败率。这是使用边界，不是代码缺陷。

### 2.5 文件隐形（工具可见性过滤）

你提出的"文件隐形"是独立能力，比脱敏更干净（AI 根本没看见）。**范围（决策已定）：仅凭据砖维护的敏感文件清单，集中管理**，不开放任意路径：

| 能力 | 实现 | 扩展性 |
|---|---|---|
| `hidePath()` | 工具层 read/glob/list 结果里过滤指定路径，**根本不列给 AI** | 现阶段仅凭据文件清单，后续可扩展 |
| 隐形清单 | 凭据管理器维护的 manifest | 集中管理，单一真源 |

> 隐形 = 最好（AI 不知道）；脱敏 = 退而求其次（AI 知道但拿到假的）。**两层互补。**

## 三、凭据管理器 Credential Vault

### 3.1 目标：低暴露面 + 安全 + AI 脱敏只读 + 用户管理

| 需求 | 设计 |
|---|---|
| **低暴露面** | 真值只进内存，加密落盘；**不因"发 AI"而解密出上下文** |
| **安全** | AES-GCM 加密（主密钥经系统 keyring/用户口令派生）；真值字段不暴露在服务接口 |
| **AI 脱敏只读** | AI 只能经 Sanitizer 拿"假值"；要真值走 `reveal` 借阅，默认 `ask` 审批（guardrail 联动） |
| **用户管理** | 用户可增删改查凭据、设权限（读/写/借阅）、改主密钥、看审计 |

### 3.2 数据模型

```
Credential {
  id: string          // 稳定标识（图谱和审计用它）
  type: 'key'|'secret'|'card'|'id'|'host'|'other'
  secret: encrypted   // 真值（AES-GCM，仅内存解密）
  scope: string[]     // 允许哪些服务引用
  policy: { readOnly: boolean; askOnReveal: boolean }
  meta: { 格式模板; 创建人; 过期 }
  audit: Log[]        // 谁在何时借阅/修改
}
```

**主密钥（决策已定）：系统密钥派生**——用系统级 keyring/DPAPI 自动托管主密钥，用户无感、进程重启可用，不要求用户记口令。

### 3.3 访问控制流（AI 想拿真值时）

```
AI 请求读真值
  → CredentialVault.reveal(name)
  → guardrail 裁决（decide('credential.reveal', ctx)）：
       内置默认规则（readOnly→deny、askOnReveal→ask）+ profile 档位兜底
       deny → 拒绝（记审计）
       ask  → 转用户审批（记审计）
       allow/warn → 放行真值（记审计，warn 额外留痕）
  → 归还后销毁引用
```

**实现现状（决策 B，2026-10-16）**：`reveal` 一律走 guardrail 裁决，删除了旧的内置硬编码判断。默认提供 `GuardrailEngine` 内置规则集（readOnly 拒真值、askOnReveal 转询问、无规则命中按档位默认 `loose` 放行留痕）；也支持装配时注入外部 `guardrail` 覆盖——注入的规则可让内置字段（如 readOnly）不再直接决定结果，裁决权完全归 guardrail。

## 四、与现有 palm-core 的集成点

| 现有设施 | 复用方式 |
|---|---|
| `netguard.scan*` | detect() 识别敏感的直接复用 |
| `guardrail.decide()` | 凭据借阅/写入的权限裁决（5 档） |
| `registry` / `container` | 两个砖各注册 manifest + 能力槽 |
| `net` 门面 + DLP | 真值出网的最终兜底 |
| `file 工具` | 挂文件隐形过滤钩子 |

**砖块划分（已落地）**：
- `invisible.ts`（隐形砖）：文件隐形过滤（fail-closed，仅凭据文件清单）
- `sanitizer.ts`（脱敏砖）：detect/sanitize/restore + 会话映射图谱
- `credential.ts` + `dpapi.ts`（凭据砖）：系统密钥(DPAPI)加密存储 / 增删改查 / 审计 / 借阅 guardrail 裁决
- `security.ts`（安全砖装配层）：`installSecurityBricks()` 把隐形/脱敏/凭据三砖统一注册进 LifecycleController（manifest→Registry / cap→Container / Fiber→生命周期）
- 联动：凭据砖装载时把存储文件（master.key/credentials.json）自动注入隐形清单，卸载时回滚移除

## 五、风险与边界（诚实披露）

1. **还原非 100%**：AI 自由改写假值会还原失败，只能记日志降级。→ 适用场景限定为"AI 当工具"。
2. **脱敏不代替网络 DLP**：即便脱敏，真值若出网仍要 netguard 拦——**纵深防御，不互替**。
3. **图谱在内存**：重启丢失，多进程需共享图谱存储（后续可做）。
4. **文件隐形是"尽力"**：隐形过滤只作用于工具层返回，不能阻止 AI 通过别的推理猜到；更不防用户直接给真路径。
5. **无过自动化**：识别敏感仍有误报/漏报，需类型库持续迭代；宁可多脱敏不少脱敏。

## 六、落地路径（建议顺序，决策已定：文件隐形优先）

1. **P0 文件隐形**（已完成 `invisible.ts`）：工具层过滤钩子，仅凭据文件清单。
2. **P0.5 脱敏砖**（已完成 `sanitizer.ts`）：detect→sanitize→restore 打通，FF3 FPE + 映射图谱。
3. **P1 凭据砖**（已完成 `credential.ts`+`dpapi.ts`）：系统密钥加密存储 + 增删改查 + 审计 + 借阅 guardrail 裁决。
4. **P1.5 砖块装配**（已完成 `security.ts`）：三砖注册进 LifecycleController，含隐形联动 + 卸载回滚。
5. **P2 扩展**（待定）：多敏感类型、多任务会话图谱、guardrail 与脱敏/凭据的更深度编排。

> 与 P.A.L.M 既有 P0–P6 路线图对齐，可作为安全向的一个专项推进。
