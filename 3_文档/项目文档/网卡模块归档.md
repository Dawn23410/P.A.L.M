## 一、一句话结论

网卡门面（net）+ 安全管道（netguard）+ 网卡砖（network）三层职责清晰、已落地，**经真实联网端到端验证确实"真拦真放"**；本轮"网卡再找找"深挖原版遗留后确认无实质增量可补，按"拒绝过度设计"原则不再落地代码。

## 二、实现文件（palm-core/src/）

| 文件 | 职责 | 关键点 |
|---|---|---|
| `net.ts` | 网卡门面（唯一出网出口，fail-closed） | 不碰任何联网原语；无网卡注册即抛 `NetworkForbidden`；回环放行 |
| `netguard.ts` | 安全管道（拦截→验证→转发） | SSRF 私网校验 / 出站 DLP / 入站注入扫描 / 配额熔断 / 黑白名单 |
| `network.ts` | 网卡砖（唯一持有 fetch） | 装载即插卡（管道包裹裸执行器注入门面），卸载拔卡 |

**分层原则**：门面管"能不能出网"（fail-closed 判据），管道管"安不安全"（拦/放），网卡砖管"谁持有联网原语"。llm 等纯消费者经 `net.request` 出网，摸不到执行器与管道内部。

## 二·A、完整源码归档

网卡模块**完整闭环**源码原样归档至本目录下 **`网卡模块源码/`**（保留可用 .ts 形态）：

```
网卡模块源码/
├─ src/                      # 源码
│  ├─ net.ts                 60行   门面：NetFacade + NetworkForbidden + 回环放行
│  ├─ netguard.ts           339行   安全管道：NetGuardPipeline + isPrivateIp + DLP/注入扫描 + Quota + PolicyStore
│  ├─ network.ts             97行   网卡砖：NetworkBrick + createFetchExecutor + manifest
│  └─ llm.ts                 99行   唯一消费者示例：经 net.request 出网（不直接 fetch）
└─ tests/                    # 验证
    ├─ netguard.test.ts     管道单元测试（39 项，mock 裸执行器）
    └─ gate-e2e.test.ts     端到端真实联网（13 项，插真网卡）
```

依赖链：`network.ts → netguard.ts → net.ts`；`net.ts` 独立无依赖。消费者（`llm.ts`）只依赖 `net.ts` 的 `net.request` 出网，摸不到执行器与管道内部——这就是"网卡唯一持联网原语"的落点。

- **为什么要带 `llm.ts`**：它是网卡模块唯一的真实消费者，证明"业务经 `net.request` 出网、不直接 fetch"这条约束在真实现块里成立。
- **为什么要带 tests/**:单测证"规则对"，e2e 证"真实网络下真拦真放"，两套才闭环。
- 归档源码与 palm-core 当前版本一致，后续改动以 palm-core 仓库为准。

## 三、真实验证结论（tests/gate-e2e.test.ts）

| 小配额超限 | 配额熔断 | ✅ |
| 黑名单域名 | 拦 | ✅ |
| skipDlp 豁免 | 放行到执行器 | ✅ |
| 拔卡 | 恢复 fail-closed | ✅ |
