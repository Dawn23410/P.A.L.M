## 2. 人格引擎（v1.6）

### 整合了什么

| 原位置 | 内容 |
|---|---|
| 主工程 `palm/domain/roleplay/` | 角色卡模型、双线好感度（规则引擎 + 持久化）、动态叠加、角色污染守卫、Skill 导入 |
| 共享六面 `palm_faces/` | 人格面、情感面、律动面、储存面、档位常量、面骨架、装配器、传输包 |

**冲突处理**：两套 `CharacterCard`（主工程版字段全、CCv2/V3 对齐；六面版是早期简化版）→
**以主工程版为准**，并在其上补 6 个面层兼容字段（`tone` / `age` / `birthday` / `schedule` /
`safety` / `dynamic_updates_enabled`），补 `to_dict`/`from_dict`，使面层零改动即可用。
两套好感度 → 保留主工程的规则引擎 + 结算 + 存储；六面版只留档位常量（`stages.py`）。

### 结构

```
人格引擎/palm_persona/
├── character.py       角色卡（VoiceProfile / SceneBrief / CharacterCard）+ 增删查
├── persona_render.py  人设渲染器        ├── skill_import.py  Skill(MD) → 角色卡
├── affection.py       好感度结算        ├── affinity_engine.py  规则引擎(YAML)
├── affinity_store.py  好感度持久化      ├── dynamics_engine.py  动态叠加
├── pollution_guard.py 角色化污染剥离    ├── stages.py  官方 6 阶档位 + 默认卡
├── base.py            面骨架            ├── assembly.py  注入契约 + 装配器 + 回复拆分
├── transport.py       传输包 + 控制码   ├── host.py  宿主适配（主工程在场则复用，否则本地 Data/）
└── faces/  persona / emotion / rhythm / storage
```

### 面的归属（六面取消后）

| 面 | 现归属 | 理由 |
|---|---|---|
| 人格面 / 情感面 | **人格引擎** | 本次整合主体 |
| 律动面 | **人格引擎** | 其 docstring 自述「为人格引擎服务的运行时动态」（原计划给心智核心，发现缝合引擎也在用） |
| 储存面 | **人格引擎** | 三处都导出它；作为面框架的一部分 |
| 织语面 | **缝合引擎**（`local_reply.faces.weave`，实体） | 风格约束是缝合引擎本行；心智核心与 palm-chat 桥接它 |
| 记忆面 | **记忆项目**（`palm_memory.memory_face`） | 早已独立 |
| 中间件（注入契约 + 装配器 + 回复拆分） | **人格引擎** `assembly.py` | 见下方说明 |

> **关于中间件**：原计划给缝合引擎，实际放入人格引擎。原因：`InjectionModule` 是各面产出的
> **数据契约**（人格引擎的面必须依赖它），且心智核心与 palm-chat 也要用装配器 —— 放人格引擎可避免
> 「心智核心 → 缝合引擎」这类上层互依赖。缝合引擎/心智核心/palm-chat 的 `middleware/` 均为薄桥接，
> 调用面（`from middleware.inject import PromptAssembler`）不变。

### 主工程侧

`palm/domain/roleplay/` 的 8 个已迁出模块改为**薄桥接**（`import palm_boot` + 再导出），

| 来源 | ModelScope `onnx-community/bge-reranker-v2-m3-ONNX`（**HF 不可达，ModelScope 通**，0.3s 响应） |
| 位置 | `嵌入服务/palm_embed/models/reranker/`（与嵌入同项目、同进程、同锁策略） |

| 参数 | max_len 封顶 512、**ORT 锁 8 线程**（与 embed session 共存防争抢） |

**实测判别力**（3 候选）：`0.9222 / 0.0082 / 0.0040` —— 正解被显著拉开；
延迟：首次含加载 1623ms，**二次 61ms**（3 对）。

### 16.2 PDF / Word / Excel 解析

`palm_rag/engine.py` 的 `load_text` 按后缀分派：

| 格式 | 解析器 | 处理要点 |
|---|---|---|

依赖：`pymupdf / python-docx / openpyxl`（**清华源无 pymupdf 的 Windows wheel，需用官方源装**）。
