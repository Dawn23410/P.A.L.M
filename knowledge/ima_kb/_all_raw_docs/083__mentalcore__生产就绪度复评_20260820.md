## 三、50 轮对照测试关键数据（2026-08-19，供参考）

- **架构契约 100% 遵守**：mock/live 两组注入面 5/5、数据区协议（affinity_delta 消费不外发）双双 100%，证明功能正确性不依赖模型层。
- **本地编排开销可忽略**：mock 单轮 3.6ms；build_core 42ms、语义检索 1.8s（仅首轮）。
- **延迟根因已实证**：裸 httpx 同端点 TTFB 波动 1.2~15.5s，33s 级首字 = 免费端点排队，非代码缺陷。
- **情感链路有效**：R20 吃醋轮正确输出 Δ=-0.3；live 情绪识别可检负情绪与连续值。
- 已知局限：live 12 个异常轮全部伴随端点重试/挂起（httpx 600s 超时窗口），归因端点稳定性；mock 情绪词典对「累/压力/孤独」零命中属设计局限。

## 四、就绪路线图（按目标）

**若目标是"自己能长期用"（本地桌面）→ 现在即可上线**，建议：
1. 定期备份 `mentalcore_data/`（对话密文 + 向量密文 + .master_key 三件套）；
2. 接受延迟波动，或换付费/自建端点（TTFB 可降至秒内，50 轮报告 §5 缓解建议）；
3. 可顺手把 `emotion_via_llm=False` 关闭情绪 API，省一次排队往返。

**若目标是"内部单用户服务"→ 先补三件小事（预计 1 天内）**：
1. core 层自动重试（429/5xx 指数退避 + 超时参数 + 幂等去重）；
2. `/healthz` + 首字延迟/错误率指标（复用 logging，加个轻量打点即可）；
3. 端点故障切换（base_url 列表，首个失败自动换下一个）。

**若目标是"对外多用户 SaaS"→ 尚不可行**，需先补：向量加密（已做）+ 会话鉴权与租户隔离（大工程）+ core 重试 + SLA 端点，按首评 §5 的 P0/P1 全量推进后再评估。

## 五、控制码细粒度完善（2026-08-20 增补）

用户确认目标为「个人可用」，并对对外接口与内部控制码提出最小颗粒度要求。本次扩展（不改五位码位结构，旧码全兼容）：

**新增 13 条控制码**（`/code help` 可查全部用法）：

| 域 | 码 | 功能 | 载荷（颗粒度） |
|---|---|---|---|
| 系统 | 00000 / 01000 | 心跳 / 版本号 | - |
| 储存 | 10010 | 查最近 N 条对话明细 | limit |
| 储存 | 10110 | 清最近 N 条（保留更早） | limit |
| 储存 | 10120 | 删指定编号条（从 0 起） | index |
| 储存 | 10200 | 导出全部记录（JSON） | - |
| 记忆 | 21000 | 语义检索长期记忆 | query、top_k |
| 情感 | 30000 / 30300 | 查 / 改好感度（单数值） | base/bond/dynamics 给哪个改哪个 |
| 情感 | 31000 / 32000 | 查关系状态 / 最近情绪向量 | - |
| 人格 | 40000 / 40300 | 查 / 改角色卡（单字段） | 任意角色卡字段名 |

**颗粒度达成**：修改可定位到**单个数值**（好感度三值分别改）与**单个字段**（角色卡逐字段改，不触发防污染清档——换人设仍走 `update_persona`）；控制可定位到**单条记录**（对话记录按编号删除/最近 N 条清除）；查询可定位到**单条/单字段/单向量**。载荷经 `core.control(code, payload)` 传入，CLI 层 `/code 30300 base=5.0` 即用。

**边界保护**：好感度数值越界（base -50~100、dynamics -50~50）拒绝并提示；角色卡未知字段拒绝；删除编号越界拒绝；缺参拒绝——全部返回失败响应码（D5=2）不静默。

**验证**：pytest 17 项全过、selftest PASSED、端到端冒烟覆盖全部新码（改好感度/改角色卡/删单条/语义检索/重启持久化均实测通过）。
