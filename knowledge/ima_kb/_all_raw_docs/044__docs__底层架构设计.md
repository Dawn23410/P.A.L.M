# P.A.L.M 底层架构设计

> 状态：**纯设计文档，未落地**。起稿于 2026-08-18，随用户口述持续更新。

## 1. 总体形态：特殊主板

模拟主板架构，插槽**仅三种**（原设计曾有"核心"插槽，已删除，**心智核心即为中心**）：

| 插槽 | 说明 | 约束 |
|---|---|---|
| 心智核心 | 系统的中心（agent 框架、人格引擎等） | **仅唯一** |
| 扩展 | 等效 PCIe，高速扩展 | 可多个 |
| USB | 等效 USB，外设 | 可多个 |

- 心智核心是整块主板的中心与唯一，其余插槽围绕它工作。

## 2. 前后端分离

- 一个后端对应一个前端，**前端打包在砖块内**，随砖块加载时一同加载（非固定前端）。
- 效果：未加载 / 被禁用的砖块**不显示**其前端界面，加载后才显示。

## 3. 组件链接规则

- **ABC 仅用于插槽对外边界（2026-08-18 澄清）**：每个插槽（含心智核心）向主板 / 其他插槽暴露**插槽级 ABC** 接口；插槽之间的交互一律走该插槽 ABC。
- **插槽内部（PCB / 设备之间）无需 ABC**：同插槽内的组件是统一设计的内聚单元，可直连、可直接 import（如心智核心内的 cpu / 各面 / 模型层之间）。
- **约束**：组件不得跨插槽直接 import；跨插槽一律走插槽 ABC。

## 4. 扩展 PCB 设计

- 普遍采用"扩展 PCB"板设计：**一块板合并多个内容**。

### 4.1 扩展插槽承载范围

- 语音（表达层：TTS / STT）。
- 行动（工具集、React 等自主执行循环）。
- 其余高速扩展功能。

## 5. 设计原则

1. **最小接口**：能不扩大接口数量就不扩大。
2. **高复用**：减少相同依赖的重复下载。
3. **泛化高内聚**：相同功能泛化、高内聚。
4. **安全高内聚**：安全相关内容高内聚，**禁止其他组件持有**（如联网能力只归安全组件）。

## 5.1 全局规则（2026-08-18）

- **所有组件对 LLM 的影响，一律通过"模块"提示词注入方式**（经动态 prompt 注入中间件）；不得存在其他直接渠道（如直接改写模型参数、绕过注入直接改上下文）。

## 6. 心智核心（魔方）

- **定位**：唯一中心。目标——让 AI"活"过来，达成**高拟真度对话**。
- **范围收敛（2026-08-18）**：心智核心 = "LLM Pro 版"——只负责**"想"**（推理、记忆、人格、情感、缝合），**不负责"说与做"**：语音（表达）与行动（工具 / React 等）归入**扩展插槽**。
- 形态以"魔方"为隐喻组织：中心一个内核，四周多个功能面，彼此经 ABC 契约衔接，可旋转组合。
- **面 = 注入模块的生产者（2026-08-18 认知确认）**：从 prompt 视角，各面是**联动**的——记忆面 / 人格面 / 情感面 / 织语面 / 律动面全部产出注入"模块"，由动态 prompt 注入中间件（§6.9）组合成**一条 prompt** 交给模型层；模型层回复再经 LLM 回复拆分中间件（§6.11）把数据分发给各面。**心智核心 = 一个 LLM + 一条 prompt + 多个联动注入面**。
- **静态与动态分层（2026-08-18 定）**：人格卡（CharacterCard）是**初始静态设定**；另需维持**动态角色扮演注入**——每轮的运行时状态注入（人物状态 / 关系状态 / 时间日程 / 叙事进度），由律动面 / 情感面等联合产出。

### 6.1 中心：推理内核（模型层）

- 对话生成的算力底座，所有认知能力的出口。
- **首版范围（2026-08-18 收敛）：仅集成多供应商流式生成**——OpenAI 兼容（OpenAI / DeepSeek / Qwen 等云端端点）、Anthropic 原生、本地 Mock 离线回显；统一分片（正文 / 思维链 / 用量）。
- **保留接口、不执行**：原生工具调用（tool_calls 协议透传接口保留，供扩展插槽消费），心智核心内**不执行工具调用**；若工具调用不可用，**不得让 AI 感知到自己能调用工具**（fail-closed，防 AI 幻觉宣称工具能力）。
- **网络放开（仅此面）**：模型调用不做拦截、不设白名单（毕竟只是个 LLM）；该放开的网络**仅内销给 LLM 用**——仅供模型层调用模型端点，其他组件不可用；出网仍由安全组件统一出口，对模型层请求全放行。
- **暂不考虑**：本地 Ollama（归扩展插槽）、文件发送 / 多模态文件（魔方内不做）。

结论：推理内核面可从已有模型层直接复用其**流式生成与 tool_calls 协议**部分，无需重写。

- **封装关系（2026-08-18）**：推理内核（模型层）之下**封装一个更核心的 cpu**（编排引擎，见 §7.1）——cpu 是心智核心真正的核心，模型层为其外层封装；cpu 驱动各面、中间件与模型层，模型层只负责"算"。

### 6.2 记忆面：记忆层 + 本地记忆向量库

- **结论（2026-08-18）**：现有记忆引擎（Memory 类，palm/domain/memory/）**基本够用，直接复用**——五子模块（核心记忆 / 归档记忆 / 衰减计算 / Token 预算 / 写入决策）+ 本地向量语义检索（零联网）+ 短期记忆语义筛选 + 混合检索兜底（上下文真压缩已砍，见 §6.2.1）。
- **与中间件衔接**：记忆面是注入"模块"的生产者之一——**核心记忆 → 固定模块（在上，可缓存）；短期记忆 / 归档记忆 → 动态模块（在下）**。
- **不可用即不注入**：向量库不可用静默降级关键词检索；记忆整体不可用时静默不注入（AI 不自知缺失）。
- **Token 预算（2026-08-18 砍范围）**：TokenBudgetAllocator **仅负责"记忆"模块的传入 Token 预算分配**（核心记忆 / 短期 / 归档三块的内部比例）；**占比配置需向外索取**（不自带配置，由外部提供）。

### 6.2.1 记忆层级（与现有结构对照确认）

- **用户画像**（动态修改、永久保存）= CoreMemory 的 user_profile + personality（update_profile 更新、落盘持久化）。
- **长期记忆**（少改动、长期保存）= ArchivedMemory 归档记忆（注意：含幂律衰减与 prune 清理，属缓慢演化）。
- **短期记忆**（高频修改、短期保存）= 对话历史 50 轮滑动窗口。
- **工具记忆（2026-08-18 已砍）**：工具记忆相关机制（工具结果回灌、失败经验）**全部砍掉**，交由对应模块（扩展 / 行动域）解决；记忆面只保留纯对话记忆（用户画像 / 长期 / 短期）。
- **防污染删除（2026-08-18 定）**：**修改人设（character card）时，清空所有聊天记录与向量归档**，防止旧人设语气 / 记忆污染新人设。
- **上下文真压缩（2026-08-18 已砍）**：不保留——注入总量已受中间件限制，被裁剪的历史原文已归档 + 向量化，语义内容仍可检索召回；"摘要时间线"若日后需要再议。

### 6.3 人格面：人格引擎

- 稳定的性格、人设、语气与价值观表达（人设卡片、语气渲染、污染守卫）。
- "活"的关键：同一灵魂，而非每次都是新对话的陌生人。
- **现有内容盘点（2026-08-18）**：
  - **人设卡片 CharacterCard**（CCv2/V3 对齐）：性格支柱（3-5 条含矛盾）、声音四维（用词/句式/禁语/口癖）、示例对话、缺点脆弱面、话痨程度（0-100）、场景简报、背景/目标/价值观/行为准则/安全边界、first_mes/alt_greetings/tags、daily_schedule、age_progression、affinity_enabled/affinity_stages。
  - **人设渲染器 persona.py**：把人设卡片渲染为对 AI 的直接指令（不暴露计算逻辑）——即"人格模块"注入生产者。
  - **语气污染守卫 pollution_guard.py**：strip_roleplay_tone 剥离语气——**2026-08-18 评估：可砍**（防污染已由记忆面"只存事实 + 改人设清空"承接）。
  - **好感度规则**：关系档位规则（官方 6 阶 YAML / 自定义档）、双线结算、动态叠加（年龄/关系/叙事 overlay）。
  - **格式规范 format_spec**：角色卡自带对话格式（如 `[动作]（神态）<内心独白>` + 尾部好感度 JSON）——**织语面"向人格引擎要要素类型"与 LLM 回复拆分格式均由此出**。
  - **梦瑶角色**：从 Skill 文件导入（import_skill + ensure_builtins）。
  - **安全边界（2026-08-18 更新）**：角色卡 safety_bounds **已删**；系统级安全**不单独成面**（维持现状实现）。
- **人设卡片字段清单（2026-08-18 重构）**：
  - **对 LLM 可见**：name；personality_pillars（性格：单条 ≤6 字、最多 6 条）；flaws（缺点：同性格限制）；tone（语气，由 voice 四维改）；example_dialogue（示例对话）；background（背景，scene 与故事合并，纯背景）。
  - **必填**：id / name / tagline、personality_pillars、flaws。
  - **修改**：talkativeness 改三档（话少 / 适中 / 话痨）；daily_schedule / age_progression 合并为开关 dynamic_updates_enabled（是否开启动态时间传参）。
  - **删除**：scene 四要素（地点 / 时间 / 刚发生的事 / 此刻想要什么）；**safety_bounds（安全边界，2026-08-18 删）**。
  - **新增**：age（年龄）、birthday（生日）；schedule（日程表格：时间段 ↔ 内容）。
  - **静态档案（照常注入）**：tone、example_dialogue、background、talkativeness、age、birthday、职业·学业、居住地、感情状态、兴趣——生日 / 职业 / 居住地 / 感情状态 / 兴趣均属静态，**不进动态域**。
  - **动态传参（2026-08-18 定）**：真正动态的只有**时间相关**——①**当前时间每轮注入**；②**日程按当前时间段切片**（只发当前时间段的条目）。由 dynamic_updates_enabled 开关控制。
  - **保留**：affinity_enabled / affinity_stages、format_spec、first_mes / alternate_greetings、tags / creator_notes。

### 6.4 情感面：好感度 / 情绪引擎

- 关系动态（基础好感、动态波动、羁绊），情绪随互动累积变化。
- 让对话有温度、有关系成长，而非冷冰冰的一问一答。
- **演进决策（2026-08-18）**：
  - **关系档位动态获取**：档位规则不写死、不内置——**动态向人格引擎索取规则文件**（标记：找人格要文件）。
  - **面级停用机制**：人格引擎未开启好感度（affinity_enabled=False）时，**整个情感面禁用**（不注入、不结算）。
  - **档位注入、数值不注入**：关系档位对应内容（档名 / 称呼 / 语气）以"模块"注入 LLM；**好感度数值绝不注入**——AI 不自想关系，只按被告知的档位内容行事。
  - **情绪向量补全（方案）**：**共用推理内核模型**做情绪识别，结果转情绪向量（无工具调用）。
  - **本地结算器**：LLM 只输出好感度增量（delta），**结算在本地**（base / dynamics / bond 计算由情感面本地完成，不交给 LLM）。
- **现有能力盘点（2026-08-18）**：
  - 好感度引擎（成熟）：双线机制（base 信任 -50~100 慢变 + dynamics 当下心情 -50~50 快变、幂律回归）+ 羁绊值 bond（无上限、承接 base 溢出）+ 官方 6 阶档位 + YAML 规则解耦 + 角色卡自定义档位 + 模型回复末尾 JSON 结算（兼容中文键）+ 态度注入（称呼/语气/心情方向，零数值暴露）+ 越界冷却 + 久别幂律冷却 + 记忆复苏（旧日暖意/微涩心境）。
  - 情绪向量（**空壳，待补全**）：`_core/emotion.py` 为桩——detect 返回中性（valence/arousal/dominance 全 0），真实情绪识别未实现。
  - 织语面内部另有情感分类（定语气用，词典离线占位），不属本面。

### 6.5 织语面（原"缝合面"）：对话缝合引擎

- 把检索到的记忆、人格指令、情感状态与模型生成无缝融合（语义检索 + 人格回调缝合）。
- 高拟真对话的"组装车间"：让 AI 说的每句话都带着记忆与人格。
- **现有引擎功能盘点（2026-08-18）**：
  - 双检索后端：默认 mock（BM25 + 字 n-gram 混合稀疏检索，零依赖零联网）；bge-small-zh ONNX 稠密语义检索（权重就位自动升级、缺失静默回退 mock）。
  - 四要素解析：`[动作]（神态）<内心> 正文`，与角色卡格式约定对齐。
  - 流水线：情感分类定语气 → 检索召回 → 桥接缝合（top2 承接句）→ 人格四要素调味 → 多样性改写（19 组口语同义词库）→ 短上下文回调（话题承接句）。
  - 诚实兜底：无自信匹配时明说答不了并建议问 LLM，绝不装听不清。
  - 输出可观测：emotion / tone_manner / matches / rewrite_variants / mode / recall_real / recognized / suggest_llm。
- **参数集现状（2026-08-18 核查）**：**全部写死，无外部配置**——BM25 系数（k1=1.5 / b=0.75）、混合权重（0.7 BM25 + 0.3 字 n-gram）、召回判定（top1 < max(top2×1.05, 0.02) 判未命中；recall_real ≥ 0.02）、调味概率（神态 0.6 / 改写 0.5 / 内心 0.3 / 动作 0.4）、改写与回调概率（0.4 / 0.5）、语料与向量路径、兜底话术。仅语料文件（mengyao_hq_part*.jsonl）可替换。
- **演进决策（2026-08-18）**：
  - **通用要素解析**：四要素解析改为通用要素解析——不再写死 `[动作]（神态）<内心> 正文`，根据**人格引擎传入的要素类型**动态匹配解析。
  - **语料策略**：自带**默认语料**；支持**用户对话语料替换**——从用户历史对话 / 回答获取语料，替换后**触发初始化路径**重建检索索引 / 向量。
  - **初始化路径**：语料加载 → 建立检索索引 / 向量（替换语料后必须重走此路径）。

### 6.6 / 6.7 已移出：语音与行动

- 语音（表达）与行动（工具 / React 等）**归入扩展插槽**，不属于心智核心。

### 6.8 安全闸门

- **联网能力由安全组件统一持有**（唯一出口），心智核心不自持联网。
- 心智核心的模型调用**放开网络限制**：安全闸门对模型层请求全放行（不拦截、不设白名单）。

### 6.9 动态 prompt 注入中间件

- **定位**：请求模型前的组合中间件。心智核心各面（组件）产出独立的注入"模块"，中间件统一组合后交给模型层。
- **组合规则（用户定）**：
  - **固定内容在上、动态内容在下**——最大化 KV cache 复用（固定前缀命中缓存）。
  - **信息可见性控制**：靠动态组合让 LLM"知道哪些、不知道哪些"——不可用即不注入（如工具调用不可用，就不传入工具列表）。
  - **模块化组合**：各组件发送需要注入的独立"模块"，中间件只负责组合。
- **采纳项**：
  - "不可用即不注入"推广到所有模块：记忆检索失败、情感模块异常等一律不注入失败痕迹，AI 不自知缺失。
  - 注入清单留痕：每轮记录"注入了什么 / 各占多少 Token / 裁掉了什么"，供排查"AI 为什么不知道 X"——**标记为开发者功能**（不面向普通用户）。
- **归位**：模块元数据（优先级 / 固定性 / Token 预算）、动态区总量裁剪、冲突裁决——**交由对应组件自理**，中间件保持只组合。

### 6.10 模型参数对外信息

- **对外信息发送**：把用户当前所选模型的参数对外提供——上下文长度、是否支持多模态、是否支持文件上传等。
- 用途：前端展示当前模型能力；其他组件（扩展等）据此决定行为（如是否直传文件、上下文上限）。

### 6.11 LLM 回复拆分中间件

- **定位**：LLM 回复的拆包器——把回复拆成"用户可见正文"与"组件数据"两部分。
- **方案（用户定，2026-08-18）**：对外开**统一传输接口**，所有需要对外传输的内容**打包一起发**；外面加**解释器**拆分。
- **双向 + 字段正文形式（2026-08-18 定）**：传输通道为双向——出向（`send_message` 返回）与入向（`receive` 接收）同构，均为**字段 + 正文**：`字段` 为结构化数据区（供解释器拆分 / 注入），`正文` 为显示或内容文本。输入输出文本统一此形式。
- **补充建议**：
  - **数据区统一格式**：所有组件数据打包进**一个**结构化块（尾部），不散落多块；现有"回复末尾 JSON 结算好感度"机制升级为通用数据区。
  - **组件注册字段**：各组件声明自己要的字段 → 解释器按注册表分发，不写死字段名（最小接口）。
  - **进出对称**：进 LLM 靠"模块注入"，出 LLM 靠"字段分发"——同一管道两个方向。
  - **流式兼容**：正文边流边显，数据区尾部攒齐后一次性分发。
  - **fail-closed**：解析失败 → 数据区整体丢弃、正文照常；用户界面绝不见数据区；AI 不自知数据区存在。
- **[标记] 待接线**：情感面本地结算器订阅"好感度 delta"字段；情绪识别结果走"情绪向量"字段；织语面通用要素解析与数据区格式对齐；前端只收正文（解释器剥离数据区）。
- **拆分策略（2026-08-18 定）**：先拆**魔方内**字段——目前仅**好感度 delta**（丢给情感面本地结算器）；其余**未匹配字段统一打包往外发**（给扩展 / 外部）。情绪识别 / 记忆写入 / 织语面要素均为本地或输入侧处理，不消费回复数据区。
- **分发语义（2026-08-18 定）**：分两种——**拆出来**（消费型：字段从数据区移除、不放回，如好感度 delta）；**读取**（只读型：数据区保留、继续外发）。

### 6.12 律动面（动态面 · 人格引擎动态扩展）

- **定位**（2026-08-18）：删除原"锚面（安全面 · 防 OOC）"；改为**律动面**——人格引擎的**动态方面扩展**，专为人格引擎服务（名字暂用"律动面"，备选：时光面 / 流转面）。
- **功能（建议，待取舍）**：
  - **时间感知**：当前时间 / 日期 / 星期 / 季节，每轮注入（动态传参）。
  - **日程切片**：从日程表格按当前时间段取条目注入。
  - **人物动态**：生日触发年龄增长；节日 / 纪念日感知。
  - **状态叠加**：当下状态（心情 / 精力 / 忙碌）运行时叠加（承接现有 dynamics_engine overlay）。
  - **叙事动态**：关系 / 剧情线动态叠加层。
- **边界**：好感度"档位内容注入"（称呼 / 语气）仍在情感面；律动面管时间 / 日程 / 状态 / 叙事的运行时动态。
- **原锚面内容随面删除**：防 OOC / 越界追踪 / 禁止话题 / 安全等级不再单独成面（系统级安全维持现状实现，不新设面）。

### 6.13 储存面（魔方新增面）

- **定位**：魔方的统一存储面（2026-08-18 新增）。
- **承载**：
  - **记忆层内容**：如本地向量库等记忆持久化。
  - **完整对话记录**：全量对话落盘；**可连织语面**——织语面"用户对话语料替换"由此获取历史对话 / 回答。
  - **其他魔方要存的东西**：通用存储。
- **对外开放（[标记] 2026-08-18）**：
  - **信息共享**：直接**注入传输接口**（LLM 回复拆分中间件的传输接口）一起发。
  - **控制接口**：只传**五位数字控制码**（按位次梯度分类，见 §7.14），内外部各加**解析器**翻译——**对外契约保留控制码解析方案**（2026-08-18 定）。
- **加密（2026-08-18 定，[落地] demo 级）**：储存面存储**必须加密**。demo 以零依赖流密码（标准库派生密钥）实现落盘加密；真实接入换 **crypto 芯片插槽（SM4 国密、密钥绑硬件指纹）**，经其插槽 ABC。
- **向量归档（[落地]）**：记忆写入时同步落「向量归档」（demo 以加密 jsonl 承载，真实接 ChromaDB）；防污染链路的「清空向量归档」即清此处。
- **现有实现评估（2026-08-18，仅魔方内）**：**功能够用，契约已备**——通用文件池（分类/配额/压缩/可选加密/事务，pool.py）、完整对话记录（conversation_store）、记忆层自带持久化（核心记忆 json / 归档 / 向量库 ChromaDB）；**PersistPort ABC 已存在**（save_session / save_memory / load_*），可作契约起点。
- **建议**：
  - 储存面 = **契约（PersistPort 扩展）+ 委托现有实现**（pool / conversation_store / 记忆持久化），不重写、不迁移数据。
  - 记忆持久化（向量库 / 归档 / 核心记忆）的落盘路径与生命周期**统一归储存面管理**。
  - 完整对话记录**收归储存面**（含按 conv_id 删除——衔接"改人设清空记录"防污染规则）。
  - 织语面语料替换从储存面对话记录取。
  - 压缩 / 加密 / 配额复用 storage pool 底座，不造轮子。

## 7. 内部设计（逐项）

### 7.1 对话流程编排

- **一轮对话时序**：
  1. 接收用户消息。
  2. 输入侧：情感面情绪识别（共用模型）→ 情绪向量。
  3. 各面取数（**并行、非流式**，内部先计算完整）：记忆面（核心记忆固定 + 短期/归档动态）；人格面（人格卡静态固定 + 动态角色扮演注入动态）；情感面（档位称呼/语气动态）；织语面（语料风格模块动态）；律动面（当前时间 + 日程切片动态）。
  4. 组装：动态 prompt 注入中间件——固定在上、动态在下，组合成一条 prompt。
  5. 生成：模型层多供应商生成，**面向用户渲染使用流式**（正文边生成边显示）；内部处理为非流式（先备好再生成）。
  6. 流式完成后**统一处理**：数据区（尾部统一块）攒齐 → 拆分分发。
  7. 拆分分发：好感度 delta → 情感面本地结算（拆出来）；其余未匹配字段 → 统一打包外发；正文 → 前端。
  8. 写入：记忆面归档 + 向量化；情感面结算落盘；储存面对话记录落盘（加密）。
  9. 状态更新（律动时间、情感档位）→ 进入下一轮。
- **cpu 核心（编排引擎，2026-08-18 重构）**：原"会话编排器"重构为 **cpu 核心**——心智核心真正的核心，类比主板的 CPU。采用**封装**概念：**推理内核（模型层）之下封装一个更核心的 cpu**，由 cpu 驱动全流程——接收消息、驱动各面取数、调两个中间件、调模型层、驱动写入。cpu 是唯一"知道流程"的地方。
- **输出打断逻辑（[标记] 待完善，2026-08-18 澄清）**：输出被中断（用户取消 / 异常 / 错误）时——**直接忘掉，啥都不给**：不抛错、不补残句、不暴露失败痕迹；**内部回归初始状态、本轮直接不计**（不写记忆、不结算好感度、不落对话记录、不更新律动/情感状态），界面维持中断前状态。
- **决策**：各面取数并行（模块间无依赖）；动态角色扮演注入由律动面 + 情感面内部先联合；固定 = 人格卡静态部分，其余全动态；任一模块不可用 → 不可用即不注入；模型层失败不暴露失败痕迹；**流式仅用于面向用户的渲染，内部一律非流式，流式结束后再统一后处理**。

### 7.2 组件 ↔ 模型层独立调用通道

- **需求**：部分面需对 LLM 做**输入侧 / 旁路调用**（非注入、非面向用户），如情感面情绪识别（共用推理内核模型识别用户消息 → 情绪向量）。方向区别于主通道：主通道是"组件**影响** LLM"（注入）；独立通道是"组件**以 LLM 为工具取**分析结果"——两者不冲突（§5.1 仅约束前者）。
- **模型层双通道设计**：推理内核暴露两类能力——
  1. **主生成通道**：cpu 组装 prompt 注入 → 流式生成 → 面向用户（§7.1 步骤 4–6）。
  2. **独立调用通道**：旁路分析，非流式，结果不面向用户、不入对话历史、不参与 KV 缓存前缀。
- **内部直接调用（守 §3 修正）**：心智核心内的面与模型层同属一个插槽，**无需 ABC**，面可经 cpu 路由或直接调用模型层的 `analyze` 能力；abc 仅出现在心智核心**对外**插槽边界（§7.13）。
- **调用时机**：在 §7.1 步骤 2（输入侧情绪识别）走独立通道——对用户消息做分析，非流式，产出（情绪向量）作为局部数据供后续模块组装。
- **不污染主链路**：独立通道的调用 prompt 为内部专用，不面向用户、不进对话历史。
- **fail-closed**：独立通道失败 → 该结果"不可用即不注入"（如情绪识别失败则不注入情绪，AI 不自知缺失）。
- **网络一致性**：独立通道同属模型层放开网络、仅内销给 LLM 用（§6.1 一致）。
- **[标记] 待细化**：哪些面需要 `analyze`（情感面已定；记忆面重排 / 织语面是否需待定）。

### 7.3 动态角色扮演注入的组装责任

- **静态 vs 动态**：人格卡（CharacterCard）= **静态模块**（固定，在 prompt 上方，可缓存）；动态角色扮演注入 = 每轮运行时**动态模块**（在下方）。
- **组装责任**：cpu 在 §7.1 步骤 3–4 负责合并——
  - 律动面产出动态片段：当前时间 / 日程切片 / 人物状态（忙碌·精力等）。
  - 情感面产出动态片段：关系档位内容（称呼 / 语气 / 档名）+ 关系状态。
  - 两者**无互相依赖**（都只依赖用户消息 + 各自状态），由 cpu 在组装阶段合并为一个**"动态角色扮演模块"**注入（单一来源、单一顺序，避免多模块打架）。
- **不注入数值**：好感度数值绝不进模块（§6.4），只进档位内容。

### 7.4 记忆写入触发路径

- **触发**：每轮**成功完成**（非打断，见 §7.1 输出打断逻辑）后，在步骤 8 执行。
- **写入内容**：
  - 核心记忆更新：仅当用户透露画像信息、经**写入决策**评分 ≥3 才入档（身份 / 亲属 / 偏好 / 事实）。
  - 归档记忆：重要度 + 幂律衰减 + prune 清理。
  - 向量化：ChromaDB 语义索引（供后续检索召回）。
  - 短期记忆：50 轮滑动窗口推进。
- **防污染（守 §6.2）**：归档前按"只存事实"策略过滤——不存语气 / 角色表达（语气污染守卫已砍，由"只存事实"承接）。
- **失败处理**：记忆写入失败不影响本轮已生成的输出，仅记录 + 下轮重试，不暴露给用户。

### 7.5 织语面形态转换（独立回复引擎 → 语料风格模块生产者）

- **形态变更**：织语面不再生成完整回复；改为**检索相关语料 → 产出"语料风格模块"**（风格示例 / 语气参考 / 承接句），作为动态模块注入 prompt，由 LLM 以角色语气说话。
- **检索后端保留**：BM25 + 字 n-gram 混合（默认 mock，零联网）/ bge-small-zh ONNX 稠密（缺失静默回退）。
- **通用要素解析（守 §6.5）**：依人格面 `format_spec` 的要素类型动态匹配，不再写死四要素。
- **诚实兜底处置（[决策点] 默认）**：原"无匹配明说答不了"的兜底职责**移交 LLM 自身判断**（织语面只提供风格，不决定能否回答）；检索无自信匹配时，风格模块**降级为弱风格提示**，而非兜底话术。如要保留独立兜底话术请告知。
- **语料**：自带默认语料 + 用户对话语料替换（§6.5 / §6.12 衔接：语料从储存面对话记录取）。

### 7.6 情绪识别输入口径

- **识别对象**：仅**用户消息**进入时识别（AI 回复不识别，避免循环）。
- **通道**：情感面经独立调用通道（§7.2）调用模型，产出情绪向量（valence / arousal / dominance 三轴）。
- **去向**：① 供情感面态度 / 心境计算；② 随用户消息**归档**（记忆面情绪五因子，E_enc 仅 v≥0）；③ 识别失败 → 不注入情绪（fail-closed）。
- **非流式**：输入侧分析在生成前完成（守 §7.1 内部非流式）。

### 7.7 律动面时间源与日程切片规则

- **时间源**：本机系统本地时间（时区取设置项）；每轮注入当前日期 / 星期 / 时段（早 / 中 / 晚 / 夜）。
- **日程切片**：`schedule` 为时间段 ↔ 内容表格；仅取**当前时段**匹配条目注入，非当前时段不注入（由 `dynamic_updates_enabled` 开关控制）。
- **时间相关动态**：生日触发（年龄 +1 / 纪念日感知）→ 律动面在对应日期注入特殊状态。
- **失败**：时间源异常 → 不注入时间 / 日程（fail-closed），不影响其余面。

### 7.8 储存面契约（内部委托 + 跨插槽 ABC + 对外）

- **内部（心智核心内，无 ABC）**：储存面直接委托现有实现管理落盘路径与生命周期——storage pool（通用存储 / 压缩 / 配额）、conversation_store（全量对话按 conv_id 落盘 + 删除）、记忆持久化（核心记忆 json / 归档 / ChromaDB 向量库）。
- **跨插槽依赖（守 §3，走插槽 ABC）**：
  - 实际落盘委托 **storage 芯片插槽**（存储芯片）——经其插槽 ABC。
  - 加密委托 **crypto 芯片插槽**（本机加解密，SM4 国密、密钥绑硬件指纹）——经其插槽 ABC（落盘**必须加密**，§6.12 已定）。
- **对外（§6.12）**：信息共享 → 注入传输接口（§6.11）一起发；控制接口 → 只传控制码，内外各加解析器。

### 7.9 面间内部约定（原"面间 ABC 契约"，按 §3 修订为内部约定，无 ABC）

- **人格 ↔ 情感**：人格面提供 `get_stage_rules()`（关系档位规则文件，动态获取，§6.4）+ `affinity_enabled` 开关；情感面依此决定档位内容注入与整面是否启用。
- **人格 ↔ 织语**：人格面提供 `get_element_types()`（源自 `format_spec` 的要素类型，§6.5 通用要素解析依此动态匹配）；织语面据此解析 / 生成要素。
- **人格 ↔ 律动**：人格卡提供 `schedule` / `dynamic_updates_enabled` / `age` / `birthday` 等字段；律动面读取做时间 / 日程 / 年龄动态。
- 以上均为**同插槽内部直接调用**（无 ABC）。

### 7.10 注入模块结构 与 字段注册表

- **注入模块结构（数据）**：
  ```
  InjectionModule {
    source: str        # 产出面标识（记忆 / 人格 / 情感 / 织语 / 律动）
    content: str       # 注入正文
    fixed: bool        # 是否固定（属 KV 缓存前缀，在上）
    priority: int      # 排序优先级（固定模块间 / 动态模块间）
    token_budget: int  # 该模块允许占用的 Token（动态模块受预算约束）
    available: bool    # 是否可用（不可用则不注入，fail-closed）
  }
  ```
- **字段注册表（数据区字段 → 消费方，§6.11）**：
  ```
  FieldRegistry {
    "affinity_delta": 消费方=情感面, 语义=拆出来（消费型，从数据区移除不放回）
    # 其余未注册字段 → 统一外发
  }
  ```
  各组件注册自己要的字段；解释器按注册表分发。

- **对外**：经心智核心插槽 ABC / 传输接口提供给前端展示与扩展插槽决策（§6.10）。

### 7.12 防污染删除触发链路

- **触发**：人格面检测到人设修改（CharacterCard 关键字段变更）。
- **链路**：人格面 → 通知储存面（同插槽内部直接调用）→ 清空该 conv 的**全部聊天记录 + 向量归档**。
- **时机**：人设修改提交时**立即同步**执行，避免污染窗口。
- **范围（[决策点] 默认按字面）**：仅聊天记录 + 向量归档；**不含核心记忆（用户画像静态）**。若要连核心记忆一并清空请告知。
- **[落地状态]**：demo 中由 `MentalCore.update_persona(**fields)` 触发——改人设字段后即时 `clear_records()` + `clear_vectors()`，并重置内存 history；`/persona <k=v>` 命令可演示。

### 7.13 心智核心对外插槽 ABC（心智核心插槽接口）

- 心智核心作为主板唯一插槽，向主板 / 其他插槽 / 前端暴露**插槽级 ABC**（内部 cpu / 面 / 模型层对外不可见）：
  ```
  MentalCoreSlotPort {
    send_message(fields, body) -> 流[正文] + 传输包（字段+正文，§6.11）  # 对话主入口（输入亦为字段+正文）
    receive(fields, body)                                                # 向内传输接口（§6.11 双向）：外部注入字段+正文
    control(code)                                                        # 控制接口，只传五位控制码（§6.12 / §7.14）
    get_model_info() -> ModelInfo                                        # 模型参数对外信息（§6.10 / §7.11）
    # 前端：砖块内前端随载（§2），经此插槽对外呈现
  }
  ```
- **双向传输（2026-08-18 定）**：传输通道（§6.11）为双向——**出向** = `send_message` 返回的传输包；**入向** = `receive` 接收的传输包；两者同构，均为**字段 + 正文**形式（`字段` = 结构化数据区，`正文` = 显示 / 内容文本）。
- 这是心智核心与主板其余部分（扩展 / USB 插槽、前端）交互的**唯一边界**。
- **[落地状态] demo 交付形态**：原 web 前端（server.py + frontend）已**拆除**，改为纯命令行 `mental_core_demo/cli.py`（交互式对话流式显示 + `/model` `/manifest` `/code` `/receive` `/persona` 命令）。前端随砖块加载的概念仍保留在 §2，待真实主板砖块前端接入时再挂。

### 7.14 控制码编码（五位 · 按位次梯度分类）

- **形式（2026-08-18 定）**：控制码为**五位十进制数字**（00000–99999）；**按位次梯度分类**——高位 = 粗分类，低位 = 细分类，逐位收窄。
- **位次梯度结构**：
  | 位 | 位权 | 梯度含义 | 示例取值 |
  |---|---|---|---|
  | 第1位（万位）D1 | 域大类（最粗） | 0=系统 / 1=储存 / 2=记忆 / 3=情感 / 4=人格 / 5=对话 / 9=保留 |
  | 第2位（千位）D2 | 子类（域下模块） | 各域自定义 |
  | 第3位（百位）D3 | 动作 | 0=查询 / 1=清除 / 2=导出 / 3=修改 / 4=启用停用 / 9=其他 |
  | 第4位（十位）D4 | 对象 | 具体对象编号 |
  | 第5位（个位）D5 | 参数 / 方向（最细） | 0=请求 / 1=成功响应 / 2=失败响应 / 其余=参数 |
- **示例**：`10100` = 储存域(1) · 对话记录子类(0) · 清除动作(1) · 对象=全部(0) · 请求(0) → 请求清除全部对话记录；`10000` = 查对话记录数。
- **[落地状态] 枚举与路由已补全**：
  - **D2 子类枚举**：`SUBCLASSES` 按域定义（如储存域 0=对话记录 / 1=向量归档 / 2=导出包 / 3=加密状态；记忆域 0=短期/1=长期/2=核心记忆画像；情感域 0=档位/1=关系/2=情绪；人格域 0=角色卡/1=动态/2=要素类型）。
  - **D4 对象枚举**：`OBJECTS`（0=全部 / 1=最近N / 2=指定编号）。
  - **外部意图 → 控制码**：`INTENT_ROUTES`（如「查对话记录数」→10000、「清向量归档」→11100），CLI 可直接填意图名。
  - **内部路由**：`StorageFace.handle_control` 按 D1/D2/D3 路由到具体动作（查/清/加密状态）。
