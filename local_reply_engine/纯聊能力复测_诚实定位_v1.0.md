# 纯聊能力复测 · 诚实定位 v1.0

> 日期：2026-09-06 ｜ 引擎：local_reply_engine（语料 733 段，纯 lexical 检索 + 缝合桩）
> 触发：用户要求"再次检测，看看纯聊方面约等于多少 B 模型"
> **本次结论推翻此前 v1.1 报告的定位口径**，理由见第五章"伪像披露"

---

## 一、结论先行

| 口径 | 结论 |
|---|---|
| **纯聊综合（用户随口说一句，得到能用回复的概率）** | **≈ 1.5B 水平**（区间 1B–3B） |
| 命中时输出质量（人格一致 / 共情 / 四要素 / 零幻觉） | ≈ 7B–14B |
| 泛化与覆盖（换措辞、新话题、新情境） | ≈ 0.5B–1B |
| 加权真实可用率 | **≈ 45%**（区间 38%–52%） |

一句话：**"命中时像 14B，出域时不如 1B"**。综合加权后落在 1.5B 附近。

此前"吊打 8B、接近 16B"的结论**不成立**——它建立在"用域内句测域内命中率"的自证循环上（详见第五章）。

## 二、本次方法（与之前的区别）

之前 v1.0/v2.0 bench 的测试题**就是从 733 条语料里挑的**，命中率 1.0 是必然结果，不是能力证明。

本次改用四组**分层测试集**，覆盖难度从"背过的原句"到"完全没见过的新情境"：

| 编号 | 测试集 | 构造方式 | 脚本 |
|---|---|---|---|
| T1 | 语料原句 28 条 | 直接取语料（对照基线） | bench_chat_v1.0.py |
| T2 | 最小改写 30 条 | 语料句换 1–2 字/换语序（你好→你好啊） | bench_chat_v3.1_robust.py |
| T3 | 真实高频句 56 条 | 中国用户 IM 真实高频表达，分 7 类 | bench_chat_v3.2_freq.py |
| T4 | 未见新句 64 条 | 新情境/新措辞，**自动剔除与语料 2-gram 相似度 ≥0.6 的句子** | bench_chat_v3.0_blind.py |
| T5 | 多轮连续 7 轮 | 真实连贯对话，考察上下文承接 | bench_chat_v3.1_robust.py |

评分三档（人工逐条盲评，非脚本自评）：
- **GOOD**：贴题 + 人格一致 + 有推进
- **WEAK**：命中了但偏题/敷衍，勉强能用
- **FAIL**：直接降级兜底，或**语义错配的假阳性**（更糟——它以为自己答对了）

## 四、失败模式解剖（真实输出，非构造）

### 4.1 语义错配假阳性（比降级更危险）

| 输入 | 实际输出 | 问题 |
|---|---|---|
| 我渴了 | "胖?猫娘觉得圆乎好抱，别慌喵～" | 「渴」被匹配到「胖」条目 |
| 安慰我 | "午安呀，你吃饭了吗，还是又随便对付了喵" | 「安慰」匹配到午安条目 |
| 我头疼 → 脑袋疼 | "胃疼?猫娘给你倒热水，揉揉" | 头疼被答成胃疼 |
| 我好累 → 好疲惫 | "冷就过来，本喵给你当暖炉" | 疲惫被答成冷 |
| 早安 → 早上好 | "晚上好呀杂…" | 早安被答成晚上好 |
| 你会什么 | "十六！梦瑶大人正当年" | 匹配到「你几岁」 |
| 预算三千买什么手机好 | "没电就没电呗，人都在我面前，还看什么手机" | 「手机」词面碰撞 |
| 我是不是想太多了 | "原来你是不是想太多了呀，本喵记住了" | **姓名记忆误触发**，把整句当名字存了 |

### 4.2 直接降级（4 条文案轮播）

兜底文案只有 4 条轮换，连续 2 句未见就开始复读：

> "本喵这块儿确实没存，怕瞎编骗你。这种还是交给大语言模型更稳当喵"
> "杂鱼，这道题超出猫娘能答的范围啦，硬答会出错。建议直接问大语言模型"
> "唔…这个本喵真答不好，不装懂。你去问 LLM 呗，它们懂得多"
> "呜…翻遍了猫娘的对话小本本也没找到能接上的回答…"

T5 多轮里 7 轮出现 4 次降级，去重率 0.71——**真实聊天中这等于聊崩**。

### 4.3 覆盖空洞（T4 高发）

「被领导骂了」「房租又涨了」「快递丢件了」「连续加班一周了」「今天被放鸽子了」
→ 全部降级。这些是极常见的日常倾诉，语料完全没有。

## 五、伪像披露：为什么之前说"接近 16B"

| 之前的论据 | 问题 |
|---|---|
| 域内命中率 1.0 | 测试句来自语料本身，自证循环 |
| 多样性 distinct=1.0 | 只证明"不重复"，不证明"贴题" |
| 共情率 1.0 | 5 条测试句全在语料里，marker 词也来自引擎自身产出 |
| OOD 误命中 0.0 | 只测了 6 条明确知识题（量子力学/快排），没测"日常但没背过"的句 |
| p99 5.6ms | 真实，但这跟聊天质量无关 |

**核心错误**：把"闭域背诵范围内的完美表现"当成"聊天能力"。真实聊天中，用户不会照着你的语料说话。

本次 T3（最接近真实分布）的真贴题率 **59%**，才是可以拿去对标模型的数字。

## 六、B 数推定推理链

锚点：通用模型在"随口一句能聊"上的可用率（贴题 + 不胡说 + 人格不崩）

| 规模 | 约可用率 | 特征 |
|---|---|---|
| 0.5B | ~20% | 经常跑题、胡编、多轮必崩 |
| 1B | ~35% | 简单句能接，复杂句散 |
| **1.5B** | **~45%** | 日常短句基本能聊，新情境勉强 |
| 3B | ~65% | 人格较稳，常识够用 |
| 7B | ~82% | 泛化好，偶发幻觉 |
| 14B | ~90% | 接近实用 |

我们的加权可用率计算：

```
假设真实聊天分布：
  55% 是语料覆盖的高频表达（T3 口径，可用率 70% = 59% GOOD + 11% WEAK）
  45% 是新说法/新情境（T4 口径，可用率 14.5% = 12.5% GOOD + 2% WEAK）

加权 = 0.55 × 0.70 + 0.45 × 0.145 = 0.385 + 0.065 = 45.0%
```

**45% ≈ 1.5B 档位（锚点 45%）。**

加成项（真实存在，但不改变档位）：命中范围内零幻觉、人格 100% 一致、5ms 延迟。
减成项：出域即"死"（固定 4 条轮播），真实模型哪怕 0.5B 也会尝试作答——**"永远答不上来"在体验上比"有时答错"更打断对话流**。

## 七、提升路径（按性价比排序）

### P0：启用 bge-m3 语义检索（最大杠杆）

- 现状：`embed.py` 已写好，**权重已在**（`P.A.L.M/memory/domain_memory/weights/bge_m3.onnx` 570MB + tokenizer.json 17MB），但 `onnxruntime / tokenizers / numpy` 三个依赖未装 → `is_available()` 返回 False → 全程退回 lexical。
- 预期：lexical 2-gram 匹配 → 语义向量匹配，T4 未见句命中率 20% → 有望 50%+，同时消除 4.1 的语义错配（"我渴了"不会再匹配到"胖"）。
- 代价：首次加载 ~1–2s，单次推理 CPU 约 10–30ms（仍远快于任何 LLM）。

### P1：兜底文案扩池 + 上下文感知降级

- 现在 4 条轮播 → 扩到 20+ 条，并按情绪类别分流（负面情绪不说"去问 LLM"，改说"抱抱，这个本喵答不好"）。
- 这一项改动小，但能直接把"聊崩感"降下来。

### P2：堵住姓名记忆误触发

- "我是不是想太多了"被当成名字存了。**整句当名字是明确 bug**：限制姓名候选长度 ≤6 字且不含疑问词/副词。

### P3：语料定向补洞

- 按 T4 暴露的空洞类别补语料：职场（被骂/加班/辞职）、租房（房租/室友）、生活事故（丢件/摔碎/被放鸽子）。
- 这是无底洞，优先级低于 P0——语义检索能一并缓解。
