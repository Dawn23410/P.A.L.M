## 六、语义检索没治好的问题（诚实清单）

| 问题 | 现状 | 性质 |
|---|---|---|
| `安慰我` → "午安呀，你吃饭了吗" | **未修复** | 语义分过阈但匹配错条目 |
| `帮帮我` → "你好呀，今天怎么有空" | **新出现的假阳性**（原先是降级） | 语义检索把低分也捞过阈了 |
| `然后呢` / `为什么` → "谢什么谢" | 未修复 | 虚词类短句无语义锚点 |
| `今天好热` / `今天好冷` → 天气播报 | 未修复 | 工具触发规则把"热/冷"当成天气查询 |
| `我是不是想太多了` → 被当名字存 | **未修复** | 姓名抽取 bug（P2），与检索无关 |
| `我刚才那句话是不是说错了` | 未修复 | 需上下文指代，检索解决不了 |
| `你说呢` | **退化**（原 GOOD → FAIL） | 语义把它拉到"你没听清？"条目 |
| 需常识判断题（房租/考研/相亲/合租） | 仍全降级 | 超出陪伴域，应交给 LLM |

**净变化**：修好 14 类，新引入 1 类假阳性（`帮帮我`），退化 1 类（`你说呢`）。净收益明确为正。

## 七、延迟实测（纠正 v1.0 未测、本次初测 437ms 的误判）

| 阶段 | 耗时 |
|---|---|
| 首次 `embed()` 调用（含 ONNX session 加载） | **1645 ms**（进程内一次性） |
| 单条 `embed()` 稳态 | **15.6 ms** |
| `respond()` 稳态（semantic） | **52 ms**（实测 49.8–59.3） |
| `respond()` 稳态（mock） | **5 ms** |
| 引擎启动（索引缓存命中） | 215 ms |

> 首轮测出 437ms 是把 1645ms 的 session 加载摊到 4 条样本上（1645/4≈411）。
> **稳态真实值是 52ms**，与 engine.py 文档注释的 ~57ms 一致。

52ms 对陪伴对话完全无感（人类感知阈值 ~200ms），且仍是任何本地 LLM 的 1/20 以下。

## 八、下一步建议（按优先级）

| 优先级 | 事项 | 收益 |
|---|---|---|
| **P0-a** | **默认开启 `semantic=True`** | 1.5B → 3.5B，成本仅 47ms，无理由不开 |
| P0-b | 进程启动时预热 `embed`（吃掉 1.6s 首次加载） | 消除首句 1.6s 卡顿 |
| P1 | 修 `帮帮我` 类假阳性：语义 top1 与 top2 分差 <0.03 时判不确定，改走降级 | 把新引入的假阳性堵回去 |
| P2 | 姓名抽取加约束（≤6 字、不含疑问词/副词） | 修 "我是不是想太多了" 被存成名字 |
| P3 | 兜底文案扩到 20+ 条并按情绪分流 | semantic 下仍有 16% 降级，降低聊崩感 |
| P4 | 语料补洞：职场/租房/生活事故/需常识判断类 | 剩下 24 条 FB 里约一半能救 |
