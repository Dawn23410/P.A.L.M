# 内存压缩可行性研究 · 三档方案 v1.0

> 日期：2026-09-07 ｜ 触发：用户要求"研究内存压缩到 512MB；不行则两档：50MB 纯 mock / 2GB 满血"
> 性质：**研究报告，未落码**。所有数字为本机实测（perf_profile_v1.0 / mem_tiers_v1.0 / 定向探针），非估算。

---

## 一、结论先行

| 问题 | 结论 |
|---|---|
| 全语义能压到 512MB 吗 | **不能**。bge-m3 权重 RSS 底线 570MB（int8 文件=570MB，ORT 不二次压缩），加运行时 ≈650MB。换小嵌入模型可到 ~300MB，但那是"换模型"不是"压缩"，质量需重标定 |
| 50MB 纯 mock 档 | **可行，实测 32MB**。但需先修一个 bug：当前 mock 模式也无条件预热 reranker，实际占 **1760MB** |
| 2GB 满血档 | **可行但需取舍**。当前全功能实测 2700MB；`_MAX_LEN=8192` 修复 + 去 T5 后 ~2460MB，仍超；再换小 reranker（279MB 文件）≈ **1.3GB** ✓，或 v2m3 惰性加载保留满血质量但接受 3.5s 首触发尖峰 |

---

## 二、内存账本（实测分解）

当前全功能 2700MB 的构成：

| 组件 | 文件大小 | RSS 实测 | 说明 |
|---|---|---|---|
| Python + 语料 + 索引 npy | 11.6MB | **~168MB** | 含 2707 记录、分词器 |
| reranker v2-m3 (int8) | 880MB | **~1704MB** | ORT arena 几乎翻倍，代码注释"880MB"严重低估 |
| bge-m3 embed (int8) | 570MB | **~830MB** | 首响应时惰性加载 |
| Randeng-T5 改写 | — | **0MB** | t5_rewrite.onnx 不存在，本来就走离线模板 |

**三个实测爆点：**

1. **mock 档被 reranker 拖累**：`engine.py` 的 `reranker.warmup()` 在 mock 分支也无条件执行 → 纯 mock 实测 1760MB。注释掉的预热后实测 **32MB（boot 0.03s，median 16ms）**。50MB 档白送。
2. **`_MAX_LEN=8192` 是内存/延迟双炸弹**：单条 8192 token 输入 → **+4.8GB RSS + 18.3s 停顿**（arena 永久保留不归还）。用户粘贴一段长文即可触发。实测曲线：64tok +572MB / 256tok +585MB / 1024tok +729MB / 8192tok +5384MB。聊天查询中位数 18 token，cap 到 256 零质量损失。
3. **reranker 的 arena 开销 = 文件大小 ×1.94**：换旧 reranker（`data/reranker/model_quantized.onnx`，279MB）预计 RSS ~550MB（待实测）。

## 三、三档方案设计

### 档位 A：lite（纯 mock）—— 目标 50MB ✓ 实测 32MB

- 改动：`reranker.warmup()` 移入 semantic 分支（约 3 行）。
- 质量：≈ v1.0 报告的 1.5B 档（lexical 口径）。命中时人格一致零幻觉，泛化差。
- 适用：低端机 / 常驻挂机 / 嵌入其他小项目。

### 档位 B：balanced —— 实测 998MB（可选中间档）

- 组成：bge-m3 语义 + MAX_LEN=256 + **reranker/T5 全关**。
- 质量损失（消融实测）：多轮 p90 213ms→18ms（coherence 关）；reranker 仲裁在常规负载 0 触发，损失很小；**语义主检索完整保留**。
- 适用：512MB-1GB 预算的主力档。注：如果硬要 <512MB，唯一路是换 bge-small-zh（int8 ~25MB 文件，总 RSS 估 ~300MB），需重建索引+重标定阈值+重跑盲测，质量未知——列为可选项，不推荐首发。

### 档位 C：full —— 目标 2GB，两条实现路线

| 路线 | 预计 RSS | 代价 |
|---|---|---|
| C1：v2m3 惰性加载（保留现有质量） | ~1.0GB 常驻 + 首次仲裁 **3.5s 尖峰** | 多轮首次连贯重排卡 3.5s，体验突刺 |
| **C2（推荐）：换旧 reranker（279MB）** | **~1.3GB 常驻，零尖峰** | 仲裁/连贯重排换成小模型，需重跑标定与盲测验证质量 |

两路线都需：warmup 移入对应分支 + `_MAX_LEN 8192→256`。

## 四、独立化（"独立引擎"前置条件）

当前 `models/weights/` 为空，bge_m3.onnx 靠回退路径从 `P.A.L.M/memory/domain_memory/weights/` 加载——**包不自包含**。独立化 = 复制 bge_m3.onnx (570MB) + tokenizer.json 进包（占磁盘不占额外 RAM），删除外部回退路径。reranker 权重已在包内 `data/`。

---

## 五、推荐落地顺序（待确认后执行）

1. **修 mock 泄热 bug**（warmup 移分支）——3 行，收益 1760MB→32MB，零风险
2. **`_MAX_LEN` 8192→256**——1 行，拆掉 5GB/18s 炸弹
3. **档位参数化**：`StitchEngine(tier="lite" | "balanced" | "full")`，按上表控制 warmup/重排/reranker 规格
4. **C2 路线**：旧 reranker 重标定 + T2-T5 盲测复测（质量验证后才定档）
5. **独立化**：权重收进包 + 删外部回退

> 风险披露：C2 换 reranker 后仲裁阈值（0.5/0.6 那套标定）失效，必须重标；balanced 档关 coherence 的多轮质量损失只有延迟数据、没有质量数据，若启用需补一轮 T5 盲测。
