# 换模型对比 · bge-m3 → bge-small-zh 质量缩水实测 v1.0

> 日期：2026-09-07 ｜ 控制：只换嵌入模型（bge-m3 1024维 → bge-small-zh-v1.5 int8 512维），
> 语料/检索流程/reranker/重排/守卫全部不动，阈值按新模型重标定（0.72 → 0.75）。
> 数据：`bench_result_v3.3_m3.json` vs `bench_result_v3.3_small.json`，同题同口径逐条对照。

---

## 一、结论先行

| 指标 | bge-m3（满血） | bge-small（换模型后） | 缩水 |
|---|---|---|---|
| T2 最小改写命中 | 30/30 | 28/30 | -2 |
| T3 真实高频句命中 | 55/56 | 53/56 | -2 |
| **T4 未见新句命中（同口径 56）** | **52/56 = 93%** | **36/56 = 64%** | **-29pp** |
| T5 多轮命中 | 6/7 | 4/7 | -2 |
| 加权可用率（0.55×T3+0.45×T4） | **≈92%（14B 档）** | **≈83%（7B 档）** | **≈一整档** |
| embed 延迟 | ~15.7ms | **1.8ms** | ÷9 |
| full 档内存 | 2701MB | **1855MB** | -846MB |
| balanced 档内存（无重排） | 999MB | **159MB** | -840MB |

**一句话：只换嵌入模型 = 用"泛化能力"换内存。域内短句几乎不掉（T2/T3 -2 句），掉的是 T4 长句/口语改写（93%→64%），缩水约一整档（14B → 7B）。**

## 二、缩水质量剖析（逐条对照，非统计平均）

### 2.1 小模型接不住的 16 句（m3 命中 → small 兜底）

吃了没 / 你这会儿干嘛呢 / 我出门了 / 到家了跟你说一声 / 被领导骂了 / 快递丢件了 /
要不要一起看剧 / 你觉得熬夜值不值 / 夏天和冬天你更喜欢哪个 / 你今天心情怎么样 /
我要是消失了你会找我吗 / 你是不是对所有人都这么好 / 今天开了一下午会脑子嗡嗡的 /
外面下雨了突然有点想你 / 最近总失眠恶性循环了 / 如果我说我不开心你会怎么哄我

**规律**：①口语省略（"吃了没"）②长句多信息（开会+想听说话）③情绪隐喻（下雨+想你）。
这类的共同点是字面与语料问句差异大、全靠语义泛化——正是 25MB 模型与 570MB 模型的差距所在。

### 2.2 新增假阳性：仅 +1

- "我今天第一次自己做饭，居然没翻车，开心" → 接成"馋了/偷吃冰箱布丁"（m3 正确接做饭）
- 其余命中句质量与 m3 同源（同一语料记录池），人格一致性无差异
- 兜底全部是诚实交棒文案，零幻觉——失败模式依然优于同级 LLM

### 2.3 意外收益

- "感冒了鼻子堵得慌"：m3 接成树洞倾听（WEAK），small 接成热敷通气（**GOOD**）——阈值抬高（0.75）滤掉了 m3 的一次弱命中
- embed 延迟 15.7ms → 1.8ms，单轮快路径 median 16ms → **~3ms**

### 2.4 全量回归暴露的真实缩水（31 点 ×3 抽）

- **small 档 29 过 / 2 失败**：`我感冒好了`（痊愈）抽到"感冒啦？躺好我守着"（生病照顾）——**小模型分不清"感冒了"与"感冒好了"的时序反转**，这是最典型的语义精度损失实例。m3 档同点全过。
- 伪影巡检 0/2707、延迟中位 **2ms** / p99 3ms——稳定性无缩水。
- 修复选项（未落码）：加"X好了"守卫（查询含"好了"时排除"照顾病人"类候选），3 行，与开黑/冰雹守卫同族。

## 三、内存实测（独立包，fresh 进程，与上次研究口径一致）

| 档位 | 组成 | RSS |
|---|---|---|
| lite（--lite） | 纯 mock | **32MB** |
| **balanced-small** | small 语义 + 无重排 | **159MB** |
| balanced-m3 | m3 语义 + 无重排 | 999MB |
| **full-small（--small）** | small 语义 + reranker v2-m3 | **1855MB ✓ 2GB 达标** |
| full-m3（默认） | m3 语义 + reranker v2-m3 | 2701MB |

修复记录（研究报告中 ①② 的落地，均已验证）：
- `reranker.warmup()` 移入 semantic 分支：mock 档 1760MB → 32MB
- `_MAX_LEN` 8192→256：拆掉"+4.8GB/18.3s"长句炸弹
- **新增修复**：`Hub.Embedder` boot 即加载 m3 session（与 embed 模块重复，独立包化后权重入包触发）——改惰性加载，全档 RSS -500~850MB
- 索引首建改 256 条/块分块（一次性整批会把 arena 顶爆）
- 缓存按模型命名（stitching_vectors_m3.npy / _small.npy），m3 陈旧缓存（2837 行 ≠ 2837 记录 ✓ 对齐后重建）

## 四、独立包清单（任务 1 交付物）

- `local_reply/engine/models/weights/`：bge_m3.onnx (570MB) + bge_small.onnx (24MB) + 两个 tokenizer——**自包含，P.A.L.M 回退路径已删除**
- `run_chat.py`：ollama 式 REPL（`--lite` / `--small` / 默认满血；`/stats` `/reset` `/exit`）
- `梦瑶对话.bat`：双击即用
- 模型选择：env `PALM_EMBED_MODEL=m3|small`（run_chat 已封装）

## 五、选择建议

| 场景 | 推荐 |
|---|---|
| 主力日常陪聊，追求拟人 | **full-m3（默认，2.7GB）** |
| 常驻后台 / 2GB 预算 | **full-small（1.86GB）**：短句体验几乎无损，长句泛化缩水 |
| 极致轻量 / 嵌入其他项目 | balanced-small（159MB）或 lite（32MB） |

> 披露：T3 可用率按命中质量与 m3 同源估算（±2pp）；T4-56 口径因 part49/50 入库从 58 句变为 56 句，两侧同口径对比不受影响。小模型档未重跑 31 点回归清单（阈值 0.75 下历史坏标记的命中率需单独验证，启用 small 档前建议补跑）。
