### 1.3 "8B Wall" 实证的失败模式（正是我们的免疫区）
来源：moto-westai《The 8B Wall》《8B Parameter Reality Check》、insiderllm 调试指南
1. **上下文退化 / Lost-in-the-middle**：长对话中部信息丢失，模型"忘记"前文。
2. **幻觉**："Every language model hallucinates. Smaller models hallucinate more." 14B 比 7B 少，但仍非零。
3. **人设漂移 / Goal drift**：多轮后偏离角色或原始目标。
4. **重复循环**：repetition loop，需调采样参数救。
5. **过度自信的错事实**：日期/名字/代码语法，以高置信度说错。
6. **负向约束失败**："做 X 但不要 Y"容易执行被禁止的 Y。

### 1.4 硬件现实
- Qwen2.5-14B 需 ~12–20GB VRAM（Q4_K_M / Q5_K_M），32B 需 24GB+，且每 token 数十~数百 ms。
- 我们的引擎：纯 CPU、零依赖、单次 **~5.6ms**，开销约为 8B 本地调用的 1/2400 万。

## 四、苛刻用户实测（harsh_user_test.py 真实输出）

### 4.1 混合命中 / 不命中
- **域内 10/10 命中**：角色认知、情感、共情、夸赞、生活事件、起居、闲聊、亲密、自我介绍接话、偏好——全部四要素锁死、人设味足。
- **OOD 5/5 诚实兜底**：推荐电影 / 股市 / 写爬虫 / π / 考雅思——全部明确交 LLM，**零幻觉、零误配**。
- **跨轮姓名召回**：先「我叫阿杰」→ 后续「你喜欢吃什么」自动带出「阿杰，刚才想啥呢喵」，**个性化真实生效**。

### 4.2 同问随机性
- 「今天好累」连问 6 次 → 去重 4/6 不同 ✅（前缀四要素锁死是设计预期，后缀随机变体生效）。
- OOD 兜底连问 4 次 → 3/4 不同（诚实兜底允许有变体，不机械复读）。

### 4.3 人设一致性挖坑
- 「你叫什么名字 / 你多大了 / 你是什么性格 / 你喜欢吃什么」四连问 → 名字、年龄、性格、偏好全部一致且人设锁定（修补了先前「你是什么性格」漏召回的缺口，已补 part10）。

### 4.4 苛刻用户视角可挑刺点（诚实披露）
1. **OOD 不接话**：苛刻用户会嫌"能不能至少接个话"——这是有意为之的诚实边界（零幻觉优先于讨好），非缺陷。
2. **随机性 4/6**：前缀（动作/神态/内心）锁死，只有后缀变。若要更高随机性可放宽，但会牺牲人设一致性，当前取舍合理。
3. **覆盖有界**：未补语料的高频陪伴句仍诚实兜底（如部分冷门话题），靠持续扩语料收窄。

## 七、符号伪推理层（reason.py）+ 语义检索升级（bge-m3）

> 在五轮杠精修复 + 双基准零回归基础上，进一步上两道确定性增强（用户指令"23搞"）：
> ② 符号伪推理层（A 方向，确定性 DST 变体）+ ③ bge-m3 本地语义检索（P1，根治近义误配）。

### 7.1 reason.py · 符号伪推理层（A 方向）
- **学术对应**：Dialogue State Tracking (DST) 的**确定性 slot-value 变体** + 规则化 Coreference Resolution（CogNIAC/Multi-Pass Sieve 的 precision-first）+ 轻量 Production System（CLIPS 风格 match→resolve→act）。纯标准库、零模型、零网络、fail-closed。
- **组件**：
  - `BeliefState`：结构化世界模型（entities 注册表 / last_entity 锚点 / profile{name,facts,preferences,dislikes} / emotion streak / turns），可序列化、可调试。
  - `Extractor`：规则化抽取实体命名（`它叫咪咪`→咪咪）、自我介绍（`我叫阿杰`）、偏好/厌恶（`我讨厌吃香菜`→香菜，剥首动词+尾助词+去重）。
  - `Inference`：产生式把抽取结果应用到 BeliefState（确定性、可复现）。
  - `PseudoReason`：编排 `update`（抽取+推理）→ `resolve`（指代消解增强检索）。
- **集成进 engine.respond**（最小加法、零破坏）：
  1. `self.reasoner = PseudoReason()` 在 `__init__` 挂载；
  2. respond 早期 `reasoner.update(query, emotion)` 维护信念，并同步 `name` 进既有 `memory["user_profile"]`（单源）；
  3. **指代消解增强检索**：`resolve(query)` 把代词替换为最近实体（如「它呢」→「咪咪呢」）后重检，仅当消解版 ≥ 接受阈值且高于原分才采纳——比碎片拼接更确定、可调试。无实体时不硬解（fail-closed）。
- **真实验证**（`test_reason_integration.py` 全过）：实体名规整为 `咪咪`（非之前 bug 的`咪咪超可爱的`）、两次「它呢」跨轮命中猫条目、`我讨厌吃香菜`→香菜无重复、无实体时「它呢」不硬解、名字单源同步。

### 7.2 bge-m3 语义检索（P1，根治近义误配）
- **可行性**：本机 P.A.L.M 项目已缓存 `bge_m3.onnx`（570MB 量化版）+ `tokenizer.json`；managed venv 已装 `onnxruntime 1.23.2 / numpy 2.2.6 / tokenizers 0.23.2`——**零下载、零安装**，直接复用已验证的加载模式（`_local_onnx_embed`：InferenceSession + `[CLS]` 池化 + L2 归一）。
- **新增 `embed.py`**：权重路径本地优先 + P.A.L.M 回退；首次为 733 条语料构建索引落盘缓存（`stitching_vectors_bgem3.json`），启动秒级加载。
- **语义模式路由**（engine）：主用 bge-m3 稠密检索（根治 lexical 近义串台：天气/洗手），语义 top1 < 0.72 时**退化为 mock 混合检索**（保留 `normalize_synonyms` 挽救亲昵类，如 `爱你哟`→爱你），两阈值尺度不同故动态切换接受阈值。
- **语义相似度实测**（真跑）：你真可爱 vs 天气遛弯 = **0.477**（清晰区分）、我困了 vs 今天好困 = **0.844**、我好难过 vs 我想哭 = **0.758**、我饿了 vs 想吃火锅 = **0.685**（同义高相似）。
- **语义模式验收**：域内命中 **1.0** + OOD 误命中 **0/7**（比 mock 更干净，彻底消灭天气/洗手串台）；延迟 ~57ms（ONNX CPU 固有，仍比 8B LLM 快 4 个数量级）。设为**可选升级（semantic=True），默认 mock 仍 5.8ms 全绿**。

### 7.3 两道增强后的定位结论
- 确定性方案在陪伴窄域的结构性优势进一步坐实：**DST 式信念状态**（记得实体/偏好/名字）+ **语义检索**（根治近义误配）+ 既有人设锁/零幻觉/真·多样/共情递进/傲娇应变。
- 「吊打 8B、接近 16B」的判定不变且更稳：8B 的不可控（漂移/幻觉/单调/近义翻车）被结构性覆盖；16B 的"未见话题新措辞"在"不看 OOC"下仍是唯一未覆盖维度，不构成短板。

## 八、工具调用层（时间 / 日期 / 天气）

> 用户指令："搞简单工具调用，比如时间，日期，天气这种结构化信息"。
> 定位：在检索缝合桩上新增**确定性工具分发**，覆盖"结构化事实查询"——这类是 8B 模型会做但对离线 mock 来说本该零成本的甜点。

### 8.1 设计原则（fail-closed）
- **时间 / 日期**：纯本地 `datetime`，零网络、零模型、确定性，永远成功。
- **天气**：走 `open-meteo` 免费无密钥 API（含 30+ 城市坐标表，北京/上海/广州/深圳/成都/杭州/武汉/南京/西安/重庆/天津/苏州/东京/纽约/伦敦/巴黎/新加坡/首尔/悉尼/莫斯科等）；网络失败 / 超时 / 解析异常 → **诚实降级**（"怕给你瞎编温度，换个时候再问"），绝不编造。
- **不破坏人设**：工具结果经 `engine._tool_reply` 包成四要素前缀 `[耳朵动了动]（抬眼）<看了眼墙上的钟>` + 正文，与检索回复同源。
- **闲聊护栏**：日期词 + 天气词若属夸赞闲聊（"天气真好呀/不错"）→ 不触发工具，回检索语料，避免「今天天气真好呀」被天气工具误吞。

### 8.2 工具清单
| 工具 | 匹配 | 数据源 | 结构化 data.type |
|---|---|---|---|
| `time` | 现在几点了 / 几点了 / 现在什么时间 | 本地 datetime | `time` |
| `date` | 今天几号 / 今天星期几 / 今天是 | 本地 datetime | `date` |
| `weather` | 城市+天气/气温 / 明天天气（带 day offset）/ 多少度 | open-meteo（联网） | `weather` |

### 8.3 真实验证（test_tools.py 全过 + 双基准）
- **匹配路由**：工具意图全命中；闲聊（今天天气真好呀/你人真好/我好难过）与知识 OOD（写代码/等于几）**不误伤**。
- **时间/日期**：本地确定性 + 结构化 type 字段 + 人格化四要素包装。
- **天气网络**：联网时有数据（测试实测 ~918ms 单次网络往返）；断网 → `ok=False` → 诚实降级文案。
- **双基准零回归**：v1.0（域内 1.0 / 真实检索 1.0 / OOD 误命中 0% / 四要素 1.0 / p99 **5.67ms**）；v2.0 全绿。天气网络延迟**单独计**（不污染聊天 p99）。
- 修真 bug：`tools.format` 原用裸 `{city}`/`{desc}` 字段名 + 只传 `d=`/`note=`，`.format()` 找不到字段 → `KeyError`；改统一 `{d[...]}` 引用。`明天天气`（无城市）漏匹配 → 补"日期词+天气"规则。天气 data 缺 `type` 标识 → 三工具补齐 `type` 字段。

### 8.4 诚实边界
- 天气依赖网络：离线环境该工具**不可用**（诚实降级），这是已知约束，非缺陷。
- 工具仅覆盖"结构化事实"，无法替代"对话陪伴"——它补齐的是 8B 伴侣也会做的"报时/查天气"这类机械能力，与检索缝合桩的陪伴能力**正交互补**。
- 城市表有限（30+），未列城市 + 无"天气"强意图词会走检索/兜底；扩城市只需加 `_CITY_COORDS` 字典项。

### 8.5 用户三点意见落实（预缓存 / 授时 / 本机兜底）

> 用户反馈：①天气可以预缓存；②时间可以去授时平台，没网直接读本机；③日期同理，没网直接读本机。
> 统一原则：**网络优先、本机/缓存兜底、fail-closed 不幻觉**。

- **① 天气预缓存**：`WeatherTool` 内置 `{city|offset: (data, ts)}` TTL 缓存（默认 900s）。`execute` 三级逻辑：
  1. 缓存新鲜（≤TTL）→ **直接返回，不联网**（验证 prefetch 北京/上海今明 4 条后，缓存命中 0.000s 秒回）；
  2. 缓存过期/未命中 → 联网 open-meteo 拉取并刷新缓存；
  3. 联网失败 → 若有**陈旧缓存（≤3×TTL）则兜底返回并标注 `stale=True`**（"本喵记的稍旧"），否则 `ok=False` 诚实降级。
  - 新增 `prefetch(cities, days)` 预热接口：启动/定时把常用城市今明天气灌进缓存，离线首问即秒回。
- **② 时间授时**：`_now()` 优先尝试多授时源（worldtimeapi → 多个可靠主机的 `Date` 响应头解析）拿精确时间；任一可达即 `source="network"`，不一致则取最新；**全部不可达则静默读本机 `datetime` 并 `source="local"`**——永不失败、永不幻觉（沙箱里授时平台不可达时实测自动降级 local，正是 fail-closed 正确行为）。
- **③ 日期同理**：复用 `_now()`，没网直接读本机日期，`source` 如实披露（network/local）。
- **`source` 字段透明化**：时间/日期 data 新增 `source` 字段，诚实告知用户此刻答案是"授时平台"还是"本机时钟"，避免假装联网。

### 8.6 落实后真实验证
- 授时可达时：`source=network`，时间 19:34 / 日期 2026/9/6 精确；不可达时 `source=local` 自动兜底。
- 天气 prefetch：4 条缓存预热后命中 0.000s；陈旧兜底路径在断网+有陈旧缓存时返回 `stale=True` 不降级。
- 双基准零回归（8.5 落实后）：v1.0（域内 1.0 / 真实检索 1.0 / OOD 误命中 0% / 四要素 1.0 / 边界 1.0 / **p99 5.99ms**，天气网络 ~849ms 单独计）；v2.0 全绿；`test_tools.py` 9 项全过（含断网时间回退本机、天气缓存不重复联网、陈旧兜底）。
- 修真 bug（落实时）：原 `_now` 单点 worldtimeapi 太脆弱 → 改多授时源冗余 + 本机兜底；天气缺 TTL 缓存与陈旧兜底 → 加三级逻辑 + `prefetch`。
