## 0. 结论先行

**「思考强度」不是一个跨厂商通用概念**，它分成三档存在性：

| 存在性 | 厂商 | 对降级通道的意义 |
|---|---|---|
| ✅ **有强度档位** | OpenAI、xAI Grok、DeepSeek、智谱 GLM、Kimi、Google Gemini、Anthropic（数值 budget）、通义（部分模型） | 档位枚举**逐家不同**，且**同厂商不同模型也不同** |
| ⚠️ **只有开关，无强度** | 豆包（火山）、腾讯混元 | 只有 enabled/disabled(/auto) |
| ❌ **完全没有，思考常开不可调** | MiniMax（M 全系）、Kimi K3（只能靠 effort 间接影响） | 传任何思考字段都可能被拒 |

→ **思考相关字段一律不进「基础字段」白名单**（见 §4）。

## 1. 有强度档位的厂商（逐家明细）

### OpenAI
- 参数：`reasoning_effort`（Chat）/ `reasoning.effort`（Responses）
- 档位：`none` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`
- 模型级约束：**推理模型不支持改 `temperature`**；**非推理模型不支持 `reasoning_effort`**；gpt-5.5 默认 `medium`
- 默认：随模型而变（官方未给单一默认值）

### xAI Grok
- 参数：`reasoning_effort`
- **同厂商不同模型默认值相反**（二级匹配的直接证据）：
  - `grok-4.3`：支持 `none/low/medium/high/xhigh`，**默认 `low`**
  - `grok-4.5`：支持 `low/medium/high/xhigh`（**无 `none`**），**默认 `high`**
  - `grok-4.6`：支持 `low/medium/high/xhigh`，**默认 `high`**

### DeepSeek
- 参数：`reasoning_effort` + `thinking:{"type":"enabled|disabled"}`
- 档位：`low` / `high` / `max`；默认 `high`
- **映射随模型变**：`xhigh` → v4-flash 映射为 `high`，→ v4-pro 映射为 `max`
- 思考模式下 `temperature` / `top_p` / `presence_penalty` / `frequency_penalty` **无效（不报错）**

### 智谱 GLM
- 参数：`reasoning_effort`（**仅 GLM-5.2+**）+ `thinking:{type}`（**仅 GLM-4.5+**）
- 档位全集：`max` / `xhigh` / `high` / `medium` / `low` / `minimal` / `none`，默认 `max`
- **模型级差异最大**：
  - `GLM-5.3` / `5.3-FLASH`：**仅支持 `low/high/max`**，默认 `max`，**强制开启、关闭报错**
  - `GLM-5.2`：传 `none`/`minimal` → **放弃思考**；`low`/`medium` → 映射为 `high`；`xhigh` → 映射为 `max`
  - `GLM-4.7` / `5.x`：默认**开启**；`GLM-4.6`：默认**混合（自动开启）**

### Kimi（Moonshot）
- `kimi-k3`：**始终思考**，`reasoning_effort`（`low/high/max`，默认 `max`），**无 `thinking` 参数**
- `kimi-k2.7-code`：thinking 默认开启且**关闭报错**；`temperature` **固定 1.0（传其他报错）**、`top_p` 0.95
- `kimi-k2.6` / `k2.5`：默认开启，**可关闭**；k2.5 无 preserved thinking
- `kimi-k2.5` / `moonshot-v1`：2026-08-31 已下线

### Google Gemini
- **两套参数并存**：3 系列用 `thinking_level`；2.5 系列用 `thinkingBudget`。**两者不可同时传 → 400**
- 档位：`minimal` / `low` / `medium` / `high`
- 模型级差异：

| 模型 | minimal | 默认 | 能否关闭 |
|---|---|---|---|
| Gemini 3.1 Pro | ❌ 不支持 | `high`（dynamic） | ❌ 不可关 |
| Gemini 3.1 Flash-Lite | ✅ **默认** | `minimal` | 可 |
| Gemini 3 Flash | ✅ | `high`（dynamic） | ❌ 不支持全关 |
| Gemini 3.5 Flash | ✅ | **`medium`** | 可 |
| Gemini 2.5 Pro | — | dynamic（`-1`） | ❌ 不可关 |
| Gemini 2.5 Flash | — | dynamic | `thinkingBudget=0` |
| Gemini 2.5 Flash-Lite | — | **模型本身不思考** | — |

### Anthropic
- 参数：`thinking:{type:"enabled", budget_tokens:N}` 或新版 `thinking:{type:"adaptive"}`
- **新旧写法在模型间互斥且方向相反**（最强二级匹配证据）：
  - `budget_tokens` 在 **Opus 4.6 / Sonnet 4.6 已废弃 → 用了 400**
  - `type:"enabled"` 在 **Opus 4.7/5、Sonnet 5、Fable 5、Mythos 5 → 400**，必须改用 `adaptive`
  - 而 **Sonnet 4.5 / Opus 4.5 / Haiku 4.5 及更早拒绝 `adaptive` → 400**，这些仍需 `budget_tokens`
  - **Opus 4.7 不支持 Extended thinking**；Sonnet 4.6 / Haiku 4.5 支持

### 通义千问（阿里云百炼）
- 主参数：`enable_thinking`（非 OpenAI 标准，须走 `extra_body`）+ `thinking_budget`
- **同为「混合模型」但默认值相反**：`qwen3.8/3.7/3.6/3.5` 默认 `true`；**`qwen3-vl-plus` / `qwen3-vl-flash` 默认 `false`**
- 带 `-thinking` 后缀（如 `qwen3-vl-235b-a22b-thinking`）：**仅思考，不可关**
- `qwen3.8-omni-flash`：改走 **`reasoning_effort`，默认 `xhigh`**；⚠️ **不可与 `thinking_budget` 同时传（报错）**；`minimal→low`、`high/max→xhigh`、`none`=关闭
- `Qwen-Omni-Turbo`：**不支持 `enable_thinking`**

## 2. 只有开关、没有强度档位

| 厂商 | 参数 | 说明 |
|---|---|---|
| **豆包（火山方舟）** | `thinking.type` = `enabled` / `disabled` / **`auto`**（模型自主判断） | 默认 `enabled`；Responses API 用 `reasoning.effort=minimal` 关闭。⚠️ **不带"深度思考"标签的模型（如 `doubao-seed-character-251128`）本身不支持**，直接调用即可 |
| **腾讯混元** | `thinking:{type:"enabled"}` | `hy4-preview` 默认开启；**HY 2.0 Instruct 不支持深度思考**；`hunyuan-a13b` 的快/慢切换靠 **query 前加 `/no_think` 前缀**（不是参数） |

## 3. 完全没有思考强度参数

| 厂商 | 官方事实 |
|---|---|
| **MiniMax** | M 全系（`MiniMax-M3` / `M2.7` / `M2.5` / `M2.1` / `M2`）官方**均为 reasoning model**，参数清单里**没有 `reasoning_effort` / `thinking` / `enable_thinking`** 任何一项（只有 model/messages/stream/max_tokens/max_completion_tokens/temperature/top_p/tool_choice/tools/response_format/stream_options）。思考通过 **Anthropic 兼容端点**（`api.minimax.io/anthropic`）以 thinking blocks + interleaved thinking 呈现，官方推荐走该端点 |
| **Kimi K3** | 无 `thinking` 参数，只能靠 `reasoning_effort` 间接影响深度 |

## 4. 对降级通道的直接影响：基础字段白名单

**绝对不能进基础字段**（存在性或枚举逐家/逐模型不同）：

```
reasoning_effort   reasoning.effort   thinking   thinking.type   thinking_level
thinking_budget    enable_thinking    clear_thinking   chat_template_kwargs
extra_body 里的任意键
```

**可以进基础字段**（OpenAI Chat Completions 规范核心，各家必定实现）：

```
model   messages   stream   temperature   top_p   max_tokens
```

**应剥离**（部分端点会拒或语义不一致）：

```
tools / tool_choice     # DeepSeek 思考模式下 supportsToolChoice=false；部分老端点不支持
stream_options          # 部分网关不认
stop                    # 混元语义与 OpenAI 相反（停在匹配内容之后）
response_format / logprobs / n / seed / user / logit_bias
```

**消息降级规则**：一律降为 `{"role": ..., "content": <string>}`；
多模态 blocks → 抽取 text 拼接；**带 `tool_calls` 的 assistant 与 `role="tool"` 消息整体丢弃**（降级通道不保留工具轮次，否则会因缺少 tool 响应而再次 400）。
