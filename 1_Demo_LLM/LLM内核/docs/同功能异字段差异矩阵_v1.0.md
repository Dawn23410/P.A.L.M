# 各供应商「相同功能 · 不同字段」差异矩阵 v1.0

> **API 面已统一（2026-09-23）**：对外入口收敛为 `palm_llm`（等价 `palm_llm.api`），
> 内部实现件全部加下划线私有。下文若出现旧函数名/旧模块路径，那是当时的形态；
> **当前清单与改名对照见 [《API函数库重构_v1.0》](API函数库重构_v1.0.md)。**

> 版本：v1.0　｜　日期：2026-09-23　｜　可信度：**B 级（厂商官方文档）**，逐条标注来源
> 用途：作为**二级匹配 / Profile 数据**的字段依据；也是「降级通道」判定"哪些字段不通用"的底稿
> 关联：`各模型思考强度调研_v1.0.md`、`供应商协议差异与特化通道方案_v1.1/_v1.2.md`

---

## 0. 结论

**有，而且很普遍。** 共整理出 **13 个功能维度**，其中：

| 严重程度 | 维度 | 后果 |
|---|---|---|
| 🔴 **致命** | 思考开关、最大输出、用量统计、停止原因、思维链字段 | 字段名错 = 功能静默失效或 400 |
| 🟠 **高危** | 系统提示位置、工具调用结构、图片输入结构 | 结构不同，必须整段转换 |
| 🟡 **中等** | 停止词语义、结构化输出、usage 开关 | 语义或支持度差异 |

一句话：**「OpenAI 兼容」只兼容了骨架（`messages` + `choices` + 流式 SSE），血肉全是方言。**

---

## 1. 🔴 思考开关（4 种写法，最臭名昭著）

| 写法 | 厂商 | 官方原文要点 |
|---|---|---|
| `thinking: {"type": "enabled\|disabled"}` | DeepSeek、**智谱 GLM-4.5+**、豆包（另有 `auto`）、**腾讯混元** | 智谱官方：`thinking` 对象仅 GLM-4.5 及以上支持 |
| `enable_thinking: true\|false` | **通义千问**（须走 `extra_body`，非 OpenAI 标准）、ERNIE | 百炼官方：非标准参数，OpenAI SDK 需 `extra_body` 传 |
| `reasoning_effort: none\|minimal\|low\|medium\|high\|xhigh\|max` | **OpenAI**、**xAI Grok**、**DeepSeek**、**Kimi K3**、**智谱 GLM-5.2+**、通义 omni 系列 | 各家档位枚举不同，见 `各模型思考强度调研_v1.0.md` |
| `chat_template_kwargs: {"enable_thinking": ...}` | vLLM + Qwen3 自建部署 | 部署侧方言，云端不适用 |

> 还有**完全不支持**的：MiniMax M 全系（无思考字段）、Kimi K3（无 `thinking` 参数）。

---

## 2. 🔴 最大输出 token（字段名分歧）

| 字段 | 厂商 | 说明 |
|---|---|---|
| `max_tokens` | OpenAI（旧）、DeepSeek、智谱、Kimi、通义、豆包、混元、ollama `/v1` | 事实标准 |
| `max_completion_tokens` | **OpenAI 新模型**（o 系/gpt-5.x 起推）、**MiniMax**（官方标注 `max_tokens` **已 deprecated**） | MiniMax 官方原文："Deprecated in favor of max_completion_tokens" |
| `num_predict` | **ollama 原生**协议（在 `options` 里） | 非 `/v1` 兼容层 |
| `max_tokens` **必填** | **Anthropic** | Anthropic 官方：`max_tokens` 是 Messages API **必填**参数 |
| `max_output_tokens` | **Gemini**（`generationConfig`） | 官方提醒：含 thought tokens，撞限会 `MAX_TOKENS` 且**仍计费** |

---

## 3. 🔴 停止原因（字段名 + 值域都不同）

| 厂商 | 字段 | 值域 |
|---|---|---|
| OpenAI 系 | `finish_reason` | `stop` / `length` / `content_filter` / `tool_calls` |
| **Anthropic** | **`stop_reason`** | `end_turn` / `max_tokens` / `stop_sequence` / **`tool_use`** / **`pause_turn`** / **`refusal`** / **`model_context_window_exceeded`** |
| **Gemini** | **`finishReason`**（驼峰，在 `candidates[]`） | 含 `STOP` / `MAX_TOKENS` 等 |

⚠️ Anthropic 的 `max_tokens` 和 `model_context_window_exceeded` **都表示"被截断"**，但 OpenAI 只有 `length` 一个 —— 映射时不能一对一。

---

## 4. 🔴 用量统计（字段名不同，且位置不同）

| 厂商 | 字段 | 备注 |
|---|---|---|
| OpenAI 系 | `usage.prompt_tokens` / `completion_tokens` / `total_tokens` | 流式需 `stream_options.include_usage` 才给（多发一个 `choices=[]` 的帧） |
| **Anthropic** | `usage.input_tokens` / `output_tokens` | **流式默认就给**（`message_delta` 事件），无需开关 |
| **Gemini** | **`usageMetadata.promptTokenCount` / `candidatesTokenCount` / `totalTokenCount`** | 在 `candidates` 之外的顶层 |
| ollama 原生 | `prompt_eval_count` / `eval_count` | 内核已转换为 OpenAI 风格，另附 `load_ms` / `prompt_eval_ms` / `eval_ms` / `total_ms` |

明细字段：`completion_tokens_details.reasoning_tokens`（OpenAI/DeepSeek/百炼）、
`prompt_tokens_details.cached_tokens` / `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`（DeepSeek）。

---

## 5. 🔴 思维链返回字段（4 种）

| 字段 | 位置 | 厂商 |
|---|---|---|
| `reasoning_content` | `choices[].delta/message` | **DeepSeek / 智谱 / 火山豆包 / Kimi / 阿里云百炼**（本项目已双读） |
| `reasoning` | `choices[].delta/message` | **OpenAI 官方**、vLLM、ollama `/v1` |
| `message.thinking` | 顶层 `message` | **ollama 原生 `/api/chat`** |
| `content[].type == "thinking"` | content block | **Anthropic**、**MiniMax（Anthropic 兼容端点）** |
| `reasoning_details[]` | 含 `signature`，须跨轮回传 | **腾讯云** |

> Kimi 官方明确：`reasoning_content` **不在 SDK 类型定义中**，须 `hasattr/getattr` 读。
> Anthropic 的 thinking block 带 **`signature`**，工具调用多轮**必须原样回传**（改一字节即 400）；
> `redacted_thinking` 是**独立块类型**，按 `type=="thinking"` 过滤会**静默丢块**。

---

## 6. 🟠 系统提示位置

| 厂商 | 写法 |
|---|---|
| OpenAI 系 | `messages[0] = {"role":"system", ...}` |
| **Anthropic** | **顶层 `system` 字段**（不是 message）。Claude Fable 5.1 / Mythos 5.1 / Fable 5 / Mythos 5 / Opus 4.8 / Opus 5 支持 `messages` 里的 `role:"system"`，但**不能是第一条** |
| **Gemini** | `systemInstruction`（顶层，非 contents） |

---

## 7. 🟠 工具调用结构

| 厂商 | 声明 | 调用 | 结果回填 |
|---|---|---|---|
| OpenAI 系 | `tools: [{"type":"function","function":{...}}]` | `message.tool_calls[]` | `{"role":"tool","tool_call_id":...}` |
| **Anthropic** | `tools: [{name, description, input_schema}]`（**无 `function` 包裹层，且是 `input_schema` 不是 `parameters`**） | `content[].type=="tool_use"` | `content[].type=="tool_result"` 带 `tool_use_id` |
| **Gemini** | `tools: [{functionDeclarations: [...]}]` | `parts[].functionCall` | `parts[].functionResponse`；**3.x 起必须带 `id` 且 `name` 匹配、数量一一对应**（否则返回空响应 + `finishReason: STOP`） |
| **智谱** | 同 OpenAI，另有独有参数 `tool_stream=true`（工具调用流式输出，仅部分型号支持） |

⚠️ Anthropic 官方：`tool_use` 的 `input` 是**对象**不是 JSON 字符串；OpenAI 是 JSON 字符串。

---

## 8. 🟠 图片输入结构

| 厂商 | 结构 |
|---|---|
| OpenAI 系 | `{"type":"image_url","image_url":{"url": "..."/"data:image/png;base64,..."}}` |
| **Anthropic** | `{"type":"image","source":{"type":"base64","media_type":"image/png","data":"..."}}`（**不接受 URL，必须下载后 base64**） |
| **Gemini** | `{"inline_data":{"mime_type":"image/png","data":"..."}}` 或 `file_data`/`fileData`（本轮未逐条回抓官方页，标注待核） |

内核现况：`providers/_multimodal.py` 已实现 `openai` / `anthropic` 两种 mode（Anthropic 分支由 P.A.L.M 主工程迁入，单一实现）。

---

## 9. 🟡 停止词 `stop`（**语义相反**）

> 腾讯混元官方原文：调用 **OpenAI 接口**时模型停止在匹配 `stop` 的内容**之前**；
> 调用**混元接口**时停止在**之后**，且"未来可能修改"。

→ 这是**同字段名、反语义**，比字段名不同更危险（不会报错，只会静默错）。
→ 已列入降级通道剥离项。

---

## 10. 🟡 结构化输出

| 厂商 | 写法 |
|---|---|
| OpenAI | `response_format: {"type":"json_object"\|"json_schema"}` |
| Anthropic | **无此参数**（官方建议用 prompt / prefill / tool use 约束） |
| Gemini | `generationConfig.responseMimeType` + `responseSchema` |
| MiniMax | `response_format` **仅 MiniMax-Text-01 支持** |

---

## 11. 🟡 流式 usage 开关

| 厂商 | 行为 |
|---|---|
| OpenAI | 需显式 `stream_options: {"include_usage": true}`，且会**多一个 `choices: []` 的帧** |
| Anthropic | 默认给（`message_start` / `message_delta` 事件里） |
| Kimi | 官方同建议；K3 兼容特性标注 `supportsUsageInStreaming: false` |
| 部分网关 | 不认 `stream_options` → 已列入降级通道剥离项 |

---

## 12. 采样参数

| 参数 | 差异 |
|---|---|
| `temperature` | OpenAI 推理模型**不支持修改**；**kimi-k2.7-code 锁死 1.0（传其他报错）**；DeepSeek 思考模式下**设了无效**；Gemini 3.x **不建议改**（官方：推理能力针对默认值优化） |
| `top_p` | 默认值逐家逐模型不同（GLM-5.x/4.7/4.6/4.5 = 0.95、GLM-4 = 0.9；MiniMax-M3 = 0.95、M2.x = 0.9；MiniMax 推荐参数 `temperature:1.0, top_p:0.95, top_k:40`） |
| `top_k` | OpenAI Chat Completions **无此参数**；Gemini / MiniMax / 智谱有 |
| `do_sample` | 智谱独有（false 时忽略 temperature/top_p） |

---

## 13. 响应容器

| 厂商 | 容器 |
|---|---|
| OpenAI 系 | `choices[0].message` / `choices[0].delta`，流式 `data: [DONE]` 收尾 |
| Anthropic | 顶层 `content[]` blocks，流式事件 `message_start/content_block_delta/.../message_stop`（**无 DONE**） |
| Gemini | `candidates[0].content.parts[]`，**无 DONE，靠连接关闭** |
| ollama 原生 | 顶层 `message`，NDJSON，`obj.done=true` 收尾 |

---

## 14. 鉴权头

| 厂商 | 头 |
|---|---|
| OpenAI 系 | `Authorization: Bearer <key>` |
| Anthropic | **`x-api-key`** + `anthropic-version` |
| Gemini | **`x-goog-api-key`** |
| 腾讯云 | `Authorization` 但错误帧 `error.code` **可能是字符串也可能是数字** |

---

## 15. 诚实边界

1. **除 ollama 外均无实机验证**（无各家 API key）。官方文档 ≠ 线上实际行为。
2. 第 8 节 Gemini 的 `inline_data` / `file_data` **本轮未逐条回抓官方页面**，属既有认知，标注待核。
3. `max_completion_tokens` 在 OpenAI 侧的"推荐/废弃"表述本轮**未拿到官方原文**（MiniMax 侧有明确 deprecation 原文）。
4. 各家仍在迭代，字段名会变（如 Gemini 3 系列把 `thinkingBudget` 换成 `thinkingLevel`）。规则须带 `as_of`。
