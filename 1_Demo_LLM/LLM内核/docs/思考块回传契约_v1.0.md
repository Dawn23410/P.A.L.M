# 思考块回传契约（跨通道）

> **API 面已统一（2026-09-23）**：对外入口收敛为 `palm_llm`（等价 `palm_llm.api`），
> 内部实现件全部加下划线私有。下文若出现旧函数名/旧模块路径，那是当时的形态；
> **当前清单与改名对照见 [《API函数库重构_v1.0》](API函数库重构_v1.0.md)。**

> 版本 v1.0 ｜ 2026-09-23 ｜ 取材：各厂商官方文档（抓取日 2026-09-23）
> 适用：`palm_llm` 全部 provider 通道

## 一、一句话结论

部分供应商要求多轮把**上一轮的思考原样送回**，否则请求直接 400；而另一些供应商
**收到就 400**。这条规则**逐厂商、逐代际不同**，属硬契约而非偏好，所以内核必须带
回传能力，且是否回传由两级匹配的数据决定，不能写死在通道里。

## 二、契约分级（官方口径）

| 供应商 / 模型 | 契约 | 官方原文要点 |
|---|---|---|
| **DeepSeek V4**（v4-pro / v4-flash） | **带 `tools` 时必需**；不带 tools 时传了被忽略（无害） | "若请求携带 tools 参数：历史轮次的 reasoning_content 均应回传给 API，并会被拼接进上下文。若请求未携带 tools 参数：reasoning_content 无需回传；即使传入 API，也会被忽略" |
| **DeepSeek legacy `deepseek-reasoner`**（已退役） | **必须剥离**：入参带该字段 → 400 | "if the reasoning_content field is included in the sequence of input messages, the API will return a 400 error. Therefore, you should remove the reasoning_content field" |
| **Kimi K3** | **无条件必需**：完整 assistant message 原样回传 | "K3 requires the complete assistant message returned by the API to be passed back to messages as-is, including reasoning_content and tool_calls" |
| **Kimi K2.6 / K2.7-code** | 同上（支持保留式思考 Preserved Thinking） | 官方「思考模型」页：K2.6 支持保留式思考；K2.7-code 保留式思考始终开启 |
| **Kimi K2.5** | **不回传**（不支持保留式思考） | 官方「思考模型」页对照表：K2.5 `thinking.keep` 无此参数、不支持 |
| **Anthropic（Claude 4.5+ / 5 系）** | **带思考用工具时必需**；不带工具可省略 | "It is only strictly necessary to send back thinking blocks when using tools with thinking. Otherwise you can omit thinking blocks from previous turns" |
| Anthropic：格式要求 | 原样、原顺序，**改一个字符即 400** | "Thinking blocks must be passed back unmodified and in their original order; a modified block results in a 400 invalid_request_error" |
| Anthropic：思考被关时 | **不报错**，优雅降级为剥离 | "If thinking becomes disabled mid-turn and you pass thinking content in the current tool-use turn, the thinking content is stripped" |
| Anthropic：`redacted_thinking` | 同样必须原样回传 | 安全脱敏块，`data` 字段加密，规则同 thinking 块 |

- Kimi K3 快速开始 <https://platform.kimi.ai/docs/guide/kimi-k3-quickstart>
- Kimi 思考模型 <https://platform.moonshot.cn/docs/guide/use-thinking-models>

## 三、两个"不能一律回传"的理由

第一版设想是「一律回传」——省事，但被官方口径否掉两处：

1. **DeepSeek legacy `deepseek-reasoner` 相反**：同一 Profile 下代际相反，必须模型级覆盖。
2. **Anthropic 回传有价格**：keep-all 模型上历史思考块"remain in context, count toward
   the window, and are billed as input tokens"。纯聊天（无工具）每轮都回传等于每轮
   都为旧思考付输入费，而官方明说此时"可省略"。故 Anthropic 通道改为**仅当本轮带
   tools 时回传**。

反向也不成立（一律不回传）：DeepSeek 带 tools 时不回传即 400，Kimi K3 则无条件要求。

## 四、内核落点

| 位置 | 承担 |
|---|---|
| `models.Message.reasoning` | 思考**文本**（OpenAI 系口径，即 `reasoning_content`） |
| `models.Message.reasoning_echo` | 原生块序列的不透明凭据（**勿解析**） |
| `Profile.needs_reasoning_echo` / `ModelRule.needs_reasoning_echo` | 契约的**数据表达**，模型级可覆盖 |
| `base.to_chat_message(m, echo_reasoning)` | OpenAI 系：按开关决定是否写 `reasoning_content` |
| `anthropic_wire` | 响应侧产出凭据、请求侧原样复活 |
| `server.chat._replay` | 历史消息整条搬运（含工具轮次） |

数据流（一次带工具的思考轮次）：

```
第 N 轮 响应
  provider 流式事件 ──► telemetry.extra.native_blocks ──┐
                                                       │  chat.py 收尾落盘
                                                       ▼
                       server.Message.reasoning_echo ──┐
第 N+1 轮 请求                                         │
  conv.messages ──► _replay ──► Message.to_kernel() ──►┘
                                │
             openai_compat ─────┴─► to_chat_message(echo=profile.needs_reasoning_echo)
             anthropic ────────────► to_native_messages(echo=bool(tools))
```

## 五、为什么 Anthropic 存「整条原生块」而不是只存思考块

`native_blocks` 是助手消息 content 数组的**完整重建**（thinking / text / tool_use /
redacted_thinking，含顺序），不是只挑思考块。理由有三条，全是官方的硬约束：

1. 思考块必须**打头**；
2. 交错思考（interleaved thinking）下思考块会**夹在多个 tool_use 之间**，只存思考块
   就丢了位置；
3. "原样、原顺序"是 400 的判定线。

因此请求侧发现凭据就**整条复活**，不再由内核字段重建 —— 重建只能还原出 text + tool_use。

**反向的节制**：不含思考块（即纯文本 / 纯工具）的轮次**不产出凭据**。这类消息内核字段
能无损重建，整条存一遍只会让每轮 stats 无谓膨胀。

## 六、安全默认值

`to_chat_message` 的 `echo_reasoning` **默认 False（不发）**。取舍：

- 漏发 → 只在"必需回传"的厂商上出错，且错误**明确**（400 + 官方文案）；
- 误发 → 让"必须剥离"的厂商静默 400，且从现象看不出原因。

## 七、验证情况

`tests/test_reasoning_echo.py` 18 个用例：

- 契约分级：DeepSeek V4 / legacy reasoner / Kimi K3 / K2.6 / K2.5 / generic 默认
- OpenAI 通道：真实 `complete()` 链路的出站 payload 中 `reasoning_content` 的有无（3 例）
- Anthropic 通道：凭据生产（含分片参数拼成对象）、纯文本轮次不产凭据、
  凭据原样复活、无凭据时回落重建、**通道按 tools 决定回传**（6 例）
- 服务端回放：工具轮次与凭据不丢（3 例）

## 八、遗留

1. **实机未验证**：以上均为 MockTransport 用例；DeepSeek / Kimi / Anthropic 均无可用 Key，
   未对真实端点发过请求。**首次实机验证须优先跑"带 tools 的多轮"这条路径。**
2. **工具执行环在应用层**：内核只负责把 `tool_calls` 下发并接收回填，谁执行、谁构造
   `role="tool"` 消息不在本层。
3. **混元未定契约**：`hunyuan` Profile 暂未置 `needs_reasoning_echo`（官方文档未查到明确
   的回传要求），按安全默认值处理（不回传）。
4. **Gemini 未建原生通道**：其思考块为 `thought_signature`，回传规则与 Anthropic 类似但
   字段结构不同，待建通道时另立一节。
