## 0. 结论先行

| 问题 | 答案 |
|---|---|
| 供应商内部有模型级差异吗 | **有，而且量级不比供应商间差异小** |
| 差异会致命吗 | 会。**至少 6 类组合会直接 400 或静默降级**（见 §2） |
| 要不要二级匹配 | **要**。一级（端点）只能定"骨架"，思考开关/采样参数/输出上限这类**语义参数**必须落到模型级 |
| 会不会把现状搞坏 | 不会。**未命中一律回落供应商 Profile = 现状**，且未知模型**不报错** |

> 一句话：**一级匹配解决"话怎么说"，二级匹配解决"哪些词不能用"。**

## 1. 一级 / 二级 的职责边界

```
请求 →【一级匹配：端点/域名/cfg.type】→ 供应商通道（骨架：URL、响应解析、鉴权、流式收尾）
     →【二级匹配：model id 正则】      → 模型子通道（语义：思考开关写法、档位表、禁参、固定参、输出上限）
     → 未命中                          → 回落供应商 Profile 默认（= 现状）
```

| 层 | 决定什么 | 变化频率 | 举例 |
|---|---|---|---|
| 一级（供应商） | URL 骨架、字段名、鉴权、流式收尾、stop 语义 | 低（半年~年） | `reasoning_content` vs `reasoning`、`[DONE]` vs `message_stop` |
| **二级（模型）** | 能不能关思考、用哪个参数关、档位枚举、禁参、固定参、max_tokens 上限 | **高（月级，厂商上新即变）** | glm-5.3 强制思考；kimi-k2.7-code temperature 锁 1.0 |

→ 正因为二级**变化快**，必须做成**数据**而不是代码分支（§4）。

## 4. 二级匹配设计

### 4.1 数据结构：ModelRule（仍是数据，不是类分支）

```python
@dataclass(frozen=True)
class ModelRule:
    # --- 匹配 ---
    pattern: str                 # 正则，对 model.lower() 做 fullmatch
    priority: int = 0            # 多条命中取最大；默认 0
    as_of: str = ""              # 规则取材日期，便于定期复审

    # --- 思考语义（None = 继承供应商 Profile）---
    thinking: str | None = None          # "always_on" | "always_off" | "toggle" | "unsupported"
    thinking_param: str | None = None    # "thinking_type" | "enable_thinking" | "reasoning_effort" | "none"
    effort_allowed: tuple | None = None  # 允许的档位枚举
    effort_map: dict | None = None       # 统一档位 -> 厂商档位

    # --- 参数卫生 ---
    forbid_params: tuple = ()            # 传了会 400 -> 请求前剔除（如 budget_tokens / thinking_budget）
    fixed_params: dict = field(default_factory=dict)   # 锁死值 -> 强制覆盖（如 temperature=1.0）

    # --- 其他 ---
    max_output: int | None = None
    extra: dict = field(default_factory=dict)          # 厂商独有（如 tool_stream）
    note: str = ""
```

**合并语义**：`ModelRule` 只对**显式非 None 的字段**覆盖，其余继承 `Profile`。
→ `dataclasses.replace(profile, **{k: v for k, v in rule_fields if v is not None})`

### 4.2 匹配算法

```python
def resolve_model(profile, model_id):
    """二级匹配：命中返回合并后的 Profile，未命中原样返回（= 现状，零风险）。"""
    m = (model_id or "").lower()
    best = None
    for rule in sorted(profile.model_rules, key=lambda r: -r.priority):
        if re.fullmatch(rule.pattern, m):
            best = rule
            break
    if best is None:
        log.debug("model rule miss: %s under %s -> fallback", m, profile.name)
        return profile, None            # ★ 未命中不报错
    return merge(profile, best), best
```

设计要点：

| 要点 | 决策 | 理由 |
|---|---|---|
| 未命中怎么办 | **回落供应商 Profile，不报错** | 厂商月月上新模型，硬报错会把新模型直接打死 |
| 多条命中 | 取 `priority` 最大，不用正则长度 | 正则可读性 > 巧技 |
| 版本后缀 | pattern 允许可选日期段，如 `hunyuan-2\.0-thinking(-\d+)?` | 官方 model id 常带 `-20251109` |
| 大小写 | 统一 lower 后匹配 | 各厂商大小写风格不一 |
| 优先级排序 | 具体型号 > 系列 > 供应商默认 | `glm-5.3-flash` 应先于 `glm-5\..*` |
| 可观测 | 命中/未命中打 debug，暴露 `resolve_trace(model_id → rule.pattern)` | 规则腐烂时能第一时间发现 |

### 4.3 统一内部表示 → 方言翻译管线

内核对外只暴露**两个与厂商无关的概念**：

```
thinking: "on" | "off" | "auto"
effort:   "none" | "minimal" | "low" | "medium" | "high" | "xhigh" | "max"
```

翻译五步（全部由 `ModelRule` 数据驱动）：

```
1 clamp_effort  : effort 先过 effort_map，再 clamp 到 effort_allowed 内最接近档
2 decide_thinking: thinking=off 但 rule.thinking=="always_on"
                   -> 降级为 effort="low" + 保持 enabled，并告警一次（官方迁移指南就这么要求）
                   -> rule.thinking=="unsupported" -> 整块 thinking 字段不写
3 pick_param    : 按 thinking_param 选字段
                   thinking_type   -> {"thinking":{"type":"enabled|disabled|auto"}}
                   enable_thinking -> {"enable_thinking": true|false}
                   reasoning_effort-> {"reasoning_effort": "<clamped>"}
                   none            -> 不写
4 drop_forbidden: 剔除 forbid_params（如同时传会 400 的 thinking_budget）
5 apply_fixed   : fixed_params 强覆盖（如 temperature=1.0），并告警
```

### 4.4 五个端到端例子

| 请求 | 二级命中 | 翻译结果 |
|---|---|---|
| `glm-5.3`, thinking=off | `glm-5\.3(-flash)?` → `always_on` | 不能关 → `{"thinking":{"type":"enabled"},"reasoning_effort":"low"}` + 告警（官方迁移要求） |
| `kimi-k2.7-code`, temperature=0.3 | `kimi-k2\.7-code` → `fixed_params` | 覆盖为 `temperature=1.0, top_p=0.95` + 告警（否则 400） |
| `claude-opus-4-7`, extended thinking | `claude-opus-4-7` → `adaptive` | 只写 `{"type":"adaptive"}`，**剔除 `budget_tokens`**（写了 400） |
| `claude-sonnet-4-5`, extended thinking | 同族另一条 rule | 写 `budget_tokens`，**不能用 `adaptive`**（拒绝 400） |
| `gemini-3.1-pro`, effort=none | `gemini-3\.1-pro` → 不可关 | 改 `thinking_level="low"`（`minimal` 不支持，none 不可关） |
