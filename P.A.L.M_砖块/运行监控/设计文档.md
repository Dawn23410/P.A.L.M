# 砖块设计文档 - 15 monitor 砖（运行监控）

> 版本：v1.0（2026-08-13）
> 路径：`backend/app/bricks/monitor/`
> 定位：系统监控、模式解析、健康检查

---

## 功能支持

monitor 砖提供全栈运行监控能力，覆盖系统指标、砖块状态、模式解析。

### 15.1 核心能力

| 能力 | 入口 | 行为 |
|---|---|---|
| 系统指标 | `monitor.system_metrics()` | CPU / 内存 / 磁盘 / 网络 |
| 砖块状态 | `monitor.brick_status(name)` | 启停 / 错误率 / 延迟 |
| 模式解析 | `mode_resolver.resolve(context)` | 判断当前运行模式 |
| 健康检查 | `monitor.health_check()` | 全栈健康状态 |
| 告警 | `monitor.alert(threshold)` | 指标超阈值时告警 |
| 指标导出 | `monitor.export_metrics()` | Prometheus 格式 |
| 历史回溯 | `monitor.history(metric, range)` | 历史指标查询 |
| 仪表盘 | `monitor.dashboard_data()` | 前端仪表盘数据 |

### 15.2 模式解析

`mode_resolver.resolve(context)` 根据当前状态判断运行模式：

| 模式 | 触发条件 | 行为 |
|---|---|---|
| `normal` | 默认 | 全功能 |
| `offline` | 网络不可用 | 切换本地 LLM |
| `low_resource` | CPU / 内存紧张 | 关闭非核心砖块 |
| `safe_mode` | 沙箱故障 | 仅允许只读操作 |
| `battery_saver` | 笔记本低电量 | 降频 / 减少推送 |
| `debug` | 显式启用 | 全量日志 |

### 15.3 监控指标

| 类别 | 指标 |
|---|---|
| 系统 | CPU 使用率、内存占用、磁盘空间、网络延迟 |
| 砖块 | 各砖块错误率、p50/p95 延迟、QPS |
| LLM | 调用次数、token 消耗、首 token 延迟 |
| GUI | 截图次数、点击次数、世界模型构建延迟 |
| 记忆 | 写入次数、读取次数、向量检索延迟 |
| 存储 | 各类数据占用、KV 读 / 写延迟 |

### 15.4 创新设计

- **模式解析器**：自动判断运行模式 + 行为调整
- **全栈监控**：从系统到砖块到 LLM 的全链路指标
- **告警阈值可配**：用户可设置告警阈值
- **Prometheus 兼容**：可对接外部监控系统
- **历史回溯**：保留 7 天历史指标
- **前端仪表盘数据聚合**：一次性返回前端所需全部数据

---

## 关键设计决策

### 决策 1：模式解析器
显式枚举模式（normal / offline / low_resource / safe_mode 等），避免"隐式降级"。

### 决策 2：全栈监控
从系统到砖块到 LLM 全链路，避免"问题在哪一层"排查困难。

### 决策 3：Prometheus 兼容
指标导出为 Prometheus 格式，对接外部 Grafana / 告警系统。

### 决策 4：告警阈值可配
用户 / 运维可设置告警阈值，避免误报。

### 决策 5：历史回溯
保留 7 天历史指标，支持事后分析。

### 决策 6：仪表盘数据聚合
前端仪表盘一次拉取全部数据，避免多次请求。

## 性能与边界

- 指标采集间隔：10s
- 指标保留期：7 天
- 告警响应延迟：< 30s
- Prometheus 导出间隔：15s
