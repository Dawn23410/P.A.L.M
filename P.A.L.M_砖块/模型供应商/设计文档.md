# 砖块设计文档 - 05 models 砖（多模型路由）

> 版本：v1.0（2026-08-13）
> 路径：`backend/app/bricks/models/`
> 定位：LLM 抽象层 + 多模型路由

---

## 功能支持

models 砖屏蔽不同 LLM 提供商的差异，提供统一的调用接口 + 智能路由。

### 5.1 模型支持

| 提供商 | 模型 | 用途 | 模式 |
|---|---|---|---|
| OpenAI | GPT-4o / GPT-4-Turbo | 主对话 | 云端 |
| DeepSeek | V3 / R1 / V4 Pro / V4 Flash | 主对话 / 推理 | 云端 |
| Anthropic | Claude 3.5 Sonnet | 主对话 | 云端 |
| Ollama | Qwen / Llama / DeepSeek 本地版 | 离线 / 隐私 | 本地 |
| 自定义 | 任意 OpenAI 兼容 API | 扩展 | 云端 / 本地 |

### 5.2 核心能力

| 能力 | 入口 | 行为 |
|---|---|---|
| 注册模型 | `models.register(name, config)` | 注册到模型池 |
| 列出可用模型 | `models.list()` | 返回模型清单 + 状态 |
| 同步调用 | `models.complete(name, messages, **kwargs)` | 阻塞等结果 |
| 流式调用 | `models.stream(name, messages, **kwargs)` | 逐 token 输出 |
| 嵌入向量 | `models.embed(name, texts)` | 返回向量列表 |
| 模型选择 | `models.select("main" / "flash" / "vision")` | 按任务类型选 |
| 健康检查 | `models.health_check(name)` | 探测可用性 |
| 故障切换 | `models.with_fallback(primary, fallback)` | 主失败切备 |

### 5.3 路由策略

- **按任务类型**：主对话选 main，平凡任务选 flash，图像选 vision
- **按成本**：低成本优先（flash 优先于 main）
- **按延迟**：本地优先于云端（Ollama 优先于 OpenAI）
- **按能力**：长上下文优先 GPT-4o，复杂推理优先 R1
- **fallback**：主模型失败自动切备，避免单点失败

### 5.4 创新设计

- **统一抽象层**：所有 LLM 通过同一接口调用，新增模型只需实现一个 adapter
- **能力标签**：每个模型注册时标注能力（长上下文 / 视觉 / 函数调用 / 流式 / 推理）
- **健康检查缓存**：避免每次请求都探测
- **fallback 链**：主 → 备1 → 备2，自动降级
- **DeepSeek 推理控制**：通过 `extra_body={"enable_thinking": false}` 稳定控制推理行为（避免 `reasoning_effort` 参数失效）

## 关键设计决策

### 决策 1：统一抽象层
所有 LLM 适配器实现同一接口（`complete` / `stream` / `embed`），AgentCore 不感知提供商差异。

### 决策 2：能力标签驱动路由
注册模型时标注能力（"vision" / "long_context" / "reasoning" / "function_calling"），路由按能力选而非按名字选。

### 决策 3：fallback 链
主 → 备1 → 备2 链式 fallback。**好处**：单点失败不阻塞主流程；用户感知不到切换。

### 决策 4：DeepSeek enable_thinking 控制
通过 `extra_body={"enable_thinking": false}` 显式控制推理行为（而非 `reasoning_effort=none`），降低 TTFT 30%+。

### 决策 5：trivial 任务专用 flash 模型
平凡任务（记忆压缩、规划、反思）通过 `select_model("trivial")` 选 flash 模型，未配置时回退主模型。

## 性能与边界

- 主模型默认 GPT-4o
- 平凡模型默认 DeepSeek V4 Flash
- 视觉模型默认 GPT-4o-vision
- 单次请求超时：60s
- 健康检查间隔：300s
