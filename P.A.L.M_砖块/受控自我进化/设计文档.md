## 功能支持

self_evolution 砖让 P.A.L.M 具备自我升级和自我调优能力。

### 20.1 核心能力

| 能力 | 入口 | 行为 |
|---|---|---|
| 检测新版本 | `self_evolution.check_update()` | 检查官方更新 |
| 应用更新 | `self_evolution.apply_update(version)` | 下载 + 安装 + 重启 |
| 回滚版本 | `self_evolution.rollback()` | 回到上一版本 |
| 配置自调优 | `self_evolution.tune_config()` | 基于使用数据自动调整 |
| 灰度发布 | `self_evolution.canary(feature)` | 部分用户启用新功能 |
| A/B 测试 | `self_evolution.experiment(name)` | A/B 流量分配 |
| 性能监控 | `self_evolution.perf_monitor()` | 升级前后性能对比 |
| 自动降级 | `self_evolution.degrade(reason)` | 异常时自动回滚 |

### 20.2 升级流程

1. **检查更新**：定期检查官方 release
2. **下载**：下载新版本到临时目录
3. **校验**：校验签名 / 哈希
4. **备份**：备份当前版本
5. **切换**：切换到新版本
6. **重启**：平滑重启（不中断服务）
7. **验证**：验证新版本健康
8. **回滚**：异常时自动回滚

### 20.3 灰度发布

- 流量分配：1% / 5% / 25% / 50% / 100%
- 触发条件：新功能上线 / 配置变更
- 监控指标：错误率 / 延迟 / 用户反馈
- 自动晋升：监控指标正常后自动全量

### 20.4 创新设计

- **平滑重启**：升级不中断服务（先启新版本再切流量）
- **自动回滚**：升级后指标异常自动回滚
- **灰度发布**：新功能逐步放量
- **A/B 测试**：内置实验框架
- **配置自调优**：基于使用数据自动调参
- **签名校验**：升级包签名验证防篡改
- **健康检查**：升级后自动健康验证

## 关键设计决策

### 决策 1：平滑重启
升级不中断服务（先启新版本再切流量），避免影响在线用户。

### 决策 2：自动回滚
升级后 5 分钟内监控指标异常（错误率 > 阈值）自动回滚。

### 决策 3：灰度发布
新功能逐步放量（1% → 5% → 25% → 50% → 100%），降低风险。

### 决策 4：A/B 测试
内置实验框架，无需外部服务（更轻量）。

### 决策 5：配置自调优
基于使用数据（哪些功能用户用得多 / 哪些参数触发问题）自动调参。

### 决策 6：签名校验
升级包用官方私钥签名，启动时校验，防中间人篡改。

### 决策 7：健康验证
升级后自动跑健康检查（核心功能调用一遍），失败立即回滚。

## 性能与边界

- 升级窗口：用户少时（建议 02:00 - 06:00）
- 灰度步进：1% / 5% / 25% / 50% / 100%
- 健康检查超时：5 分钟
- 回滚响应延迟：< 1 分钟
