# 砖块设计文档 - 03 chat 砖（对话与流式输出）

> 版本：v1.0（2026-08-13）
> 路径：`backend/app/bricks/chat/`
> 定位：用户对话接口与流式输出通道

---

## 功能支持

chat 砖是用户与 Agent 交互的最前端，承担消息收发、流式输出、上下文维护、前端协议对接。

### 3.1 对话能力

| 能力 | 入口 | 行为 |
|---|---|---|
| 单轮对话 | `chat.send(message)` | 同步等结果返回 |
| 流式对话 | `chat.stream(message)` | 逐 token 推送（SSE） |
| 多轮对话 | `chat.continue(conversation_id, message)` | 读取历史上下文后继续 |
| 角色对话 | `chat.roleplay(character_id, message)` | 加载角色卡片 + 人设 |
| 取消正在进行的对话 | `chat.cancel(conversation_id)` | 终止流式输出 |
| 获取对话历史 | `chat.history(conversation_id)` | 返回消息列表 |

### 3.2 流式协议

- 协议：Server-Sent Events (SSE)
- 事件类型：`token` / `tool_call` / `tool_result` / `done` / `error` / `cancelled`
- 心跳：每 5 秒发送 `:heartbeat` 保持连接
- 断线重连：前端可基于 `last_token_id` 续传

### 3.3 前端协议对接

- 协议格式：JSON over SSE
- 字段：`{type, conversation_id, payload, timestamp}`
- 兼容旧版：协议版本号在 payload.metadata 中

### 3.4 创新设计

- **统一事件流**：所有类型输出（token / 工具调用 / 错误）走同一条 SSE 通道
- **前端断线续传**：基于 last_token_id 续传，断网不丢消息
- **服务端取消**：用户主动取消时立即停止 LLM 调用
- **角色感知路由**：自动识别 character_id 并加载对应人设

## 架构组成

```
chat 砖
├── brick.py            # 砖块入口（is_core=True, bus=ipc）
├── handler.py          # HTTP/SSE 路由
├── stream_manager.py   # 流式连接管理（心跳 / 取消）
├── protocol.py         # 前端协议定义
├── role_dispatcher.py  # 角色对话路由
└── cancel_token.py     # 取消令牌
```

---

## 关键设计决策

### 决策 1：统一 SSE 通道
token / 工具 / 错误全走 SSE，前端只需维护一条连接。**好处**：简化前端实现；多类型输出可交错。

### 决策 2：取消令牌传递
取消请求通过 `cancel_token` 传递给 AgentCore.run，AgentCore 在每轮工具调用前检查取消状态。**好处**：取消响应延迟 < 100ms，避免 LLM 持续 token 浪费。

### 决策 3：角色感知自动注入
检测到 character_id 时自动加载角色卡片 + 人设到 prompt。**好处**：前端无需额外调用人设接口，简化前端实现。

### 决策 4：协议版本化
payload.metadata.protocol_version 字段，前端按版本兼容不同消息格式。**好处**：协议升级不影响老前端。

## 性能与边界

- 流式首 token 延迟：< 500ms（本地 LLM）/ < 1.5s（云端 LLM）
- 并发连接数：默认 100（可配置）
- 消息最大长度：32K 字符（超出截断）
- 单次对话最大轮次：50（可配置）
