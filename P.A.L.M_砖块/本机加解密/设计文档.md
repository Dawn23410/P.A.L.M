# 砖块设计文档 - 09 crypto 砖（加解密与密钥管理）

> 版本：v1.0（2026-08-13）
> 路径：`backend/app/bricks/crypto/`
> 定位：本地敏感数据加密 + API Key 管理

---

## 功能支持

crypto 砖负责所有敏感数据的加解密、API Key 安全存储、密码学工具。

### 9.1 核心能力

| 能力 | 入口 | 行为 |
|---|---|---|
| 字符串加密 | `encrypt(plaintext, key_id)` | AES-GCM |
| 字符串解密 | `decrypt(ciphertext, key_id)` | AES-GCM |
| 文件加密 | `encrypt_file(src, dst)` | 流式加密大文件 |
| 文件解密 | `decrypt_file(src, dst)` | 流式解密大文件 |
| 哈希 | `hash(plaintext, algo)` | SHA-256 / SHA-512 / bcrypt |
| 密码哈希 | `password_hash(password)` | bcrypt |
| 密码验证 | `password_verify(password, hash)` | bcrypt |
| API Key 加密存储 | `api_keys.set(provider, key)` | 加密后存 storage |
| API Key 读取 | `api_keys.get(provider)` | 解密使用 |
| API Key 删除 | `api_keys.delete(provider)` | 清除 |
| 随机数生成 | `random_bytes(n)` | CSPRNG |
| 主密钥管理 | `master_key` | 派生 / 轮换 |

### 9.2 加密算法

| 用途 | 算法 | 备注 |
|---|---|---|
| 字符串加密 | AES-256-GCM | 默认 |
| 文件加密 | AES-256-CTR + HMAC-SHA256 | 流式 |
| 密码哈希 | bcrypt | cost=12 |
| 普通哈希 | SHA-256 | 默认 |
| 密钥派生 | PBKDF2 / scrypt | 主密钥派生子密钥 |
| 随机数 | os.urandom | CSPRNG |

### 9.3 创新设计

- **主密钥 + 派生密钥分层**：主密钥从用户密码派生；子密钥按用途派生（API Key、文件、记忆）
- **密钥不落盘**：运行时主密钥仅存内存
- **AES-GCM 认证加密**：同时提供机密性和完整性
- **bcrypt 密码哈希**：抗彩虹表 + 自动 salt
- **API Key 加密存储**：provider + key 存 KV 存储，加密后写入
- **fail-closed**：解密失败不抛异常，返回 None，调用方按"密钥无效"处理
- **主密钥轮换接口**：`rotate_master_key(old_password, new_password)` 支持密码变更

## 关键设计决策

### 决策 1：主密钥 + 派生密钥分层
主密钥从用户密码派生（PBKDF2 / scrypt）；子密钥按用途派生（API Key、文件、记忆）。**好处**：主密钥泄露不影响历史数据；密码变更时只需重派生子密钥。

### 决策 2：AES-GCM 认证加密
同时提供机密性 + 完整性（防篡改）。**好处**：避免"密文可被中间人篡改"风险。

### 决策 3：API Key 加密落盘
API Key 加密后存 KV 存储；运行时解密使用。**好处**：配置文件泄露不暴露 Key。

### 决策 4：密钥不落盘
主密钥仅在内存，进程退出即清空。**好处**：内存快照攻击窗口极小。

### 决策 5：fail-closed
解密失败返回 None 而非抛异常。**好处**：调用方按业务规则处理（如"请重新输入密码"），不会因异常崩溃。

### 决策 6：bcrypt 密码哈希
cost=12 平衡安全性与性能。**好处**：抗 GPU 暴力破解；自动加 salt。

## 性能与边界

- AES-GCM 加解密：< 1ms（1KB 数据）
- bcrypt 密码哈希：~250ms（cost=12）
- 主密钥派生：~1s（PBKDF2 100k 迭代）
- API Key 长度：最大 1KB
