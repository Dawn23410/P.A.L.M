# 砖块设计文档 - 04 conversations 砖（会话持久化）

> 版本：v1.0（2026-08-13）
> 路径：`backend/app/bricks/conversations/`
> 定位：会话生命周期管理与历史归档

---

## 功能支持

conversations 砖负责会话的创建、查询、归档、清理，与 chat 砖、agent 砖、memory 砖协作。

### 4.1 会话能力

| 能力 | 入口 | 行为 |
|---|---|---|
| 创建会话 | `create(user_id, character_id, metadata)` | 生成 conversation_id，初始化空会话 |
| 列出用户会话 | `list(user_id, limit, offset)` | 分页返回会话列表（按更新时间倒序） |
| 读取会话消息 | `get_messages(conv_id, limit, offset)` | 读取会话消息流 |
| 追加消息 | `append(conv_id, role, content, metadata)` | 流式输出时可增量追加 |
| 归档会话 | `archive(conv_id)` | 标记为已归档，移出活跃列表 |
| 删除会话 | `delete(conv_id)` | 软删除 / 硬删除（可选） |
| 会话摘要生成 | `summarize(conv_id)` | LLM 生成会话摘要，写入 metadata |
| 跨会话检索 | `search(user_id, query)` | 关键词 + 向量混合检索 |

### 4.2 元数据管理

每条会话携带元数据：

- `created_at` / `updated_at`：创建/更新时间
- `character_id`：角色 ID（可选）
- `message_count`：消息数
- `token_usage`：累计 token 消耗
- `tags`：用户/系统打的标签
- `summary`：会话摘要（懒生成）
- `archived`：是否归档

### 4.3 创新设计

- **懒生成摘要**：仅在会话超过 50 条消息或主动归档时生成
- **增量追加**：流式输出时每收到一个 token 追加一次（性能优化可选批量追加）
- **软删除 + 30 天回收**：删除会话进入回收站，30 天后真正清理
- **跨会话用户画像融合**：从多会话中聚合用户画像（由 memory 砖负责）

## 关键设计决策

### 决策 1：懒生成摘要
摘要仅在必要时生成（消息数 > 50 或主动归档），避免每次写入都调 LLM 浪费 token。

### 决策 2：软删除 + 30 天回收
误删可恢复；30 天后自动清理避免长期膨胀。

### 决策 3：会话与消息分离存储
会话元数据走 KV 存储；消息流走时序数据库或追加日志。**好处**：元数据查询快；消息流写入高效。

### 决策 4：归档不删
归档会话移出活跃列表但保留数据，可重新激活。**好处**：用户重新进入历史会话无缝续接。

## 性能与边界

- 单用户最大会话数：1000（超出按 LRU 淘汰）
- 单会话最大消息数：10000（超出分卷）
- 摘要长度：< 200 字
- 跨会话检索 top_k：5
