# 砖块设计文档 - 02 memory 砖（分层记忆系统）

> 版本：v1.0（2026-08-13）
> 路径：`backend/app/bricks/memory/`
> 定位：P.A.L.M 的海马体，承载工作记忆、归档记忆、向量记忆、Token 预算

---

## 功能支持

memory 砖把"对话上下文 + 用户画像 + 经验总结 + 工具产出"组织为可量化、可压缩、可检索的多层记忆。

### 2.1 四层记忆架构

| 层级 | 子模块 | 容量 | 用途 | 生命周期 |
|---|---|---|---|---|
| **核心记忆** | `core_memory.py` | 滚动窗口 | 当前对话的 system / user / assistant / tool 消息 | 整个会话 |
| **归档记忆** | `archived_memory.py` | 跨会话 | 历史会话摘要 + 用户画像 + 经验总结 | 永久（可清理） |
| **向量记忆** | `vector.py` | 上万条 | 语义检索（基于 embedding） | 永久 |
| **Token 预算** | `token_budget.py` | 模型窗口 | 动态监控 token 使用 | 当前会话 |

### 2.2 核心能力

| 能力 | 入口 | 行为 |
|---|---|---|
| 创建 buffer 记忆 | `_memory_api().create_memory("buffer", model_window=128000)` | 工厂方法，按类型创建 |
| 写入消息 | `memory.add(role, content)` | 自动触发事件检测（detect_event） |
| 读取上下文 | `memory.context()` | 返回当前 LLM 可见的消息列表 |
| 归档摘要 | `memory.writer.perform_fallback()` | 每 5 轮或 token 超限时触发 |
| 语义检索 | `memory.vector.search(query, top_k)` | 返回相似片段 + 元数据 |
| Token 预算监控 | `memory.TokenBudgetAllocator(window).monitor(msg_len)` | 返回 `compress` / `ok` |
| 重要性评估 | `importance_scorer` 子模块 | 基于规则 + 关键词打分，> 阈值才持久化 |
| 防过度写入 | `importance_scorer` | 平凡消息（"嗯" "好的"）不写存储 |

### 2.3 事件触发 vs 兜底触发

`memory.writer` 双触发策略：

- **事件触发**（`detect_event`）：每条用户消息调一次，识别关键节点（用户首次提及偏好、情绪峰值、工具产出后等），命中即写
- **兜底触发**（`perform_fallback`）：每 5 轮调一次，无论是否触发事件都强制归档一批，防漏写

### 2.4 Token 预算与压缩

`TokenBudgetAllocator` 监控当前消息总长：

- 阈值未触发 → 返回 `ok`
- 阈值接近上限 → 返回 `warn`（AgentCore 收到后增加 prompt 提示）
- 阈值超过上限 → 返回 `compress`（触发主动摘要压缩）

压缩策略：

- 核心记忆（最近 N 轮）保留原文
- 归档记忆保留摘要 + 向量检索补充
- 历史消息压成"摘要 + 关键引用"形式

### 2.5 创新设计

- **事件 + 兜底双触发**：单一触发易漏写，单一兜底浪费 token 预算
- **重要性评估过滤**：避免"嗯/好的"等平凡消息污染存储
- **Token 预算与核心记忆解耦**：预算管理独立为单独子模块，可替换
- **向量记忆 + 归档记忆分工**：向量用于语义检索（"上次讨论过 XX 吗"），归档用于事实查询（"用户的名字是 XX"）
- **失败 fail-soft**：embedding 模型未就绪时仅返回空集，绝不抛异常

## 关键设计决策

### 决策 1：分层而非平铺
工作记忆 vs 归档记忆 vs 向量记忆的访问模式完全不同（热/温/冷），分层后每层可独立优化存储介质和淘汰策略。

### 决策 2：事件触发 + 兜底双触发
事件触发保证关键信息不漏；兜底触发保证平凡对话不静默丢失。**双触发代价**：每 5 轮固定归档，token 代价可控。

### 决策 3：重要性评估过滤
平凡消息（"嗯" "好的" "谢谢"）不写存储，显著降低存储膨胀。**阈值**：基于关键词 + 句长 + 工具产出 + 情绪强度加权计算。

### 决策 4：压缩时区分可压缩 vs 不可压缩
system prompt、persona、role 设定、人设台词等**不可压缩**；用户消息、工具输出、LLM 回复**可压缩**。压缩时严格保留不可压缩部分，优先压缩可压缩部分。

### 决策 5：Fail-soft 设计
所有写存储、读存储操作在 storage 砖未就绪时返回空集 / 默认值，**绝不抛异常**。AgentCore 拿到的永远是可用结果。

## 性能与边界

- **core_memory 默认 128k 窗口**（与 LLM 上下文窗口对齐）
- **向量检索 top_k = 5**（默认）
- **重要性阈值** = 0.3（< 此值不写存储）
- **每 5 轮兜底归档**
- **失败时 fail-soft**
