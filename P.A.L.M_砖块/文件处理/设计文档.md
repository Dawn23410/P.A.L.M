# 砖块设计文档 - 07 file 砖（文件处理 + 上传校验 + 鉴权访问）

> 版本：v1.2（2026-08-14 第三次重写：精简实际子模块（仅 storage + brick）+ 补全 storage.py 4 道校验 + 鉴权访问 + 路径穿越防护）
> 路径：`backend/app/bricks/file/`
> 定位：接收上传文件 + 鉴权访问 + 多层安全校验（大小 + 数量 + 扩展名 + 魔数）

---

## 摘要

file 砖是 P.A.L.M 的"文件层"。它把 v1.0 文档中描述的"reader/writer/editor/lister/searcher/mover/deleter"等概念**统一收进 file_tools.py（位于 agent 砖的 tools/）**，本砖只保留两件事：

1. **接收上传文件**（`POST /api/files/upload`）—— 经 4 道校验
2. **经鉴权提供访问**（`GET /api/files/{file_id}/content`）—— 移除原无鉴权静态目录

`storage.py` 是上传文件的落盘核心，把"校验层"和"落盘层"严格分离，校验层失败绝不落盘——这是"AI 上传恶意文件"的第一道防线。

> 重要说明：v1.0 / v1.1 文档中描述的 `reader.py` / `writer.py` / `editor.py` / `lister.py` 等独立子模块在 P.A.L.M 实际代码中**已被收纳到 `agent/tools/file_tools.py`**。本砖聚焦"上传 + 鉴权"两个核心职责。

## 1. 功能支持

### 1.1 核心能力

| 能力 | 入口 | 行为 |
|---|---|---|
| **上传文件** | `POST /api/files/upload` | 4 道校验 + 落盘 + 返回 UploadedFile |
| **读取文件** | `GET /api/files/{file_id}/content` | 应用层鉴权 + 12 位 hex 校验 + 路径穿越防护 |
| **跨砖复用** | `read_upload_bytes(fid)` | 按 fid 读取上传文件 bytes，供其他砖块消费 |
| **路径解析** | `_resolve_upload_path(upload_dir, fid)` | 12 位 hex 校验 + 防路径穿越 |
| **安全文件名** | `_safe_name(filename)` | basename 取原始名（防 `../../etc/passwd`） |

### 1.2 上传校验 4 道关（`storage.py`）

#### 第 1 关：单文件 ≤ 50MB

```python
MAX_UPLOAD_BYTES = 50 * 1024 * 1024  # 50 MB
```

- 超出直接拒绝（不落盘）
- 防 DoS 攻击：单个大文件拖垮存储

#### 第 2 关：单请求最多 10 个文件

```python
MAX_FILES_PER_REQUEST = 10
```

- 超出直接拒绝整批
- 防批量攻击：避免一次上传耗尽存储

#### 第 3 关：扩展名 allowlist

```python
ALLOWED_EXTENSIONS = {
    "pdf", "doc", "docx", "xls", "xlsx", "ppt", "pptx", "txt", "md", "csv",
    "png", "jpg", "jpeg", "gif", "webp", "bmp",
    "zip", "json", "py", "js", "ts", "mp3", "wav", "mp4",
}
```

- 24 种业务格式允许
- 不在列表的扩展名直接拒绝（防 `.exe` / `.bat` / `.dll` / `.scr` 等可执行文件）
- 不区分大小写（先 `lower().lstrip(".")` 规范化）

#### 第 4 关：魔数一致性

```python
_MAGIC = {
    b"%PDF": "pdf",
    b"PK\x03\x04": "zip",
    b"\x89PNG\r\n\x1a\n": "png",
    b"\xff\xd8\xff": "jpg",
    b"GIF8": "gif",
    b"BM": "bmp",
    b"RIFF": "wav",
    b"ID3": "mp3",
    b"\x00\x00\x00\x18ftypmp4": "mp4",
}

_STRICT_EXTS = {
    "pdf", "docx", "xlsx", "pptx", "png", "jpg", "jpeg",
    "gif", "bmp", "zip", "wav", "mp3", "mp4",
}
```

- 严格格式（`_STRICT_EXTS`）：魔数必须与扩展名一致，否则拒绝
- 宽松格式（其他 allowlist）：信任扩展名（如 `.py` / `.txt` / `.json` / `.md` / `.csv`）
- 防止"扩展名伪装"：如 `image.jpg` 实际是 `exe`
- 兼容处理：`jpeg` 与 `jpg` 视为同一类（不阻断）

### 1.3 落盘机制

```python
async def save_uploads(files, upload_dir) -> tuple[list[UploadedFile], list[dict]]:
    """落盘上传文件，返回（成功列表, 被拒列表）。"""
    if len(files) > MAX_FILES_PER_REQUEST:
        raise UploadRejected(...)
    saved, rejected = [], []
    for f in files:
        try:
            content = await f.read()
            ext = _validate_upload(f.filename, content)  # 4 道校验
            fid = uuid.uuid4().hex[:12]                  # 12 位 hex
            stored = f"{fid}.{ext}"
            with open(os.path.join(upload_dir, stored), "wb") as out:
                out.write(content)
            saved.append(UploadedFile(
                id=fid, name=_safe_name(f.filename), size=len(content),
                mime=f.content_type or mimetypes.guess_type(stored)[0] or "application/octet-stream",
                url=f"/api/files/{fid}/content",
            ))
        except UploadRejected as e:
            rejected.append({"name": f.filename, "error": str(e)})
        except Exception as e:
            rejected.append({"name": f.filename, "error": f"保存失败：{e}"})
    return saved, rejected
```

**关键设计**：
- **单文件失败隔离**：被拒文件记入 `rejected` 不影响整批
- **12 位 hex 标识**：`uuid.uuid4().hex[:12]` 生成唯一 fid（不暴露完整 UUID）
- **MIME 探测**：优先用 `f.content_type`，fallback 到 `mimetypes.guess_type`，再 fallback 到 `application/octet-stream`
- **URL 模板**：`/api/files/{fid}/content`（与 `read_upload` 路由对应）

### 1.4 鉴权访问（`brick.py`）

```python
@router.post("/upload", dependencies=[
    Depends(require_api_token),
    Depends(require_permission("file.write"))
])
async def upload(files: list[UploadFile] = File(...)) -> list[UploadedFile]:
    saved, rejected = await save_uploads(files, settings.UPLOAD_DIR)
    if not saved and rejected:
        raise HTTPException(status_code=400, detail={"uploaded": 0, "errors": rejected})
    return saved


@router.get("/{file_id}/content", dependencies=[
    Depends(require_api_token),
    Depends(require_permission("file.read"))
])
def read_upload(file_id: str) -> Response:
    path = _resolve_upload_path(settings.UPLOAD_DIR, file_id)
    if path is None or not os.path.isfile(path):
        raise HTTPException(status_code=404, detail="文件不存在")
    ...
```

**关键设计**：
- **移除无鉴权静态目录**：v1.0 之前曾用 FastAPI `StaticFiles` 直接暴露上传目录，存在被外部直接访问的风险
- **双鉴权**：API token 鉴权 + 权限粒度（`file.read` / `file.write`）鉴权
- **404 模糊化**：文件不存在时返回 404，不区分"不存在"与"无权访问"（防探测）

### 1.5 路径穿越防护

```python
_FID_RE = re.compile(r"^[0-9a-f]{12}$")


def _resolve_upload_path(upload_dir: str, fid: str) -> str | None:
    """按 fid 在上传目录查找匹配文件，防路径穿越。
    
    fid 可为 12 位 hex（匹配 {fid}.*）或完整存储文件名（精确匹配）。
    """
    if not os.path.isdir(upload_dir):
        return None
    for name in os.listdir(upload_dir):
        if name == fid or (name.startswith(fid + ".") and _is_valid_fid(fid)):
            return os.path.join(upload_dir, name)
    return None
```

**防护机制**：
- **正则校验 fid**：`^[0-9a-f]{12}$` 必须是 12 位 hex（防 `../../etc/passwd`）
- **白名单目录**：只在 `upload_dir` 查找，不接受绝对路径
- **前缀匹配**：`name.startswith(fid + ".")` 防误匹配（如 `abc123` 不能匹配 `abc1234.pdf`）

### 1.6 4 个权限粒度

| 权限 key | 标题 | 风险等级 | 用途 |
|---|---|---|---|
| `file.read` | 读取本地文件 | MEDIUM | 读取电脑上的任意本地文件（纯文本） |
| `file.write` | 写入本地文件 | MEDIUM | 创建 / 修改 / 复制 / 移动 / 建目录 |
| `file.delete` | 删除本地文件 | **HIGH** | 永久删除文件，不可恢复 |
| `file.fs_query` | 浏览与检索文件 | LOW | 列目录、查看元信息、搜索、计算哈希 |

> `file.delete` 是 P.A.L.M 唯一高风险权限——删除文件不可恢复（即使软删除也仅 30 天保留）。

### 1.7 跨砖复用

```python
capabilities={"read_upload": read_upload_bytes}
```

- `read_upload_bytes(fid) -> bytes | None` 注册为 `read_upload` capability
- 其他砖（agent / chat / evolution）经 `get_facade("file")` 取得后即可读上传文件
- **零互导契约**：消费方不直接 import file 砖

## 3. 关键设计决策

### 决策 1：校验层 + 落盘层严格分离

`storage.py` 顶层注释明确："校验层（大小/扩展名 allowlist/魔数一致性）与落盘层分离，落盘函数只调用校验。"**好处**：校验失败时无法绕过；未来增加校验类型只需扩展校验层。

### 决策 2：4 关上传承载

大小 → 数量 → 扩展名 → 魔数，4 关上承。**好处**：每关上承一种攻击（DoS / 批量攻击 / 危险格式 / 扩展名伪装），单关失效不致命。

### 决策 3：魔数严格 + 扩展名宽松双策略

`_STRICT_EXTS`（pdf / docx / png / jpg 等）要求魔数一致，其他（txt / py / json 等）信任扩展名。**好处**：纯文本格式无魔数特征，宽松处理不误拒；二进制格式严格要求防伪装。

### 决策 4：移除无鉴权静态目录

v1.0 之前用 `StaticFiles` 直接挂载上传目录，外部可任意访问。v1.1 起改为 `GET /api/files/{file_id}/content` 经应用层鉴权。**好处**：上传文件不被外部直接枚举访问。

### 决策 5：单文件失败隔离

`save_uploads` 用 try/except 隔离每个文件，被拒文件记 `rejected` 不影响整批。**好处**：1 个不合规文件不阻塞整批上传；前端可对每个文件单独提示错误。

### 决策 6：12 位 hex 作为文件标识

`uuid.uuid4().hex[:12]` 生成 12 位 hex 标识，URL 友好且不可枚举。**好处**：文件 URL 可分享但不暴露完整 UUID；长度适中便于显示。

### 决策 7：路径穿越 4 重防护

- 正则 `^[0-9a-f]{12}$` 校验 fid
- `_safe_name` basename 取原始名
- `_resolve_upload_path` 白名单目录
- 文件名 prefix 匹配（`fid + "."` 开头）

**好处**：单重失效不致命；`../../etc/passwd` 攻击至少被 2 重以上拦截。

### 决策 8：file.delete 高风险权限

`file.delete` 标为 HIGH 风险（唯一 HIGH 级文件权限），与 `file.read` / `file.write`（MEDIUM）区分。**好处**：用户授权时明确知道"删除不可恢复"。

### 决策 9：跨砖复用走 capabilities

`read_upload_bytes` 注册为 `read_upload` capability，消费方经 `get_facade("file")` 取用。**好处**：保持砖间零互导契约；缺失时降级为 None。

### 决策 10：404 模糊化

文件不存在与无权访问统一返回 404，不区分。**好处**：防攻击者用 200/404 探测文件名。

## 5. 性能与边界

- 单文件大小限制（上传）：50MB
- 单请求文件数：10 个
- 单文件读 / 写：100MB（由 file_tools.py 工具承载）
- 路径白名单：默认 `$UPLOAD_DIR`（只允许读上传文件，读其他文件由 file_tools 单独鉴权）
- 扩展名 allowlist：24 种业务格式
- 严格魔数：12 种格式
- 宽松格式：12 种格式（信任扩展名）
- HTTP 路由：2 个（`POST /upload` + `GET /{file_id}/content`）
- 权限粒度：4 个（read / write / delete / fs_query）
- 文件标识：12 位 hex（48 bit 熵，碰撞概率可忽略）
