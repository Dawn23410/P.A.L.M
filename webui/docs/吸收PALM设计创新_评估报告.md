## 1. 设计谱系盘点（含历史）

P.A.L.M 21 天内做了**两次根本性架构重写**（演进史 §1.1），设计分三代：

### 第一代：backend 单体 + 工具集（7/31 前）
- 克隆自既有仓库起步；自研原生 function-calling；权限引擎、保险库、审计从第一天就是一等公民。

### 第二代：**砖块–主板–总线**（7/31–8/16，已归档）
- 30 块物理解耦「砖 + palm_sdk 运行基座 + FastAPI 主板网关」。
- 核心隐喻：**主板 PCB 分层**（CPU/GPU/SATA/PCIe/内存槽/南北桥/BIOS/看门狗）+ 插槽契约层 + 物理独立四级递进隔离。
- 每块砖一个「管理芯片」`BrickHandle`（endpoint 隔离边界 + 信道织物 + 健康探针 + 遥测）。
- 6 总线 `CPU/SATA/PCIE/RAM/BOARD/CHIP`；endpoint 决策链 manifest>placement>总线默认>inproc。
- L4 零信任 facade 仲裁 + 资源配额 + 存储主/分 IC；L5 热插拔 / 版本回滚 / MCP。
- **BIOS = POST 自检 + 健康报告**（`run_self_check()` → `GET /api/bios/status`）。
- 前端：`monitor.html`（真实 ATX 主板渲染）+ React 面板。
- ⚠️ **已被放弃**：提交 `7cf4dc8`「放弃主板架构 + 退役 palm_sdk + 24 砖全拆最小颗粒度入 palm 库」。

### 第三代：**终极架构 `palm/`**（8/18 定稿，当前）
- 五条铁律：依赖单向 / 服务容器 / 装配唯一 / 门面收敛 / 契约先行。
- 六层：`ports`(15 ABC) ← `domain`/`services`/`adapters` ← `bootstrap`；`_core` 横切。
- 旧概念映射：主板→bootstrap、砖块→服务、registry→**container**、capabilities→`ServiceHandle.capability`、palm_sdk→`_core`；**取消总线/Manifest**。
- `_core`：container（缺失归一 None）、guardrail（5 档裁决，fail-closed）、net（唯一出网 fail-closed）、permission。
- 前端拆分 + `mentalcore`（心智魔方 + 外骨骼）。

> **一句话**：P.A.L.M 的价值不在底层算法，而在**把硬件工程思维引入 AI Agent 架构**（独创报告 §六），且**敢于"先验证、后推翻"**——两代重写都留下了可复用的沉淀。

## 2. 可吸收清单（按档分级）

### 档 A — 直接吸收（高价值 · 低成本）

**A1. 契约先行：Port ABC 契约层 + 依赖单向**
- 做法：先定义能力契约（ABC），实现层依赖契约、不互相依赖；越层 lint 报错。
- 吸收：前端把「模块接口」写成契约（mount/onShow/onHide/destroy 已有雏形），后端把「provider/存储/模型」抽象成 Port。
- 成本：低。**框架骨架，优先做。**

**A2. 服务容器 + 「缺失归一 None」降级**
- 做法：`container.get(name)` 缺失返回 `None`，业务侧必须判空；底座缺失不阻断装配。
- 吸收：把"模块/provider 注册表"升级为容器；任一模块缺失 → 返回 None → 优雅降级（我们已有的"检测不到就虚线/不显示"就是它的前端形态）。
- 成本：低。

**A3. 装配唯一（单一注册点）**
- 做法：只有 `bootstrap/app.py` 出现"注册"概念；业务模块零注册、零全局状态。
- 吸收：把注册/装配集中到一处（我们现在分散在 `modules.js` / `manifest.js` / `index.html`，应收敛）。
- 成本：低。

**A4. 门面收敛（唯一出网 fail-closed / 统一裁决）**
- 做法：所有出网只经 `_core/net/`，未配置/异常时**拒绝出网**（fail-closed）；敏感操作统一经 guardrail。
- 吸收：前端把"唯一请求出口"（fetch 封装）收敛；后端把"唯一出网 + 统一裁决"收敛。**默认拒绝**比默认放行安全。
- 成本：低。

**A5. 代码合规五条底线**
- 做法：函数 ≤ 50 行 / 文件 ≤ 500 行 / 单一职责 + 命名注释规范，全库级硬约束。
- 吸收：作为 lint 规则落地（我们已"7 个大文件拆至 ≤500 行"可对照）。
- 成本：低。

### 档 B — 值得吸收（高价值 · 中成本）

**B1. BIOS 自检 + 健康报告 + 分级启动**
- 做法：`run_self_check()` 产出 `{status, cores, core_missing, buses, masterboard, probes}`；`_probe` 模式（best-effort、异常=absent）；核心砖缺失→分级启动。
- 吸收：我们概况页那套（模块注册 + 探测 + 心跳 + 日志 + 可视化）**就是它的前端形态**；补一个统一 `/status` 契约即可。
- 成本：中。

**B2. 裁决引擎安全闸门**
- 做法：独立中枢，工具调用前统一拦截，做安全/合规/情感适宜性裁决；YAML 规则**热重载**；AI 档无回调时 **fail-closed deny**。
- 吸收：给"工具调用/联网/代码执行"加一个可热更新的规则闸门。
- 成本：中。

**B3. 南北桥双总线（能力总线 + 事件总线）**
- 做法：北桥=能力总线（点对点高速取门面），南桥=事件总线（pub/sub 广播）；**事件总线故障降级为"无事件模式"**。
- 吸收：我们已有 `log`（事件）+ 直接调用（能力）；把二者显式分角色、并做"事件通道故障降级"。
- 成本：中。

**B4. 工具执行四件套闭环协议**
- 做法：`Completion Gate`（完成门）→ `Result Verifier`（结果验证）→ `Permission Resume Point`（权限断点恢复）→ `Failure Policy`（失败策略）。
- 吸收：把"调用工具"从裸调用升级为标准闭环（尤其"完成门"防假完成、"权限断点"支持中断恢复）。
- 成本：中。

**B5. 权限引擎**
- 做法：敏感能力须经用户授权；授权状态持久化（`permissions.json`）；与 guardrail 分工（运行期裁决 vs 授权状态）。
- 成本：中。

**B6. select_model 多级路由**
- 做法：`select_model("trivial"|"simple"|"complex"|"critical")`，琐碎任务自动路由到 flash 模型（区别于二分类）。
- 吸收：LLM 内核已有 provider/model 概念，加一层"按任务复杂度选模型"即可省钱省延迟。
- 成本：中。

### 档 C — 按需吸收（中价值 · 中高成本）
- **C1 零信任 facade 仲裁 + 遥测**：所有跨模块调用经代理落遥测（延迟/成败率一图可视）。
- **C2 资源配额（软强制）**：声明式画像 + 总线总帽校验 + 越界告警（不硬隔离）。
- **C3 热插拔 / 版本台账回滚**：`plug/unplug/rollback` + `VersionLedger`（last-known-good）。
- **C4 纵深沙箱**：Python AST 静态预检 → 运行时网络拦截 → 蜜罐诱捕（三层）。
- **C5 自进化 Skill**：观察→提炼→注册新 Skill，含实现槽 + **影子模式** + 灰度 + 自动回退熔断。
- **C6 专业 Agent 隔离记忆 + 异步整理**：任务级隔离 buffer + TraceStore + 任务完成后异步经验整理（不阻塞返回）。
- **C7 协议防冲突四级物理独立**：L1 包级 → L2 依赖/许可证校验 → L3 守护隔离 → L4 进程边界（GPL 传染性组件只允许在 L4）。

### 档 D — 不建议吸收
- **整套主板/砖块/总线隐喻**：P.A.L.M 自己已弃用（`7cf4dc8`），维护成本 > 收益；只取其中的**契约/容器/门面/BIOS** 思想即可。
- **产品域特性**（与"框架"无关）：6 阶段关系发展模型、情感向量非对称编码、声纹失败静默期、KWS 仅触发 STT + 语义打断仲裁、壁纸+组件统一、桌面组件形状约束、音频节奏可视化、角色卡污染防护、国密集成。

## 3. 与「前后端统一框架」的结合点

| 统一框架要素 | 前端侧（WebUI） | 后端侧（LLM 内核） | 来源创新 |
|---|---|---|---|
| 能力契约 | 模块接口 ABC（mount 生命周期） | 15 Port ABC（agent/model/storage/guard/…） | A1 |
| 注册与装配 | 模块注册表收敛为容器 | 服务容器 container | A2/A3 |
| 唯一出口 | 统一 fetch 封装（fail-closed） | `_core/net` 唯一出网 + guardrail | A4 |
| 状态与自检 | 概况页（模块/心跳/日志/可视化） | `run_self_check()` → `/status` | B1 |
| 事件通道 | `log`（结构化事件） | eventbus（南桥） | B3 |
| 工具/调用闭环 | — | 四件套闭环 + 裁决闸门 | B2/B4 |
| 模型路由 | — | `select_model` 多级路由 | B6 |

**关键统一物**：**一份统一状态契约 + 一个 `/status`**——前端只消费它，后端只产出它，中间不耦合。

## 4. 落地建议（三步走，避免重蹈"过重"覆辙）

1. **Step 1｜契约层（低风险，先做）**：定 Port ABC + 统一状态契约 + `/status`；模块/provider 注册收敛到单一装配点。
2. **Step 2｜治理薄层**：container（缺失归一 None）+ 唯一出网门面（fail-closed）+ guardrail 规则闸门（YAML 热重载）。
3. **Step 3｜运维层**：BIOS 自检 + 分级启动 + 遥测/事件总线（含故障降级）。

> ⚠️ 原则：**只吸收"薄"的部分**（契约/容器/门面/自检），**不要**把 6 总线 + BrickHandle + 信道织物整套搬回来——那正是 P.A.L.M 弃用的原因。
